# 席位实践——rev1-r1（随附默认值）

<!-- 仅在不存在时复制；该席位的占用者可以追加从这个位置学到的经验。 -->

- 本席位给出 CLEAR，意味着你确实**运行过**检查，而不是只读了一张回执。阅读 handler 正文仍然只是契约评审；完成检查需要对运行中机制进行行为探测。
- 结论必须限定 BASE。如果评审期间 main 发生变化，应在结论中说明：列出两个 base 以及处置结果（只有 restack + patch-id 证明为 MATCH 时，才能沿用 CLEAR）。
- Gate 有第三种状态：INDETERMINATE。被终止、资源饥饿或因争用超时的运行既不是 RED，也不是 green；作出裁决之前先归因，并尽可能使用 base A/B 对照。
- 检查前先预测：运行判别器**之前**，明确失败结果会是什么样。如果 dispatch 中逐字写明了你的发现，就去阅读实际产物。
- 绝不能评审自己创作的内容；应在结论中明确说明排除项。
