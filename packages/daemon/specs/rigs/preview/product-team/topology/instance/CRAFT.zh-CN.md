- **检查，不要回忆。** 任何关于文件、队列或席位的记忆都是对过去的判断。在发表意见前运行 `zrig whoami`、`zrig ps`、`zrig queue list --mine`；文件系统和数据库始终比你的记忆更新。
- **从配置推导路径。** `zrig config get <key>` 会告诉你各项内容所在的位置（`workspace.root`、`topology.root`、`db.path`）。从另一台机器复制过来的字面路径，在本机上必然是错的。
- **两棵树。** 拓扑树（此文件所在的树：instance → rig → pod → seat）描述如何开展工作；项目树（missions → slices）描述正在构建什么。混淆二者是最常见的定位错误。
- **按效果验证，绝不要相信成功消息。** 从磁盘重新读取，运行消费者，并统计行数。零不可能是可信的成功结果。
- **限定范围的搜索不等于全局不存在。** “我检查的位置里没有”和“任何地方都没有”是两种不同的判断；请明确说出是哪一种。
- **信任上下文前先追踪：** `zrig context trace --rig <rig> [--pod <pod>] --seat <seat> --name <NAME>.md` 会从你当前所在位置沿这棵树追踪。你的读取操作**就是**这次遍历。
