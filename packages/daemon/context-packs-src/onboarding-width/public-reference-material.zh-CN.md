# 可以查阅哪些资料

**你迟早会遇到这份入门内容无法回答的问题。**这是预期情况——它是一份世界模型，不是操作手册。重要的是你会去查找书面答案，而不是自行推导，因为**一旦说出口，臆造的答案和已知答案看起来完全一样。**

因此，下面列出一台 zrig 机器上有哪些书面资料，以及每类资料大致能回答什么问题。你现在不需要阅读它们，只需知道它们存在。

## 命令界面——源代码仓库中的 `docs/as-built/`

使用源代码仓库的 `docs/as-built/` 索引，以及标记为 `kind: as-built` 的文档。从与问题相符的入口开始：

- **`README.md`——“领域地图 + 模块索引”。**不知道需要哪份文档时，从这里开始。
- **`codemap.md`——“导航索引 / 领域地图”。**即将阅读代码、却不知道目标由哪个模块负责时，从这里开始。
- **`cli-reference.md`——`zrig` 命令参考。**其中包含每个命令组、子命令、flag 和 JSON 结构。**这是判断命令如何工作的权威来源**；能力说明（`public-what-you-can-do.md`）只是通往它的地图。

将文档的验证标记与当前使用的源代码进行对照。即使文档一直有人维护，也可能落后于已变更的命令；更新历史不能证明当前行为。

### 判断文档可信程度的字段

这些文档都带有 frontmatter，其中三个字段尤其值得记住：

- **`applies-when:`**——触发条件。它说明何时应该查阅本文档，而不是文档包含什么。检索相关资料时，可以优先扫描这些字段。
- **`siblings:` / `prerequisite-reads:`**——关系图。这里的文档会指向相邻资料，因此只要先找到大致正确的一份，它就会继续引导你。
- **`last-verified-against-source: <commit>`**——**最坦诚的字段。**它记录文档最后一次对照源代码检查时使用的 commit。如果 `main` 已在此后前进很远，应预期文档存在滞后，尤其是在近期频繁变更的区域。

**明确写出验证依据的文档，具有一种具体、可度量的可信度**；通过这个字段进行校准，不必猜测。文档与实际二进制行为不一致时，**以二进制为准**；这种差异值得报告，不能只在本地绕过。

## 实时答案——`--help`

**直接询问你将实际运行的二进制文件。**`zrig <verb> --help` 和 `zrig <verb> <subcommand> --help` 是命令结构、flag 和默认值的权威来源。它只需几秒，是本清单中成本最低、收益最高的习惯。

**还应把它当作搜索工具，而不只是查询入口。**`zrig --help` 会列出已安装的顶层命令。开始构建某项能力之前，应先阅读该列表；代价最高的失败，是用底层原语重新造出一个已经可以通过现有命令组合得到的解决方案。

## 森林之外——当本机没有任何资料能够回答时

有一类问题超出了源代码仓库和实时 `--help` 的范围：外部库如今的真实行为、训练截止时间之后发生的变化，以及这个仓库之外的现实情况。

**这与本页此前警告的是同一种失败，只是方向朝外。**不知道下列外部来源存在的智能体，会选择臆造而不是查找；它会依据训练快照作答，却把答案陈述为当前事实——而一旦说出口，臆造的答案和已知答案看起来完全一样。

使用当前 harness 中实际可用的工具。如果安装了 `context7` 等文档连接器，请使用其当前查询界面查找相关库和版本。如果有 `exa` 等网页搜索或抓取工具，则用它查找最新的一手来源。这些工具名称只是示例，不代表你的安装必然包含它们。任何影响答案的访问限制或版本限制都应明确说明。

### 信任规则——并不是这些工具容易让你误以为的那一条

**搜索结果只是关于目标内容的页面抓取；一手来源才是目标本身。**搜索用于**寻找**；任何关键事实都必须回到一手来源**确认**，例如 registry、API、仓库或运行中二进制的 `--help`。

搜索索引和缓存可能落后于它们描述的来源。对于已发布的软件包版本，应查询 package registry；对于 API 契约，应检查带版本的提供方文档或实现。二手页面上的“已更新”时间戳，并不能说明它对应哪一版源代码。

因此，这些工具扩展了你的查询范围，却不会获得高于一手来源的优先级；*看起来更新*不等于*确实更新*。

## 有一份资料需要通读，而不是按需查询

**`openrig-operating-model`**——关于上下文放置和沿链路查找的 skill。本页其他资料都是在已有具体问题时再去查阅；**这一份则需要完整读过一次**，因为它描述了其他内容所依附的整体形态：两棵树、上下文如何按层级组织，以及一个空白智能体如何找到所需资料。通读它，才能避免重新发明已经存在的组织方式。

## 所有这些资料要培养的习惯

**连续三次搜索为空，说明你对目标的称呼可能不正确，而不是目标不存在。**换一个名称再试一次，然后询问可能知道的人，最后记录这一资料缺口。

**没有加载，绝不等于不可用。**这里几乎没有任何资料会预先进入你的上下文，但几乎所有内容都只需一条命令即可获取。
