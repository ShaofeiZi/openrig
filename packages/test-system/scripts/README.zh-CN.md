# 按场景解析的桩脚本

根据 51-01 脚本响应契约，场景可以解析一份按席位提供、在 `up` 时交付的桩脚本；如果场景未指定脚本，则应用 51-01 内置的 DEFAULT 脚本（启动 → 就绪）。

## 当前状态（编写于 51-01 第 5–8 项落地之前）

- 生命周期、send、queue、policy 与 ps 场景（#1、#2、#3、#4、#7、#9、#10）只需要 51-01 内置的默认“启动并就绪”脚本——此处无需自定义脚本。
- emit 行为场景（#6 compaction、#8 slow_output）使用 51-01 的四种行为 `{compaction, slow_output, mid_turn_death, restore}`，这些行为会在 51-01 第 5–8 项（R-01）中落地。目前尚未在这里编写对应的行为脚本：emit 边界要等 51-01 落地后才存在，针对尚未构建的边界编写脚本，恰好就是本系统要防止的捏造。它们已经完成路由（R-01/R-02），会在能力集合落地后加入。
- 不存在名为 `usage_limit` 的脚本——它只适用于真实运行时，必须在桩拓扑中明确触发验证失败。

此目录有意保持轻量：51-03 只负责组合；对于它当前还无法诚实编写脚本的桩行为，应将其路由回 51-01，而不是在这里伪造。
