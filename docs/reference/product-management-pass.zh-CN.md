# 产品管理这一遍 —— 在规划者碰任务目标之前、跑在规划之上的那一层

2026-08-28 从一次真实发布准备中磨出来的工作 SOP 毕业；起源团队的频道细节留在它自己的 playbook 里。

## 这一层为什么存在（读这一段，否则后面的步骤就是仪式）

构建是一条有损压缩流水线：产品意图 → 规划者 spec → 构建者代码，每一级的读者都比上一级窄。没有任何维度会因邻近而向下漏——产品 owner 席位持有、却不**写下并路由**的维度，会从产品里被删掉，而且删除是静默的：下游智能体会编造一个看似合理的替代，而不是举手。这一遍是产品品味物理进入流水线的唯一位置。它的输出只用一把尺衡量：

> 一个 slice 文件夹什么时候算就绪？当**仅凭 SPEC.md**（加上 SPEC.md 显式路由到的东西），就能在一个完全没有你上下文的读者那里复现设计意图。

## 步骤

1. **扎根原材料。** 盘点想法实际住在哪里：owner 意图层、旧时代的设计、那些对话。先廉价枚举（intent frontmatter、索引）；自己读核心文档；派读者做广度，要求带引用的报告（带可打开路径的主张；状态：shipped / partial / designed-never-built）。绝不 grep 然后祈祷。
2. **综合出一个范围记录。** 主题；wave；有约束力的设计原则；一个显式的"不做什么"清单（是决定，不是遗漏）；owner 决策集，每条带建议。把被取代的规划归档到一个冷读者不会误认为权威的地方。其他所有界面都从这份文档**派生**；它们不一致时，它赢。
3. **把决策呈到"可裁决"状态。** 一次一个，带字母编号，先给建议，引用记录。owner 的裁决在下游一切设门——尽可能机械（一个 blocked-on 锚点），绝不靠记忆。
4. **在规划时铸造 slice**，带真正的一段式 intent。
5. **存入设计 —— 保真法律。** 每个承载设计的 slice，其 SPEC.md **内联**携带完整设计契约：owner 原话、已定的不再重开的决定、活证据、完成的形状、反目标。一行 intent 是约 20:1 的有损压缩；只靠它构建，匹配设计纯属巧合。在对话里发生过的设计，要么在铸造时存入，要么随作者的上下文窗口死掉。带持久具名种子的机械 slice 可以保持薄——薄是逐 slice 判断，绝不是默认。
6. **路由一切 —— spec 就是路由器。** 下游读者的世界是 SPEC.md；他们的好奇心不越过它，一个文件的存在不是一条路由。spec 自己携带逐 slice 的完整阅读清单（你**实际**用的源，每条一行理由）和逐 slice 的调研路由（哪个工具回答哪个问题——包括在外部框架会污染一个 owner 设计的模型时，显式写 NO）。没有任何承重的东西可以依赖读者主动去找。
7. **逐 slice 框定规划。** 每个 spec 里：规划档位及其理由（`docs/reference/planning-dial.md`）；什么最重要；要求的输出形状。为调研轮 slice 自己写调研提示词——上下文门禁：提示词来自持有产品上下文的智能体；执行可以扇出。对每个 spec 都有约束力的约束写在 spec 里，绝不假定已知。
8. **心智模型重读。** 在放出这一批之前，**扮成那个狭窄的下游读者**重读每个 spec——一个拿到队列票、只读这一个文件、并且会不问就编造任何缺失东西的智能体。每一句"可他们怎么会知道 X？"都是现在就要补的洞。
9. **排序与设门。** wave 文件不相交；任何必须先于派发的东西，把它作为行依赖设门，绝不作为一个被记住的意图；展开指挥棒带着档位分配，并按 slice 路由回来。
10. **保持记录活。** 面向 owner 的看板从范围记录重新派生；修正先落在治理文档里，再向外投射。

## 这一遍存在是为了防的失败模式（每个都在现场观察到过）

- 薄 intent 发出去，仿佛展开者能补回它从未有过的保真度。
- 漂亮的上下文写在磁盘上却从不路由——只写不读的产物。
- 阅读清单是真实源集合的策展摘录。
- 调研需求塑造者知道，却从不派给一个工具或一个问题。
- 门没到就派发；排序记在脑子里而不是一行。
- 以十个维度理解世界，写的时候却以为缺的七个会自己渗过去。它们不会。路由它，否则它就没了。

## 对接广角席位：给上下文，不给指令

当任何席位把发现、问题或提案发给一个广角席位（顾问、产品塑造者）时，它把这些框成**桌上的上下文**——把问题讲清楚、给出依据、有候选方案就给——并明确把方向盘留给接收者。绝不写成指令，哪怕手里已有一个自信的建议。原因：窄孔径席位产出窄方案，并默认用命令语气；一个信任发送者的广角席位会照做，而窄决策就是这样未经综合漏进产品的。这个模式把发送者的强度（深、聚焦、当下）转成接收者的综合（宽、跨切、跨时）。这是保真法律的入站一半：出站时，塑造者存入设计好让压缩吃不掉它；入站时，发送者框成上下文好让孔径绕不开综合。

**协议是双向的。** 向下——编排者到构建者——同一套布线纪律镜像适用：把目标、验收标准和完整上下文**摆上桌**，把实现的方向盘留给接收者。一个编排者把上下文转成一步步命令，绕开构建者综合的方式，和一个窄席位的命令语气绕开广角席位完全一样。赋权以上下文交付，绝不以指令——两个方向都是。

## 孔径默认收窄——而这正是重点

别把上面读成"给每个席位分孔径"。智能体不可避免会收窄：埋头做一类活、一个席位专业化，而收窄**就是**专业化效应——系统的核心机制，绝不是要纠正的缺陷。把一个专家拉宽，会冲淡让他们精英的东西。绝不刻意设一个窄孔径；席位自己长到它的孔径。你唯一要调控的孔径是那个宽的：广角本身是一种专业化，它的定义纪律是顶着那股收窄其他所有人的拉力**维持宽度**。只有当一个角色必须守住高度时，才在角色里写明孔径。

## 拓扑配对（蓝图笔记）

一个强拓扑把一个**编排**席位（流：派发、排序、容量——全局宽、动作时窄）和一个**产品塑造**席位（品味：一致性、契约、时间判断——产品范围宽）配对，各自在角色里写明孔径。"上下文非指令"规则就是它们之间的布线协议。

## 把价格定低一层 —— 对层检查

在接受你伸手够到的那个修复之前，把价格**再低一层**算一遍。倾向是往高处修——高处修复好写好测——而有时候窄恰恰是对的：有时候你只需要一块创可贴。但有时候你是在接骨，而征兆是可学的：

- **接骨征兆：** 低处修复一次塌掉几个未决问题，而且往往比那个补丁**更小**——它删除或复用，而不是添加。
- **创可贴征兆：** 下层稳定、正确、只是不方便；缺陷确实局部；下游没有别的地方共享它。
- **地板：** 有一个甜点。修到你拥有的原语之下是别人的泳道；在组合够用处造一个新引擎，过不了简洁这关。
- **机械动作：** 点名你本能选的那一层；点名它下面那一层；说明各自修什么、各自留什么坏着；在价格可见时做选择。

这是上面广角镜的垂直双胞胎："上下文非指令"跨席位保护综合，"你在对的层吗"跨层保护综合——这是对每个修复都该问的问题，每一次都值得往低一层看一眼。
