# 发布边界 —— 每个栅栏跑一次的家务清单

这是一份判断指南清单，不是门禁：每一项都说了**为什么**，大多数项只有一个动作，任何情境性事项在下一个边界即过期。每个发布栅栏跑一次，在上一个发布的仪式完成之后。项目和席位 owner 选定适用动作，并把理由保留在边界记录里。

## 1. 席位 —— 按每个席位的连续性需求，重置或重新上料

- **和 owner 一起为每个席位选连续性。** 全新启动、带重新上料的受管压缩、或保留当前会话，服务不同需求。光看角色名选不出来。记录选择、理由和未决工作的保管权；选一个流程本身并不授权一个生命周期动作。
- **全新启动**可以清掉积累的上下文、加载当前启动指引。在授权退出之前，保留席位挣得的知识和接续材料（在 provisioned 处补一段 recap）；核验新占用者的真实身份和安装。
- **带重新上料的受管压缩**可以在保留规划连续性的同时，恢复下一阶段所需的上下文。**保留当前会话**可以维持正在进行的保管。两种情况下都要检查哪些指引已过期，并投递选定的当前上下文；磁盘上的编辑不是投递到会话。
- **重新上料 = 世界行走 + 当前能力增量 + 任务目标安装**，按 mission-install 约定（`docs/reference/mission-install.md`）：世界那半恢复"你在哪"；项目那半（五层、两种深度剖面、节拍化指针行走）恢复"你在做什么"。从具名产物组合，让来源优先级保持可见。
- **仪式本身就是实验。** 上面每个动作都跑在产品自己的原语上，所以仪式同时是它们的活体测试。被动观察：每个重新上料的席位头几个自然回合伸手去够什么？什么坏了？发现落在边界记录旁边一个带日期的观察文件里。

## 2. 记忆 —— 蒸馏，绝不堆积

- 逐席位的 learned 文件：一轮蒸馏。裁剪测试是："它最近改变过一个决定吗？" 留着那些；其余的移到同一文件里一个带日期的归档段。一个 learned 文件体积大了之后就不再约束、开始自我辩护。
- 任何共享智能体记忆：同样过一遍、同样测试；退役被本次发布证伪的条目。
- 已完成发布的任务目标笔记：**封存为记录**，什么也不带过去。新任务目标从零开始。规则不迁移；需求通过计划迁移。

## 3. 队列 —— 按目的地清扫，全部处置

- 每个席位清扫自己的目的地，找出未决行（wake 不可靠；清扫才是读取）。已完成发布留下的每个未决行，恰得其一：带收据完成 · 带到新任务目标（对新计划重新立案，绝不拖拽）· 因被取代而关闭。清扫暴露那些错过的 wake 或过时记忆工作清单可能藏起来的义务。
- 核验每份交接文件的继承都有一个带 owner 的活 intake 行。零孤儿。

## 4. 基底 —— 拆除作为它自己的原子

- 保留当前发布和紧邻的上一个发布。在发布 N 的边界上，N-2 及更早的 worktree 和其他发布范围基底可以清理。"合格"不等于"有权丢弃独特的脏字节"：先归档或另行处置那些。用真实的 ref 和身份识别活的 `main` 和运行时状态，绝不靠一个过时目录名。
- 修剪 worktree；删除会话范围的 scratch 树；核验已合并分支已删（合并收据授权）。
- 临时目录里的 scratch 家和场景根：清扫。
- 运行时安装：保留 LIVE + LAST-KNOWN-GOOD；归档 hotfix 链；处置启动器备份。
- 中途发布产生的 vendored 文件备份，在包含真正修复的发布上线后删除。
- 已拆除拓扑的快照：每条一行索引，或删除。

## 5. 仪器与看板

- 已完成发布的跟踪和计划看板：**冻结**为记录，并贴标签说明。新任务目标拿全新看板——先有 markdown 真源，看板从它派生。
- 冻结的评审标准：归档在证据旁边，标注"可用、未削弱、不是门禁"。
- 在任务目标开始时抓一份干净盒子的基线收据（负载、进程数、健康尾延迟）——下一个性能问题值得有个 before。

## 6. 能力增量生命周期（常设法律）

每个发布的能力增量在栅栏处撰写，绑定到确切候选，然后对账到发布出去的切点。它的基线是 canon 实际上次吸收的标记，而不是假设紧邻的上一个 semver 已被吸收。当 canon 落后时，新增量是中间所有增量的累积综合，保留取代和 pivot，而不是把旧散文拼接起来。

Canon 吸收保留下来的公开产品真理。过期需要**同时**满足：canon 头部点名该确切增量**且**存在一个独立的后继增量文件。光有头部不能让它过期；缺失或读不出来的输入保持 unknown/live。在真正的边界上，先核验事件再记录过期，然后停止引用过期增量。不要仅仅为了让条件成立而造一个后继。候选被吸收不等于已发布或已在生产中被采用。

私有项目拓扑、主机实践和发布归属，进入带版本的项目世界，而不是漏进公开包。新发布的增量义务从**它自己的**切点开始。

## 7. 世界吸收与可发现性

- 每个变更的能力拿一张小地图：**用户处境 · 当前能力 · 权威来源 · 自然的首次产品遭遇 · 持久上下文住所 · 干净智能体探针**。已经是好路线的，记下来别动。
- 优先用现有 `--help`、错误、命令输出、活状态、上下文目录、工作安装或 skill 路由器里的"点处真理"。世界安装提供宽度和本体；它不该复制活界面能派生的确切事实。
- 发布任务目标在可能时于切点前负责这轮审查，好让公开世界/帮助改动随能力一起发布。本边界核验打包出来的确切结果，把任何漏掉的吸收作为显式债务补上，吸收私有项目真理，重新上料，并观察一个干净装好世界的智能体能否从它的处境出发、不被点名就到达该能力。
- 缺失路线是一个发布发现。修最小的既有接缝，或把有证据的缺口存进可派生上下文任务目标；不要在边界造第二个能力注册中心、搜索服务或世界仓库。

## 8. 边界上刻意不做什么

- 不做流程迁移：情境性规则在栅栏处过期。常设语料库是四条检查原则——按效果验证 · 证据在源头 · 诚实裁决（包括对自己不利的）· 绝不捏造。
- 不重审已完成发布的裁决；封存文件就是记录。
- 不给本清单加项，除非附上一个活过的样本。
