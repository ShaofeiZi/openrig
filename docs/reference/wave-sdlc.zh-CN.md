# wave SDLC —— 并行构建、wave 级评审、组合即关怀档位

这是 `sdlc-conventions.md` 组件菜单里一个可选的构建与评审模型。任务目标 owner 判断它是否适合这份工作。本模型里的锁章是**增量**的：批准追加元数据，绝不改写已撰写字节，所以一个候选的身份在它自己的批准后依然存活。

## 一段话讲清这个模型

各 slice 在所有构建类席位上**并行**构建，每个在一块**不相交的文件领地**里，每个在其候选带着构建者证明的收据冻结的那一刻，由一个集成者串行合入。独立评审**每个 wave 做一次**，覆盖该 wave 累积的整段范围——两个不同视角（最好是不同运行时）的评审者，绝不是作者本人——他们的发现驱动修复轮，在该轮的最终修订上重新挣回两个裁决。检查保持逐 slice（先失败测试证明、按效果验证、诚实收据）；轮次按 wave 发生。

## 机制

1. **PLAN（计划）：** 计划记录里的 wave 条目；规划者塑造 spec；计划权威锁章。每个 slice 必须有一个真实工作区，否则证明无家可归。
2. **DISPATCH（派发）：** 指挥棒带着**独占文件领地**扇出。**brief 就是单元**：每次派发都带着目标、验收标准、完整的上下文路由（确切路径）、领地——以及这条常设授权："自己导航实现：派生你需要的东西、调研、派读者、决定你自己的构建顺序。卡住就问；编排者在这儿帮你。" **默认范围是整个 spec**，一次持续跑完，产出一个冻结候选。派发更小的块必须在 brief 本身上点名理由（一个未决决定、一个活的领地冲突、一个真实的岔路风险）——一个没解释的小块是派发缺陷。领地重叠 = 串行。构建中途发现冲突 = 停下裁决。原因：构建者持有 spec 和代码；怎么建的决定属于构建上下文所在之处。详细的排序指令在模型弱的时候是脚手架；今天它们是笼子，逐命令路由是失败模式，不是勤奋。**brief 是地图，不是领地。** 蒸馏是受欢迎的——对一个极小 slice，brief 诚实地可以比 spec 更丰富——但它绝不是接收者**唯一**的上下文：构建者的第一个动作是按路由阅读清单做自 onboarding（slice 规模上的 mission-install 模式），然后拿地图对照它实际站的地面。没人比构建者更懂一层地板；广角镜在上一层。当地面和地图不一致时，那是一个要上报的发现——不是跟着地图冲下悬崖的理由。
3. **BUILD（构建）：** 在干净基线上先失败测试，测试字节最终提交；冻结单个候选修订；收据引用**最终**修订（任何 rebase 后重新挣得）。
4. **MERGE（合并）：** 仅集成者、串行、每次都在源头验证（候选 parent 等于合并前 tip；改动文件等于声明领地）。合并公告是对所有未决候选的 rebase 触发器。
5. **WAVE REVIEW（wave 评审）：** wave 构建完成时触发。两个独立评审者，在 tip 上按基线范围，作者不评自己的活。两道门问**不同**的问题——结构站得住吗，对每一条主张接触源码后还成立吗。这是设计，不是冗余。评审者也评审**漂移**，不只是缺陷：建出来的东西还匹配 brief 陈述的验收标准吗——这还是 owner 要的狗屋吗，还是那些局部站得住的步骤堆积成了一个月球基地？走样是一等发现，和逻辑缺陷同列。评审还按原因**处置**每个漏项：CONTEXT-GAP——spec 或它的路由缺了当下需要的东西（一个规划发现；修复落在 spec 里）——对比 JUDGMENT-GAP——上下文在场、但判断错了（一个构建者发现；修复是一条检查）。裁决产物里一个词。它产出的比率，就是派发形状用来校准的东西。
6. **FIX ROUNDS（修复轮）：** 发现变成前向修复候选（合并站住；已合并不等于在跑）。每轮一次重审，在最终修订上重新挣回两条腿。窄修正配窄复查。
7. **SEAL（封存）：** 两条腿在同一个修订上都过 = wave 封存；下一个槽位打开。

## wave 就是关怀档位

wave 的**组成**是"一件事被多仔细地对待"的控制面：一个大的、复杂的或承重的 slice 有**它自己的 wave**（它的评审仪式只为它单独触发）；一个大块甚至可以跨 wave 拆分。这把一个旧模型混在一起的两件事解耦了：任务目标和 slice 工作区保持灵活的组织容器；wave 是独立的一层，负责排工作顺序、派工作、并给它的处理关怀定价。关怀是逐件事的属性，从来不是逐任务目标的。

## 什么时候用

许多中小、根因清楚、有证据支撑的 slice；席位够多可以并行；领地能干净切分；一个能串行合并、快速验证的集成者。

## 什么时候别用

设计不确定或共享区域的活（一个 slice、经典两腿评审，或先开设计会）。一小时内不可逆的任何事（发布、割接、破坏性操作）——那是重路径。以及当没有独立的、不写作的评审者时：没有东西会自评；没有他们，wave 门就是演戏。

## 失败模式与缓解

- **冻结-合并赛跑：** 一个候选在合并不动 tip 前几秒冻结。缓解：在隔离 worktree 里做零重叠 restack，带内容身份证明（稳定 patch-id）；合并公告时构建者侧自查。
- **证据演戏：** 一个因错因而失败的失败测试，读起来和真的一模一样。缓解：评审者独立重新派生失败；错误定性退役到修正史，绝不静默改写。
- **"存在而非缺席"测试：** 断言真行存在，却让假行还在打印。规则：在每种编码里都钉死假主张的**缺席**。
- **幽灵 checkout 状态：** 引用式合让共享 checkout 的 index 过时。绝不在共享 checkout 里构建或提交；在栅栏处同步它的 index。
