# 知识成熟度 —— 认知阶梯

**本文件是成熟度模型的权威住所**：阶梯本身、它的时间尺度、晋升与降级、warrant 规则，以及成熟度在每个界面上如何承载。一个说不清自己信任模型的语料库，也就没法告诉你它正在腐坏——这就是本文件存在的原因。

## 阶梯

知识爬四级：

**DATA（数据）→ FIELD NOTES / OBSERVATIONS（现场笔记/观察）→ INSIGHTS（洞见）→ CANON（正典）**

信任跟随成熟度，**一个主张的地址就告诉你它的信任度**。每一级的预期变化速率大致比下一级慢一个数量级：

| 级别 | 变化时间尺度 | 住在哪里（按地址） |
|---|---|---|
| Canon（正典） | 年 —— "它一直是对的，我们只是在发现和策展它" | `conventions/` · `doctrine/` · 原语 · `SOP.md` · `CULTURE.md` |
| Insights（洞见） | 月 —— 稳定，仍在挣 | `LEARNED.md` 上半 · 大多数 skill 的判断内容 |
| Field notes / observations（现场笔记/观察） | 天–周 —— 紧跟现实 | `NOTES.md` · `LEARNED.md` 的原始下半 · `field-notes/` |
| Data（数据） | 持续 | 流事件 · 转录 · 收据 · 日志 |

## Canon 由它的时间尺度定义

"让一件事成为 canon 的，是它预期变化非常慢。" canon 之下一切变化更快，越往下越快。一次对 canon 界面的更新几乎绝不意味着"canon 变了"——它意味着我们发现或策展了更多本来就是 canon 的东西。`LEARNED.md` 是跟踪变化现实的文件；`SOP.md` 是沉淀已定真理的文件。

活出来的后果：**一个 canon diff 应当读起来是"追加"。** 频繁编辑已有 canon 行是一种坏味道——要么那行从来不是 canon（降级它），要么真有东西变了（一次 pivot，值得有仪式感）。

## 晋升与降级

晋升是每一级上的一个显式动作：**收获/注意 → 用自己的话折入 → 策展（显式、带日期）。** 内容以它当下的任何成熟度进入活层（`LEARNED.md`），随时间证明自己稳定，然后毕业。

发现向上流；canon 几乎从不向下流——而当它发生时，那是一个值得注意的降级事件。**降级合法但很响（LOUD）**：它刻意信号化"曾经以为的 canon 不再成立"。

## warrant 规则

**一个被晋升的主张带着它压缩过的 warrant** —— 为它挣得地位的那块疤痕、证据或裁决，随它一起走。"没有 warrant 的 canon 是排版漂亮的 cargo cult。" 当 warrant 点名分级时，warrant 等级保持可读：一个有决策背书的主张和一条反复确认的定律，不必假装携带同等证据。本文件自己的 frontmatter 就在践行这条规则。

## 成熟度是多维的

上面的认知阶梯是一维。第二维是**上下文架构阶梯**：上下文如何被生产，最底一级是"世界形状里的散文"——可理解、有效、但容易漂移；最顶一级是"从源派生"，那里的内容不会腐坏，因为一条命令会重新派生它。

产品成分是**阶梯概念本身——把系统建得让信息向上爬**——而不是任何具体的级数。这里的级数是描述性的，不是规范性的。设计系统时要想着"爬"：让日后派生成为可能的接缝，从诞生就贴标签，好让信任元数据在任何机器读它之前就开始积累。

## 两种编码，一架梯子

成熟度在不同界面上承载方式不同。下面是同一架梯子的两种编码，按界面支持什么来选——不是矛盾。

**语料库和树文件按地址承载成熟度。** 文件名法则就是梯子：`NOTES.md` 是现场笔记，因为名字就这么说；`conventions/` 和 `doctrine/` 按位置就是 canon。晋升或降级是一次**移动**，而一个响亮地打断引用的移动是个特性——改变信任应当有仪式感。不需要逐节级别标签；地址就是标签。

**Pack、lore 和 scope 条目从诞生起就把成熟度当作一个 stage 字段承载**，使用随包发布的词汇（四级加两个出口）：

`wip | provisional | established | canonical | superseded | retired`

`superseded` 必须点名它的继任；`retired` 表示"不要使用"。这些是**唯一**合法值——自造阶段（shape、shaped、draft）会被拒绝。按新约定铸造的条目从诞生起就带 stage：从第一天贴标签是免费的，事后补标是考古。

本节是 lore 和 pack 工作的 stage 词汇来源。分类轴（WORLD / LORE / SKILLS / MISSION）与 stage 正交：**分类说是什么种类，stage 说有多可信。**

## 成熟度不是什么

有两条轴习惯上被和成熟度混在一起，但它们不是：

- **受众/位置。** 受众决定知识住在哪里——哪个高度、哪个文件；成熟度给文件里的那一行分级。一个 pod 级条目可以是原始观察，一个席位级条目可以是 canon。晋升到 canon 是一个成熟度事件，不是沿树向上移动。关于机制的事实可以跳级（一条命令的验证就定了）；关于实践的推断必须积累证据。
- **功能生命周期。** "功能生命周期与认知成熟度是两回事" —— 生命周期（`active | deprecated | retired`）回答智能体是否还该在一个行为上继续建设；成熟度回答一条知识有多可信。

## 方向，不是施工

一个可能的终态是一棵"级别优先"的语料树，一个地址字符串同时携带信任、领域、主张和新鲜度。它只是方向。

**本文件里没有任何东西被机械化**：没有强制工具、没有大规模重贴标签、没有新的分级方案。本文件确立上面的词汇和"从诞生贴标签"；读者、一致性检查和晋升工具都在其范围之外。
