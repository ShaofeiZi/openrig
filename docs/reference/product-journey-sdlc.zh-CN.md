# 产品旅程 SDLC 组件

这是一个可复用菜单，用来搭出最小的完整用户结果。一个任务目标或 slice 只选它工作需要的组件，并在 mission/slice YAML 里记录顺序。这**不是一个模式、流水线、拓扑、工作组形状或强制门禁集**。如果没有组合，用 `sdlc-conventions.md` 里轻量的 Part A 流程。

## 狗屋与月球基地

**狗屋（doghouse）**是用户真正要的产品结果。**缺一扇门**是一个内部也许打磨得漂亮、却干不了基本用户活的实现。**月球基地（moon base）**是一堆精巧机械——常常是护栏、抽象、证明仪式、安全剧场或流程脚手架——消耗了大部分力气，却没让狗屋能用。

按这个顺序用那把披露梯子：

1. 一句话说出狗屋，不用流程词汇。
2. 在赞叹内部之前，先通过公共界面操练它的门。
3. 修最小的、缺失的产品接缝。
4. 只有当证据表明下层在造成可见失败时，才考虑更深的机械。
5. 移除或拒绝任何不保护、不交付一个具名用户结果的东西。

同一套纪律对新任务目标和拯救一个漂移了的任务目标都管用。新任务目标里，它防月球基地；拯救里，它找出还有没有一个能用的狗屋，并把它和不该带走的机械分开。

## 组件契约

下面每个组件都写明：

- **何时用** —— 接纳它的证据。
- **何时跳过** —— 不跑它的最便宜理由。
- **输入** —— 负责智能体实际必须读或观察什么。
- **动作** —— 执行的有界工作。
- **输出** —— 交给下一个组件的产物或可观察结果。
- **停止** —— 防止组件自我扩张的边界。
- **下一步** —— 正常后继；YAML 可以选另一条显式边。

组件 ID 是稳定地址。它们的散文可以改进，而不迫使 mission YAML 改动。

## 组件目录

### context.fresh-start

- **何时用：** 既有上下文可能带着过时架构、裁决或实现惯性。
- **何时跳过：** 当前智能体能独立从一手来源说出用户结果、起始候选和边界。
- **输入：** 身份、项目/任务目标/slice YAML，以及选定地址。
- **动作：** 把选定上下文加载进一个新会话，或从活源重新定向当前会话。清一个席位需要它单独的连续性决定；选这个组件不授权它。
- **输出：** 一段就绪声明，点名角色、用户结果、起始候选和边界。
- **停止：** 不要只因旧队列 lore 存在就重建它。
- **下一步：** `intent.recover` 或 `journey.choose`。

### intent.recover

- **何时用：** 工作已存在，但可能已偏离它最初的用户意图。
- **何时跳过：** 这是绿地工作，有一个当前的、无歧义的意图。
- **输入：** 最早的权威意图、后来的 mission/slice spec、候选代码，以及观察到的用户行为。
- **动作：** 区分需求和后来规划者的展开；找出最小仍需要的结果和显式反目标。
- **输出：** 一张简洁的拯救图：保留、检查、不需要——绝不本身就是一个破坏性裁决。
- **停止：** 不要把既往评审强度或沉没成本当产品价值。
- **下一步：** `journey.probe`。

### journey.choose

- **何时用：** 一个新任务目标有意图，但还没有被证明的产品路径。
- **何时跳过：** `intent.recover` 已经点名下一个最小结果。
- **输入：** 权威意图和当前公共产品界面。
- **动作：** 选一条端到端用户旅程，它的完成自带独立价值。
- **输出：** 一个可观察结果，加它最小可信的公共探针。
- **停止：** 只要一个结果；相邻能力是另一次组合。
- **下一步：** `journey.probe`。

### journey.probe

- **何时用：** 总是，在加或拯救产品代码之前。
- **何时跳过：** 绝不；把探针做小，而不是跳过。
- **输入：** 真实用户操作的公共 CLI、API、UI 或其他界面。
- **动作：** 跑最小的一次性端到端旅程，检查它的效果，而不只是退出状态。
- **输出：** PASS（不需要代码），或一个具体的、用户可见的缺口，带保留的证据。
- **停止：** 一次通过的旅程不授权投机加固。
- **下一步：** PASS 就收尾；否则 `depth.look-below` 或 `build.minimal-gap`。

### depth.look-below

- **何时用：** 公共失败反复出现、跨组件边界、被下层状态矛盾，或一个表面补丁会复制下层已拥有的逻辑。
- **何时跳过：** 失败局部、已理解、能在公共接缝修而不重复；也在唯一论据是"更健壮"时跳过。
- **输入：** 一个观察到的公共失败和直接负责的接缝。
- **动作：** 只下**一层**；说出因果假设，点名会证伪它的下层观察，然后检查或探那一层。
- **输出：** 三个深度决定之一：
  - `LOCAL` —— 修公共接缝；
  - `BELOW` —— 修点名的承重接缝，重放公共旅程；
  - `HOUSEKEEPING` —— 改产品代码之前先修环境/数据/拓扑卫生。
- **停止：** 每次准入下一层。第二次下探需要新证据和新陈述的假设。"既然来了"、泛化预防和无关清理都出范围。
- **下一步：** `build.minimal-gap`、`research.before-build` 或 housekeeping。

这个组件是平衡点。永不下探产生表面补丁和反复缺陷；没有证据门就下探产生月球基地。目标是第一个承重接缝，不是尽可能深的解释。

### research.before-build

- **何时用：** 因果假设依赖一个不稳定外部事实，或一个本地派生不出来的产品契约。
- **何时跳过：** 源、运行时状态和公共探针已经确立机制。
- **输入：** 一个可回答的未知和它的决策后果。
- **动作：** 只拿够决定实现形状的一手证据。
- **输出：** 决定、引用和剩余未知。
- **停止：** 实现决定有支撑时调研结束。
- **下一步：** `build.minimal-gap`。

### build.minimal-gap

- **何时用：** 一次失败旅程和因果接缝已确立。
- **何时跳过：** `journey.probe` 通过，或发现是 housekeeping 而非代码。
- **输入：** 用户可见缺口、深度决定、既有接缝和显式边界。
- **动作：** 加最短可读改动完成旅程，复用既有产品接缝。
- **输出：** 一个干净候选，加失败因所述原因而改变的聚焦证据。
- **停止：** 不引入新框架、安全层、schema、抽象或相邻动词，除非没有它结果就不工作。
- **下一步：** `qa.public-journey`。

### qa.public-journey

- **何时用：** 一个候选声称完成了一个用户结果。
- **何时跳过：** 集成前绝不；只在独立性未被选中时，才允许构建者在极小改动上自验。
- **输入：** 确切候选、原始公共探针和边界。
- **动作：** 在一次性上下文里从用户界面跑旅程；检查结果状态和部分失败行为。
- **输出：** CLEAR 或一个具体不匹配。
- **停止：** QA 不重新设计产品，也不要未选的仪式。
- **下一步：** `review.scope-maintainability` 或回 `build.minimal-gap`。

### review.scope-maintainability

- **何时用：** 为该结果选了独立评审。
- **何时跳过：** 组合刻意把一个低风险改动留在轻量单智能体路径里。
- **输入：** 确切候选、意图、公共 QA 证据和 base diff。
- **动作：** 判断正确性、可读性、必要性、既有接缝复用，以及公共旅程（不是内部代理）是否工作。
- **输出：** CLEAR 或一个有界的源/产品发现。
- **停止：** 评审者不能只因前次评审找到了东西就拧紧 rigor；评审产品，不评审仪式。
- **下一步：** `integrate.one-outcome` 或回 `build.minimal-gap`。

### integrate.one-outcome

- **何时用：** 一个结果选定的证据完整。
- **何时跳过：** 候选不清，或它的 base 不兼容移动了。
- **输入：** 确切候选身份和选定的 QA/评审结果。
- **动作：** 集成最小连贯结果，无关候选分开。
- **输出：** 干净规范源，多含一个用户结果。
- **停止：** 不要因为共享一个发布标签就批量无关拯救。
- **下一步：** `runtime.adopt` 或下一个 `journey.choose`。

### runtime.adopt

- **何时用：** 结果需要已装运行时或迁移证明。
- **何时跳过：** 源级证明足够、且没有活行为改变。
- **输入：** 干净规范提交、回滚边界和运行时 SOP。
- **动作：** 构建/打包/安装确切提交，原子切换，核验健康加连续性。
- **输出：** 确切活版本和保留的回滚点。
- **停止：** 采纳就是部署，不是改拓扑或数据的许可。
- **下一步：** `qa.installed-smoke`。

### qa.installed-smoke

- **何时用：** `runtime.adopt` 跑过，或打包/路径解析是产品声明的一部分。
- **何时跳过：** 没有已装产物或运行时行为在范围里。
- **输入：** 确切活版本和一次性公共旅程。
- **动作：** 操练已装命令路径，核验效果和清理。
- **输出：** 已装运行时 CLEAR 或一个具体不匹配。
- **停止：** 不要把 smoke 测试变成舰队级监控。
- **下一步：** 收尾结果或回 `build.minimal-gap`。

## 组合规则

1. `project.yaml` 可以声明项目默认；`mission.yaml` 可以选目录并为任务目标覆盖那些默认。
2. `slice.yaml` 为该 slice 选或覆盖组件。
3. 边是显式数据。数组顺序是展示，不是依赖。
4. 选最少数诚实适合这份工作的组件。
5. 一个组件可以和它邻居由同一席位持有，除非独立性是组合的刻意属性。
6. YAML 描述工作；它不是强制引擎，不造自动门。

仓库地址示例：

```yaml
sdlc:
  catalog:
    root: repository
    address: docs/reference/product-journey-sdlc.md#component-catalog
  components:
    - id: journey.choose
      owner: planner
    - id: journey.probe
      owner: qa
    - id: depth.look-below
      owner: builder
      admission: evidence-gated
    - id: build.minimal-gap
      owner: builder
    - id: qa.public-journey
      owner: qa
  edges:
    - from: journey.choose
      to: journey.probe
    - from: journey.probe
      to: depth.look-below
      when: 公共失败需要因果判别
    - from: journey.probe
      to: build.minimal-gap
      when: 局部缺口已确立
    - from: depth.look-below
      to: build.minimal-gap
      when: 决定是 LOCAL 或 BELOW
    - from: build.minimal-gap
      to: qa.public-journey
```

仓库地址从 `git rev-parse --show-toplevel` 解析。在上下文库之外，对 `path#h2-slug` 和 `path#h2-slug/h3-slug` 地址用 `loading-addressable-markdown` skill。

## 组合示例

### 绿地产品旅程

`context.fresh-start → journey.choose → journey.probe → build.minimal-gap → qa.public-journey → review.scope-maintainability → integrate.one-outcome`

只在探针命中其准入规则时加 `depth.look-below`。新任务目标不需要拯救考古。

### 漂移任务目标拯救

`context.fresh-start → intent.recover → journey.probe → depth.look-below? → build.minimal-gap → qa.public-journey → review.scope-maintainability → integrate.one-outcome`

问题不是"哪些旧提交过评审？"而是"哪个需要的用户结果能用，什么挡着下一个，以及多少代码就能完成它？"

### 反复出现的跨层缺陷

`journey.probe → depth.look-below → research.before-build? → build.minimal-gap → qa.public-journey → qa.installed-smoke?`

反复出现准一次因果下探。它不授权一次泛化平台重写。

## 解析选定路径

在全新启动、恢复或新分派时：

1. 用 `zrig whoami --json` 派生身份。从分派/工作区绑定解析项目的工作根；`zrig config get workspace.root` 定位配置好的工作树，它可能不同于席位的代码检出。
2. 读 `project.yaml` 及其项目权威上下文。沿它的任务目标根到分派的 `mission.yaml`，再沿它的组合引用到活动的 `slice.yaml`。读这些记录点名的当前意图和验收文件。不要从一个旧 onboarding packet 或一个文件夹的新旧选任务目标。
3. 按顺序解析 SDLC 选择：项目默认、任务目标默认、然后活动 slice 的显式选择/覆盖。一个更窄的显式选择替换更宽的组件列表；它不追加每个祖先的门。跟随一张带地址的 wave 图看它的成员、评审模型和边界；一个显式具名 slice 例外只对该 slice 生效。
4. 只读选定组件和额外按地址的上下文。仓库引用从代码仓库根解析；已装引用从 `$OPENRIG_HOME/reference`；context-pack 引用用 `zrig context get`。对一个 Markdown `#section` 地址，用 `loading-addressable-markdown`，而不是加载整份无关手册。当任务证据需要时扩展调查：地址图是起点，不是搜索上限。
5. 简短陈述用户结果、当前角色、候选、选定路径和下一个完成边界。没有组合就是 `sdlc-conventions.md#a1-the-flow-in-one-pass` 里的轻量 Part A 流程。不要只为有一个组合而写，也不要因为那些角色存在就铸造 QA、护栏、评审、锁或证明门。极小改动上构建者可以自验整个结果；独立评审只在选了时发生。

一个缺失的被引用文件是一个具名缺口，不是没选的证据。检视或请 owner 解决一个有后果的歧义；不要从一个显式选好的严格路径静默回退。owner 可以为具名工作显式修订选择；在该工作的权威处记录那个决定。当前命令/源现实作为事实主张胜过过时 YAML：记录不匹配、重新派生、并保留范围与观察状态之间的区分。

启动叠加、角色指引、可用席位、旧模式名和历史 packet 不能给这个选择加步。它们提供能力。skills 在选定工作需要时加载；没有测验、逐文件 ACK 门或通用预加载要求。

## 空白智能体启动

选工作之前先遵循上面的"解析选定路径"。对一个撰写好的 wave，用它本地纪律构建并核验每个 slice，在需要处串行集成；在撰写 wave 边界到达时请求一次独立评审。别在等待时逐 slice 开评审。一个单独选好的严格 slice 保留它具名的检查。评审发现为有界修复辩护，不为下一轮自动加流程。
