# 任务目标安装

一个加入工作的智能体需要两次安装。**世界安装**教它现在身处的系统——这是什么地方、怎么行动、能做什么。**任务目标安装**教它项目——正在构建什么、怎么走到今天、现在在哪、以及哪块是它的活。本文件是后半部分的约定。它适用于任务目标树能装下的任何项目：软件、一本书、记账、研究。

**写这个约定的读者，是那个帮不上你的读者。** 一个全新启动或刚清空的智能体不会自己拉上下文——它不知道有什么，所以没法问。下面每条规则都从这一点推出：安装是**替智能体组合好、由已经持有项目的人逐块推送**的。

## 什么时候跑一次

- 一个新席位加入任务目标。
- 一次占用者交接：继任者先继承席位，再拿到项目。
- 一次发布或阶段边界：每个继续的席位在新前沿重新上料。
- 一次项目切换：一个席位从一个任务目标换到另一个。

永远在世界安装**之后**。任务目标安装假定读者已经在情境里。

## 五层

每次安装都按这个顺序、从这些层组合。它们是骨架，不是脚本——深度剖面（见下）决定一个具体席位拿到每层多少。

1. **PIECES（件）** —— 已撰写的历史和设计：解释项目怎么走到今天的产物。按地址从任务目标树组合，每件带它的源路径和内容哈希。绝不改写。
2. **ARRANGEMENT（排布）** —— 件之间怎么连。这是唯一内容不在别处磁盘上的层：一份由持有过工作的人写的 recap，说明什么把件连起来、该信什么、什么取代了什么。如果没有排布文档，写一份就是准备安装的一部分——它是派发者的知识，存下来。
3. **POSITION（位置）** —— 这个席位具体学到并持有什么：它积累的教训文件和最近一次 recap。位置对谱系是私有的；它被安装，绝不发布。
4. **CONTRACT（契约）** —— 当前计划和未决决定。这是变动最快的层，所以每个契约件必须带自己的 `updated-at`，任何在组合时未重新派生的事实带一个显式 `UNVERIFIED` 标记。一个过时计划比缺失更误导。
5. **DERIVE-YOUR-OWN-DELTA（自派生增量）** —— 最后走的那件派一个**派生清单**：被安装者必须自己重新派生的易变事实，每条写成派生它的命令（绝不写成一个被记住的值）。被安装者跑这个清单，写一份**带日期的 delta**——安装没说、但现在为真的东西——作为它的第一个产物，放在席位 recap 旁边。这一层把一次简报变成了一次仪表检查。

## 两种深度剖面

- **规划类席位拿 FULL（全）深度**：跨五层的完整有序阅读集，终止于活工作指针（当前计划自己的下一项）。
- **执行类席位拿 HIGH-ALTITUDE（高空）深度**：少数几条带地址的阅读——项目框架、治理范围契约、源索引、操作 playbook——加第 5 层。slice 级深度刻意**晚些**到，随每个路由过来的工作项，其 spec 自己以完整设计契约开篇。

情境（全新、交接、边界、切换）在层上选子集；席位类别选深度。别把一切发给所有人。两种不变量在任何深度都成立：**排布层绝不跳过**（它告诉读者该信谁），以及**一个没有匹配产物的剖面槽，在安装时绝不凭空撰写**——用一个派生清单填它（加进 derive list），或留空并说明。

## 投递规则

- **推送，替智能体组合好。** 派发者组合；被安装者接收。一条消息一件，节拍化，件与件之间留吸收的余地——把同一批字节拼接倾倒，无论内容如何都是一次失败投递。
- **默认指针行走**：对一个已做过世界安装的席位，每条节拍化消息点名要读的产物，并把这次阅读框成席位自己下一个任务的前置。席位自己执行阅读；阅读就是安装。
- **只在席位读不了时字节行走**（无文件访问、跨机投递）：那时行走才带字节，分块，绝不一次一整块。
- **在消费要紧的地方逐件要反应**：一句话说明这件对读者改变了什么。一次静默行走是未校验的投递。
- **指针可以按节限定。** 当一个文件把安装内容和参考材料混在一起，指针点名要读哪些节、哪些节是参考；读者的反应点名实际读了哪些节。当两个消费方一直需要不同子集时，拆文件更好。

## 任务目标选定的执行组件

一个任务目标可以带 `mission.yaml`，一个 slice 可以带 `slice.yaml`，作为工作排布的地址图。存在时，把 `mission.yaml` 装在 ARRANGEMENT 层，活动的 `slice.yaml` 装在 CONTRACT 层。先读任务目标文件；slice 可以收窄或覆盖任务目标默认。

可复用组件目录在仓库 `docs/reference/product-journey-sdlc.md` 和已安装的 `$OPENRIG_HOME/reference/product-journey-sdlc.md`。一个 `root: repository` 的目录从 `git rev-parse --show-toplevel` 解析；用 `loading-addressable-markdown` skill 做带地址的 H2/H3 节。

被安装者认领工作之前，要求一条就绪声明，点名：**角色；用户结果；起始候选；边界**。选定的组件 ID 和显式边排布工作；它们不扩范围、不造模式、不设门。如果没有组合，`mission-slice-sop` 里轻量的 Part A 流程就完整了——缺失不是铸造 YAML 的理由。

## 组合，不是生成

安装**组合已撰写、带引用的产物。它在安装时绝不生成摘要散文。** 一个生成的摘要是第二个会漂移的源，没法信也没法验；一个撰写的件带着它的出处。为安装而产生撰写的唯一位置是排布层——而那是由对此负责的人写下、保留复用的知识，不是每次安装重新生成。

## 排除规则

任务目标树会积累一些**参考材料，绝不是安装内容**：事件残渣、被取代的规划、转录归档、为记录保留的死路。安装继承一个**清理过的**视图——当前真相，加排布对它怎么来的叙述。被排除的材料保持可寻址；排布可以指向它，但行走从不带它。准备安装时，把每个候选件分类：安装内容还是参考。拿不准，就是参考。

## 第 5 层校验循环

第 5 层是一个序列，不是建议。全部跑完：

1. 派发者最后走的那件派 derive list——每个易变事实配对派生它的命令——**并点名 delta 的确切目标路径**（新席位还没有 recap 可放旁边；派发者决定住所，被安装者不猜）。
2. 被安装者跑每条命令，在点名路径写带日期的 delta。
3. 派发者核验产物**存在**（不是被声称存在）。
4. 第二个读者——任何不是被安装者的人——检查 delta 的**事实**。当项目只有一个派发者和一个被安装者时，派发者做事实检查，delta 记录这次检查是自己做的——一次诚实降级，明说，绝不静默。
5. 一个事实错误触发一轮重派生：被安装者重跑命令、修正、重新封存 delta。修正轮是价值，不是开销：它一次动作里既验证消费、又校准仪表。

一个**没有派生命令**的易变事实——只有人或外部方能定的——照样上清单，标 `UNVERIFIED`，带一条显式 ask 指令；delta 带着它未决前进，而不是静默采用一个值。

一份没有落地、校验过的 delta 的安装不完整。那是一次广播。

## 保真法律

活在对话里的设计细节，在**铸造时存入**。一个工作项的 spec 只有一行 intent、而真实设计填满了一场讨论，是 20:1 压缩——从它构建，正确性纯属巧合。因此本约定点名存入的设计住哪：工作项自己的**design-contract 块**（或旁边一个 DESIGN-INPUT 文件）。第 1 层件指向那份全保真记录，绝不指向压缩的 intent 行。

## 边界

**任务目标安装停在任务目标根。** 它之上的一切——更宽的系统是什么、团队形状、文化——属于先跑的世界安装。往项目根以上追溯是另一个工具回答另一个问题。一次安装，一棵树。

## 用自带机制组合

各层从已存在的界面组合；不需要新机制：

- Pieces 和契约：一个 `--mission` 授权跨任务目标及其 slice——`zrig context profile <pack-ref> --situation <fresh|handover|post-compaction> --mission <mission>` 组合带出处和内容哈希的、按地址的节。`--situation` 必填，且与深度剖面是**两个**独立输入：situation 说用哪张组合菜单（全新启动、占用者交接、压缩后恢复）；FULL 对比 HIGH-ALTITUDE 说席位类别拿每层多少。两者独立选。
- 具名安装剖面让那个独立的深度/排序选择显式化。`zrig context profile world-public --situation fresh --runtime codex --profile codex-coverage --rig <rig> --seat <seat> --mission <mission> --slice <slice> --json` 是不投递的检视：在任何东西到达席位之前，报告选定剖面、有序阶段、确切件、token 估算、哈希和源出处。`codex-coverage` 剖面排序为 bootstrap → 具体项目/任务目标/角色/任务 → 覆盖图；`guided` 保留更完整的撰写行走，可单独选。两者从同一张源图选。
- Position：`--rig`/`--seat` 授权服务席位的教训和 recap。
- Runtime：`context profile` 和 `context work-install` 都接受 `--runtime claude-code`（别名 `claude`）或 `--runtime codex`。剖面组合保留 `claude` manifest/输出键；skill 投影保留 `claude-code`。剖面从 `OPENRIG_RUNTIME` 取默认，否则 Claude；work-install 要求带这个 flag 才检视或应用 skill。
- 投递：`zrig walk <seat> --through-profile world-public --profile <profile> --situation <situation> ...` 应用已检视过的剖面；`--through <files> --pace <interval>` 仍是原始字节行走路径。节拍化发送、点名按地址阅读的，服务指针行走。
- Delta：席位 recap 旁一个带日期的 markdown 文件；靠读它来校验。

这些动词不可用时（另一套工具链、一个普通文件系统），约定仍然成立：靠拷贝带源路径的按地址节来组合，节拍投递，派 derive list，要求 delta。

## 任意项目快速开始

1. 给任务目标的产物分类：安装内容对比参考（排除规则）。
2. 写或更新排布文档——件怎么连、信什么。
3. 给每个契约件标 `updated-at`；给未派生事实标 `UNVERIFIED`。
4. 选剖面：规划类全，或执行类高空。
5. 如果 mission/slice YAML 选了执行组件，把那些文件和它们按地址的目录节放在合适层。
6. 组合带出处的有序件清单；节拍投递，指针优先。
7. 以 derive list 收尾；要求带日期 delta；核验存在；二读事实；出错重派生。

任何类型的项目都适合：对一本书，pieces 是大纲的历史和语气决定，arrangement 是草稿间关系，position 是这个编辑席位的教训，contract 是带日期的当前章节计划，derive list 是"数章节、读最新编辑笔记、说出今天字数"——新智能体必须亲手碰、而不是信的事实。
