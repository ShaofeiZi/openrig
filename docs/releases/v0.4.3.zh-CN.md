# zrig v0.4.3

## 摘要 — “能够存续的工作组”

zrig v0.4.3 让工作组真正能够存续。即使后台服务或整台机器崩溃——直接断电，而非优雅停止——重启后席位也会回到**原来的**会话，恢复崩溃前 marker，且不会 fresh-prime。证明来自真实的硬断电收官测试：硬断电 → 重启 → `zrig start` → Claude 和 Codex 席位均恢复到各自原始对话。这是“能够存续的工作组”这一核心主张的关键证据。

在存续能力主干之外，本版本还交付了**对 `zrig send` 默认拒绝策略的反转**：现在只有 `needs_input`（目标 pane 中真实呈现的交互 picker）会硬拒绝发送；unknown / stale / missing / busy 均改为“提示后发送”。0.4.1 的三层 guard 在实践中过于严格；0.4.2 修复了 daemon status probe，0.4.3 则调整 send guard posture，使常规 peer 协调不再需要借助 `--dangerously-interact`。真实 prompt block 仍然保留。

Wave-2 UI 为工作区提供工作组状态与启动控制、switch-client view retarget，以及真实 theme 系统（Vellum Dark 选择启用；light 逐字节不变）。完整席位 handover 周期与席位 fork 收尾补全恢复故事，并发布 `mission-slice-sop` 技能作为工作原则。

现有 v0.4.2 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。Migration 045、046、047 均为叠加式。

## 存续能力 — 关键集合

- **崩溃恢复 resume token ledger（FR-3 → FR-7）** — 席位的 resume marker 在 adoption 时捕获（FR-3）、在 snapshot 时刷新（FR-4）、固定到 restore target（FR-5）、通过 1 小时 advisory threshold 和 `--fresh` re-verify 进行 freshness gate（FR-6 + FR-6.1 周期性重新盖戳）；最关键的是，恢复路径绝不会对曾有 resume marker 的席位静默 fresh-prime（FR-7）。FR-7 之前，恢复无法访问 token 时会降级为 fresh-prime，丢失原会话身份；这种静默降级已经消除。
- **Fixture home 隔离 guard** — 可能覆盖运行中工作组 home dir 的 fresh-prime 会被明确拒绝，不再静默吞掉问题。
- **Liveness PID 验证** — 后台服务会先确认进程确实存在，再将席位标为 running，从而区分活跃席位与 dead PID ghost。
- **后台服务 event loop 健康与 terminal broker 韧性** — 后台服务发布 event loop latency 健康信号；`TerminalSessionBroker` 可以跨后台服务重启干净恢复。
- **启动证明** — 席位通过 challenge 验证的读取路径，证明其确实读过 orientation material，而不是跳过。
- **完整席位 handover 周期** — 离任席位可以将捕获的上下文交给全新 successor；resume marker 通过 FR-3 自动携带；handoff 失败时，两条 lane 均触发明确 unwind。
- **席位 fork 收尾** — fork 生命周期在共享 checkpoint 上干净结束；predecessor 与 successor 均被命名并接线。

## 对默认拒绝策略的反转（`zrig send`）

0.4.1 的三层 guard 在 fleet 层面过于激进：unknown / stale / missing / busy activity signal 均默认阻止，常规 peer 协调不得不频繁使用 `--dangerously-interact --reason "..."` override。0.4.3 做出以下修正：

- **只有 `needs_input`（目标 pane 中真实呈现的交互 picker）会硬拒绝发送。** 真实脚枪位置的 guard 行为不变。
- **Unknown / stale / missing / busy** 改为**提示后发送**，不再阻止。Peer 消息会送达，运维人员会在 send 输出中看到 advisory。
- **`--dangerously-interact --reason "..."`** override 仍保留，供有意操作处于 prompt 的席位使用，行为不变。

此外还强化了 **Codex activity signal**：空闲 Codex 席位现在能接收普通 send；真实 prompt block 仍然有效；hook trust autoclear 作为快速后续改进落地，使恢复的 Codex 席位在恢复路径上自动清除 attention gate。

## `zrig send` 统一目标选择

`zrig send` 增加显式多接收方目标选择，包括 recipient list、`--pod` 与 `--rig`，复用既有 broadcast fanout 和逐接收方 guard。保持向后兼容：单接收方发送不变。

## Wave-2 UI 与 Theme

- **工作组状态 + 启动控制 UI** — 用于启动、停止和恢复工作组的工作区界面已落地。它将 topology view 与适用于混合计划工作组的 launch modal 组合。
- **Switch-client view retarget** — 从 switch-client 操作点击进入时，运维人员会到达正确 target view，不会留下过期 breadcrumb。
- **Dashboard theme — Vellum Dark 选择启用** — 提供真实 theme primitive：`light` 是既有 `:root` theme，逐字节不变；`dark` 是首个发布的替代主题；substrate 可通过 token block + registry entry 扩展到 N 个 theme。使用 Tailwind `darkMode: 'selector'`。Light 保持不变。

## 恢复与运维 UX

- **Idle gate watchdog** — 空闲席位若持有可 claim 的 gate qitem，会在有界 skip recording 下被唤醒，避免 queue 堵在休眠席位后方。
- **Session admin mutation auth guard** — 没有正确 auth posture 时，无法再访问 admin mutation 界面。
- **`zrig queue show` 有界 body preview** — show view 会截断较长的 queue item body；完整 body 仍可在 queue item drawer 中查看。
- **手动可配置 compaction trigger + same-seat guard** — 可以从席位外提示 Claude Code 席位执行 compact；同一席位 mutation 会被拒绝。
- **Secret boundary B1 强化（`zrig auth`）** — `zrig auth` secret boundary 现在先打开 file descriptor，后续只在 fd 上操作，不再重新解析路径，从而关闭 interruption / 并发合法工作组进程场景中的 check-then-use gap，并随之关闭 TOCTOU 类别。`zrig auth` 文件是真实凭据；leak hunt 是真实安全工作，不是形式演练。

## 工作原则与快速后续

- 发布 **`mission-slice-sop` 技能**，涵盖 `PROGRESS.md` / `PROOF.md` / `MISSION_NOTES.md` / `MISSION_BRIEF.md` / `README.md` 的逐文件规则、SCAFFOLD/POPULATE/PROJECT/VERIFY 生命周期、hot potato queue handoff，以及 `zrig scope audit` 兜底。
- **Hook trust autoclear（快速后续）** — 恢复后的 Codex 席位如果遇到 VM-local hook trust `attention_required` gate，现在会像 slice 10 一样在恢复路径上自动清除 attention，实现完全无人值守的 Codex 恢复。

## 行为与兼容性

- **Migration** — 仅叠加。本版本包含 `045_resume_verification`、`046_seat_identity_verdicts`、`047_events_node_type_index`。现有 v0.4.2 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。
- **`zrig send` 默认 posture 变化** — unknown / stale / missing / busy activity signal 不再默认阻止，只有 `needs_input` 会。如果调用处依赖 0.4.1 的默认阻止 posture，请显式添加 guard；peer 协调的 intent signaling 现在位于 fleet 标准的提示后发送路径。
- **`zrig send` grammar** — recipient list、`--pod`、`--rig` 均为叠加式新增；单接收方调用不变。
- **Project 界面外观** — Dashboard theme 通过 UI toggle 选择启用；light theme 逐字节不变。
