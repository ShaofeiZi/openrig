# zrig v0.4.6

## 摘要 — Workflow、多主机协调与 Factory 基础

zrig v0.4.6 交付确定性 workflow engine，以及构建在其上的多主机协调模型。Workflow 现在是一等产品界面：具有稳固的 engine、功能完整的 spec language、workflow CLI、workflow Web UI，以及 exception + human gate 成熟度模型，使健康运行保持零打扰。在该 engine 之上，self-driving factory starter 以已发布 MVP starter 的形式提供（`zrig up factory-rsi`）：一个工作组、七个席位、自驱动 `plan → implement → qa_check → review → release` 内循环；dogfood 解耦并在带外针对已发布产品运行，其记录的问题会输入下一轮计划。

多主机协调的完整 happy path 已落地。主机通过 Dashboard 可见 card 注册与选择；本地运维人员可以读取远程主机工作区界面；queue item 与 hot potato handoff 通过已注册 transport 显式跨主机，绝不会静默重新选择 home；直接协调 verb（`zrig send`、`zrig capture`、`zrig transcript`、`zrig broadcast`）通过已发布 HTTP transport 分支直接从 CLI 跨主机，同时保留逐字节一致的 SSH 行为；fleet 高度的 attention band 汇总整个已注册 fleet 的待关注状态。

本版本还补全多项基础：新的智能体运行时 adapter Pi 作为与 Claude/Codex 并列的一等运行时；terminal provider 在所有面向终端的界面中获得一等处理；后台服务读取路径针对多主机与 workflow 负载得到强化，但功能行为不变。

新增两个 bundled skill，以 canonical + plugin 形式发布，并由逐字节一致性 guard 守护：`openrig-herdr`（工作组终端打开/view/status 模型）与 `openrig-cmux`（provider agnostic 差异）。

Migration 仅叠加：`049_workflow_instance_version`、`050_workflow_spec_json`、`051_workflow_resume`、`052_workflow_instance_bound_rig`、`053_sessions_node_id_index`、`054_queue_transitions_archive`。现有 v0.4.4 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。（v0.4.5 已跳过；v0.4.4 与 v0.4.6 之间没有切版。）

## 已发布内容

### Workflow

- **稳固的确定性 engine** — 严格 spec 验证：拒绝未知 key，不可达 step 和无 guard cycle 会失败；在 projection 时强制 `loop_guards.max_hops`；吸收 waiting exit replay；逐 instance keepalive watchdog 在 routing transaction 中自动 arm；启动 sweep 会重新 arm 并显示卡住的 instance；`zrig workflow continue` 重新标注为只读 inspector 语义。
- **功能完整的 spec language** — step 支持 role / target.rig / preferred_targets / next_hop.on / invariants / loop_guards / exception_routing / closure / gates / skill_refs / spawn_budget；使用严格 keyset 验证；已发布 spec 的兼容性由 fixture round trip 固定。
- **Workflow CLI** — 新增 `zrig workflow run`（实例化并跟随到终端；exit 3 表示 workflow failed，与 transport 1/2 区分）、`zrig workflow watch`（在运行途中接入）、`zrig workflow status`（needs attention 汇总）、`zrig workflow route`（在单 transaction 中重新指定 frontier target）。`trace` / `list` / `show` 提供格式化的人类可读输出；`--json` 与此前逐字节一致。新 guard 会拒绝在带外关闭 live workflow frontier packet 的终端。
- **Workflow Web UI** — 新增 Workflows/Instance/InstancesBand/TopologyGraph/InstanceTrailTimeline 页面；SSE stream 不按工作组限定 scope；导出纯函数 `buildLauncherViews`、`suggestLayout` 和 edge handle assignment。UI 验收由每个切点的真实截图和双主机集成证明支撑；twin fixture backfill 作为不阻塞 0.4.7 的卫生快速后续。
- **Exception + human gate 模型** — 新增 `zrig workflow resume` verb：从失败 step 重新驱动失败 instance，重新绑定，以 capability aware 方式重新解析，并获得新的 `max_hops` 窗口。Exception 在失败 transaction 中同步变为持久 attention item；每个 class / workflow / host 支持 `orchestrator-first | human_only` 成熟度档位；attention band 感知 workflow；happy path 零打扰保证不变。

### 多主机协调

- **添加/选择主机与 Dashboard** — Dashboard 提供 `HostConfigCard` 和 `HostIndicator`；`zrig host select` 持久化 sticky selection，供 observe/interactive verb 使用；新增 `useHosts` / `useFleet` hook。
- **查看远程工作区** — 工作区可观测性 tab 增加 `--host <id>` scope；registry + bearer 按主机 fanout 读取。只读。
- **跨主机 queue routing** — `zrig queue create` / `handoff` / `handoff-and-complete` 增加 `--host <id>`，并支持带主机限定的 destination `member@rig@<host>`。仅显式 routing。通过确定性 successor ID 实现 at-least-once + idempotent；handoff 先创建 successor，再关闭 local；重试通过 primary key 吸收。逐主机结果真实报告失败。
- **跨主机智能体协调** — `zrig send` + `zrig capture` 增加 HTTP transport 分支，由 CLI 直接访问远程后台服务的既有 `/api/transport/send|capture` 路由；`zrig transcript` + `zrig broadcast` 以相同方式首次支持跨主机。`agent@rig@host` target 形式只是 session target verb 的 CLI edge sugar。对通过 SSH 注册的主机，逐字节 SSH 行为保持不变；优先级为显式 `--host` > target sugar > selection；HTTP 上的 `send --verify` 逐字输出远程路由 verdict。
- **Fleet attention 高度** — 通过 `FleetBand` + `FleetPage` 提供 fleet wide attention 汇总，以及逐主机状态和 drill down。

### Factory

- **Workflow 到工作组的绑定层** — 实例化时通过 `--rig` 将 workflow 绑定到工作组；role 根据 capability 解析到席位；capable seat 解析会考虑仅托管席位、harness pin aware runtime match、最少 pending backlog 与确定性 tie break；只解析一次并记录到 packet。Role 绑定到稳定席位坐标 `{pod}-{member}@{rig}`，因此席位背后的智能体 handover 不会让 workflow 失去目标。
- **Self-driving factory starter（`factory-rsi`）** — 新增 `zrig up factory-rsi` starter 和 `factory-rsi` builtin workflow，通过 `loop_guards.max_hops` 允许 `plan → implement → qa_check → review → release` 内循环；dogfood 解耦并在带外对已发布产品运行，其问题输入下一轮计划。RSI edge 在 MVP 中不设门禁，后续版本再完善；publish 通过 `release_signoff` gate 保持为人类操作。
- **Member exists advisory + cross rig wrapping** — 实例化时会明确捕获误路由的 workflow destination；cross rig wrapping workflow 通过跨主机 queue routing 路径传输。

### Runtime、终端与读取路径

- **Pi 智能体运行时 adapter** — 新的一等运行时，与 Claude/Codex 并列；参与所有 workflow / role / queue / send / capture 界面，行为与既有运行时一致。
- **Terminal provider 一等处理** — terminal launcher、send/capture/broadcast，以及新 `openrig-cmux` 技能的 `--provider cmux` seam 均将 terminal provider 作为一等概念，并带 best effort fallback。
- **后台服务读取路径强化** — SSE stream backpressure guard、projection cache，以及提高读取侧 query 性能的叠加 index。功能行为不变，相同读取返回相同结果，但更快。

### 新增 Bundled Skill

- **`openrig-herdr`** — 完整的工作组终端 open/view/status 模型，包括 verb、view grammar、真实部分结果读取、只读 policy 和 terminal-views.yaml schema。采用 AGPL clean room rail，不 vendoring herdr 源码文本。
- **`openrig-cmux`** — provider agnostic 与 cmux specific 的差异，以及已发布集成的 open or focus 规则。

两者均以 canonical + bundled openrig-core plugin 形式发布，并由逐字节一致性 guard 守护。

## Migration

仅叠加：

- `049_workflow_instance_version` — `workflow_instances` 的 optimistic concurrency。
- `050_workflow_spec_json` — 在 `workflow_specs` cache 完整解析后的 spec；旧行在下次 read through 时自修复。
- `051_workflow_resume` — `workflow_instances` 上的 `resume_count` + `hops_baseline`。
- `052_workflow_instance_bound_rig` — `workflow_instances` 上 nullable `bound_rig` TEXT。
- `053_sessions_node_id_index` — 叠加 index。
- `054_queue_transitions_archive` — 用于读取侧 query 性能的 archive table。

现有 v0.4.4 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。
