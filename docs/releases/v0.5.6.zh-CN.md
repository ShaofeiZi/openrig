# v0.5.6 — 将世界构建作为上下文工程

zrig 0.5.6 发布上下文系统的下一层，使长期运行的智能体具备持久连续性，并使发往人类的消息值得信任。版本围绕三个主题：席位运行所依据的上下文具有结构、标签且可验证；智能体席位无需人类管理切换，也能超越自身上下文窗口继续存在；任何路由给人类的内容都带有投递证明。

## 上下文系统：结构化、有标签、可验证

- **任务目标安装。** `docs/reference/mission-install.md` 记录五层约定，用于将项目上下文安装到席位：各组成部分、它们的排列、席位自身位置、当前契约，以及“自行派生差异”的步骤；最后一步用于证明安装内容已被真正消费，而非只被扫读。
- **Lore routing。** 席位在本地学到的内容会路由到可寻址的工作组本地 lore pack（`docs/reference/lore-routing.md`），从创建起即携带 maturity stage，并通过结构保证不会进入任何发布内容。
- **Taxonomy 覆盖所有内容。** 进入 `zrig context` 的每个 pack 都携带自身分类 WORLD / LORE / SKILLS / MISSION，并在列表中显示；未标记的 pack 会被明确拒绝。
- **带可检查主张的公开 world pack。** 公开 onboarding pack 由 atom 创作，每项主张都带一个可能失败的检查，并在 pack 内随附 verifier；公开内容无法静默腐化。
- **完整且可自行获取的技能索引。** Skill router index 现在覆盖全部已发布技能，可通过它自己教授的路由获取，并包含 recurrence test，使覆盖缺口持续可见。
- **发布内容 substance gate。** 对每个已打包文件执行整套界面 review，包括 bundle 与 npm 界面，并作为具名发布步骤运行；本版本发布时全部 5,316 个 packaged file 均通过。

## 连续性：超越自身上下文窗口的席位

- **智能体 spec 中的连续性 policy。** `compaction_strategy` 现在是实时配置，包含四种模式：`default-compaction`、`managed-compaction`、`handover`、`apprentice-handover`。模式仅应用于 Claude 席位，采用正向 runtime matching；Codex 席位保持原生行为。解析优先级与 agent spec 其余部分一致：spec default < profile < member。
- **自动化 apprentice handover。** 声明 `apprentice-handover` 的席位会获得两个已 arm trigger：接近上下文阈值时，系统创建全新 successor seat 并运行 onboarding install；更接近上限时，系统为执行 swap 的席位创建自有 handover work item。执行席位通过 policy 中的 `mechanic:` 显式配置，绝不从 topology 推断；缺失时 arming 会明确拒绝。
- **带真实恢复结果的托管压缩。** `managed-compaction` 模式的席位会收到压缩前 prep nudge，提示在窗口关闭前保存状态；配置恢复完成后，会写入持久 receipt，记录恢复实际找回多少可用上下文。因此，如果恢复只是静默重新填满窗口而没有恢复宽度，结果会清晰可见。
- **Context usage trigger 成为原语。** `zrig watchdog` 新增 usage threshold condition：席位上下文用量跨越校准的逐席位阈值时，可以触发任意命令。连续性模式建立在该原语上，用户自己的自动化也可使用。

## 人类层：可证明的投递

- **不再静默 fall through。** 统一 destination resolver 对每次 dispatch 分类：绑定终端的席位使用 terminal；registered human 与 virtual seat 通过 gateway 路由；任何内容都不会 fall through 到必然失败的 terminal lookup。未注册 external address 会收到结构化教学式拒绝。
- **Work item 上的投递 receipt。** 每次 gateway post 都会原子地将 receipt 写到 queue row：`posted`（含消息时间戳与 channel）、`transport-failed`（含错误），或可派生的 `never-posted`。`zrig queue undelivered` 现在优先查询该 ledger，只返回真实失败；“是否送达”只需一次读取。
- **统一通知级别词汇。** Queue transition 在写入时分类为 `RECORD` < `NOTICE` < `ALERT`：需要人类决定的是 `ALERT`，系统仪式事件是 `NOTICE`，其余是持久记录。两个独立 dial 分别配置最低 post 级别和最低 interrupt 级别。
- **Delivery rule engine。** 每个人类的已存储 preference 和 availability 决定各消息类别的投递方式。`off` preference 只抑制打扰，绝不抑制持久记录、post 或 receipt。Away window 将日常 traffic 延迟为 digest（4 小时与每日），并通过结构保证 exactly once：持久 episode identity、重试直到获得真实 receipt、digest 之间结构上不重叠。
- **Slack 中投递的文件变成工作。** 上传文件或图片会生成 work item，文件经认证、大小受限地下载到本地存储，并以路径引用；逐文件失败会明确命名，任何 URL 或 token 都不会写入 row。若 park 被 registered human 阻塞，会自动进入 alert 路径，并且每个 episode 只 post 一次。

## 运维真实性

- 被 rate limit 的席位会在声明的 reset 时间获得恰好一次定时 wake。
- 席位空闲但持有 claimed live work 时，系统会使用仲裁后的 activity oracle 将其唤醒；每个 park episode 恰好一次 wake。
- Refocus state 以席位当前 occupant 为 key；新 occupant 不会继承 predecessor baseline。
- `zrig ps` 将已 claim、in-progress 的工作计入 assigned work。
- Send 拒绝空 body；未知后台服务 API route 返回 JSON 404。
- Stuck sweep finding 在关闭后不再重复创建；跨主机 custody verification 会持久完成，而不是永远刷新。
- Blocker actuation 统一为一个 helper；跨主机 closure 如实处理；transaction commit 后才进行 delivery。
- 工作组 expansion 与 serialization 保留输入：`session_source` version、`services` 与 member override 均可通过 round trip；fork 会转发 model、role、restore policy 与 label。
- `zrig view show execution` 在读取时派生谁正在构建什么、下一项是什么，以及各项目的完成 rung（locked / built / reviewed / folded / adopted）；unknown 显示为 INDETERMINATE，绝不会误作 idle 或 done。

## 升级说明

- 后台服务启动时自动应用三个数据库 migration：`074_context_usage_watchdog`、`075_context_usage_watchdog_generation`、`076_owner_notification_levels`，无需手动步骤。
- 随版本发布 41 个 context pack，之前为 39 个。
- Delivery 默认值有意保持宽松：`NOTICE` 及以上进行 post，`ALERT` 及以上进行 interrupt。请根据实际测量 volume 用两个 dial 收紧，不要预先过滤。
- 连续性模式按席位选择启用；未配置席位完全保持当前行为。
