# zrig v0.5.2

## 摘要 — 测试系统投入实战、Crash Cart Conductor 与可靠性修复

**v0.5.2 正式使用 v0.5.1 的测试系统。** 本版本的可靠性修复由 scenario 发现并验证；这些 scenario 使用与人类相同的命令驱动真实产品。重点功能是 crash cart fleet restore conductor：从后台服务完全停止开始，只需一次按键，就能进入真实驾驶舱并恢复为活跃 fleet。

**v0.5.2 完整包含 v0.5.1。** 两者属于同一 lineage，没有分歧。

本版本没有新 migration。v0.5.1 已发布 migration 068–071，其中 068 和 071 是匹配的 create / drop-if-exists 对，对任何 v0.5.0→v0.5.1 升级净效果为 no-op；v0.5.2 的 migration head 保持 071。相较 v0.5.1，没有删除或重命名 CLI 命令/flag。

## 已发布内容

### Crash Cart Fleet Restore Conductor（重点）

后台服务停止时直接输入 `zrig`，即可进入真实驾驶舱：没有晦涩错误，也不会静默失败。按一次 Enter 会以 kernel first 顺序恢复 fleet，接入任何仍然存活的 tmux pane且绝不覆盖，然后展示精确的逐席位修复步骤，每一步都可通过一个按键操作。取消行为保持真实。只有 adoption 无法成功时，才会提供破坏性恢复。该功能经过十轮构建、四个独立门禁，以及非作者 QA door test。

### 后台服务 Event Loop 在负载下不再挂起

一类后台服务 event loop 在负载下冻结的问题已经修复并测量。如果后台服务曾在 fleet wide activity 下失去响应，即属于此问题类别。

### 无人值守的 Claude 席位 Handover

Claude 席位需要 handover 时，例如 compaction、session boundary 或显式 handover 请求，离任席位现在会自动写 recap 并提交 packet；接任席位拿到 recap 后继续工作，而非冷启动。该流程已通过端到端 door 验证。

### `zrig policy` 真实处理对抗性输入

格式错误或恶意的 policy 输入现在产生真实、结构化错误，不会静默失败或表现出意外行为。已完成三轮 review。

### 跨主机消息携带来源机器

跨主机发送的消息现在包含来源机器，使接收端能够正确理解多主机协调。通过 door test 端到端强制验证。

### Codex Model Config Drift Detector

新增 detector，用于发现过去不会暴露的 Codex model config drift。落地时已捕获真实问题。

### 测试完整性工作

- Test runner 拒绝在 dirty tree 上运行，使绿色结果代表绿色源码，而非意外未提交状态。
- 使用 hermetic test root。
- 隔离 flaky fixture。

### 代码中的治理

Plan lock 只有在明确请求时才选择，不从环境状态继承。Wake 需要选择启用。

### 从接口处消除 Container Tar File 挂起

Container tar file 挂起类别从结构上消除：不是临时绕开，而是关闭产生该问题的 seam。

## 已知限制（5.3 Backlog）

以下内容已如实记录到下一发布周期，明确列出尚未修复的部分：

- **Reply hint 自限定** — 某些跨主机消息的 reply hint 使用 machine ID 而非 registered host name 指向自身；直接使用 hint 可能因 “no registered host X” 失败。请用 `zrig host list` 中的 registered host name 替换。计划在 5.3 修复。
- **`zrig queue handoff --summary`** 会发出警告，但其自身输出无法设置该字段。计划在 5.3 修复。
- **`zrig send --verify` 无法检测 staged-unsent**，适用于发往 Claude 席位的多行 send；多行内容可能被静默暂存而未发送。
- **Claude transcript 在 fullscreen upsell 下变薄** — 上游 fullscreen upsell 写入 `"tui":"fullscreen"`；一次接受 prompt 就可能让整个 fleet 再次切换。修复、pin 与预防计划在 5.3 完成。
- **Test runner 可能在未构建 tree 上静默 skip** — 发布仪式已采用 final gate 规则：构建 CLI 并断言零 skip；产品侧修复在 5.3 落地。
- **`seat-handover` model fidelity 真实 Codex 端到端测试** 在 main 上以相同方式失败，尚未确定是环境还是产品问题；隔离修复计划在 5.3 完成。

此外还有少量内部技术债已记录，供维护处理。
