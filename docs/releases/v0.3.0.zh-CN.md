# zrig v0.3.0

## 摘要

zrig v0.3.0 将 0.2 版本的协调基础转化为更成熟的运维产品。本版本提供重新设计的 shell、通用 workflow starter、任务目标形态的工作区支持、项目可观测性、精选内置技能、运行时图形、上下文遥测，以及使全新安装更加干净的发布强化工作。

本版本保留了 queue 移交、workflow 运行时、watchdog 监督、产物/证明界面和智能体协调等可复用原语；与此同时，公开的 starter 内容刻意保持通用。

## 本次发布包含的内容

- V1 shell 重新设计：采用 vellum 视觉系统、两个桌面 chrome 区域、拓扑 graph/table/terminal 模式、drawer viewer，以及 Project、For You、Queue、Library、Settings 和面向证明的详情界面。
- 通用 starter workflow spec：
  - `conveyor`：适用于工位式工作，允许多个 packet 同时在拓扑中处于活跃状态。
  - `basic-loop`：适用于一次处理一个 packet 的逐步演练流程。
- `conveyor` starter 工作组，以及与 intake、planning、building 和 review 工作相匹配的智能体 spec。
- 任务目标形态的工作区默认值，以及只读的嵌套任务目标/slice 索引。
- 横跨 For You、Story、Queue、Tests、Project 汇总、证明截图和 qitem drawer 的项目可观测性升级。
- 在拓扑、queue、项目元数据、证明行、终端预览和智能体身份标记中统一应用的运行时/工具图形 package。
- 改进终端预览、活动指示器、handoff 边动画，以及拓扑 table/terminal view 中的上下文使用量遥测。
- 在 profile 解析期间，从文件系统技能根目录发现运行时技能。
- 发布前 CLI/后台服务清理：有界会话记录轮转、`zrig send` 消息 envelope、zrig install/init 标记命名，以及公开发布术语清理。

## 面向用户的变更

### 重新设计的 Shell

UI 现在采用 V1 shell 模型：包含窄 rail、随目标区域变化的 Explorer 区域、中央工作区和由具名触发器打开的 drawer。拓扑页面在同一个稳定 URL 下提供 graph、table 和 terminal 三种模式。Drawer viewer 可以展示 queue item、文件、子 spec 预览、终端预览和证明产物，避免每次点击引用都跳转到完整页面。

### Starter Workflow 与工作组

本版本提供通用 workflow 示例，不再包含特定项目的自动化 recipe。`conveyor` 展示带有自然 queue 背压的工位式流程；`basic-loop` 展示简单的单 token 逐次循环。`conveyor` 工作组是公开 workflow starter，`product-team` 则继续作为由人类运维人员驱动的更高级 starter 拓扑。

### 项目与证明可见性

项目界面现在能够区分当前工作和已归档工作、展示任务目标/slice 层级、将任务目标标签路由到任务目标页面，并公开 story/tests/proof 汇总。For You 和 Queue 卡片会补全 qitem 正文、证明图片、审计结果和下一步操作状态。Tests 证明截图可在页内 viewer 中打开。

### 拓扑与运行时可见性

拓扑现在提供混合多工作组 graph、展开/折叠控件、活动环、handoff 边动画、运行时/工具标记、上下文百分比/token 显示，以及 terminal fallback view。智能体详情界面现在使用规范的 live node details view。

### 技能与 Starter 指引

内置技能已经过筛选，以保证 starter 的一致性。运行时技能发现现在可以在运行时和工作区技能根目录中找到有效的 `SKILL.md` 文件，并且工作组本地资源的优先级高于更广泛的用户库。

## 运维 / 初始化说明

- 全新工作区默认采用任务目标形态，并从 `workspace.root` 推导。使用 `zrig config init-workspace` 创建默认工作区结构。
- 本仓库使用 npm workspaces 和纳入版本控制的根目录 `package-lock.json`。`pnpm-lock.yaml` 文件不是发布产物。
- 根目录运行时投影文件（例如 `CLAUDE.md`）有意不纳入产品仓库的版本控制。
- 已弃用的 `RIGGED_*` 别名仅保留给最初的运行时环境 key：`daemon.port`、`daemon.host`、`db.path`、`transcripts.enabled` 和 `transcripts.path`。新的 typed config key 仅使用 `OPENRIG_*`。
- 现有本地 workflow spec 仍可从 workspace/spec 位置安装；产品源码只内置通用 starter workflow。

## 已知限制

- 0.3.0 不包含插件支持。插件打包的技能和外部插件分发计划在后续版本提供。
- 公开 starter workflow 是示例，并不是完整的打包自动化方法论。
- 部分宽范围 CLI 测试对本地后台服务端口/配置状态较为敏感。最终发布门禁采用了定向发布路径测试以及 build/lint 门禁。

## 已执行的验证

- `npm run lint`
- `npm run build`
- `npm run test:repo`
- 对 CLI、后台服务和 UI 执行定向测试，覆盖发布卫生、配置边界、starter 技能发现、shell/拓扑行为和项目可观测性。
- 扫描源码中的个人路径、内部归属表述、默认 fallback 假设，以及新 typed key 上不应出现的旧环境变量别名。
