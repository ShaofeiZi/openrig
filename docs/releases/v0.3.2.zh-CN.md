# zrig v0.3.2

## 摘要

zrig v0.3.2 将 Rigbundle 作为跨原语打包机制的一等能力发布，使 workspace + workflow 运维界面达到 GA，完成一轮包含 4 个问题的 `zrig up <starter>` 易用性修复，交付一轮包含 5 项修复的协调与首次用户初始化改进（slice 21），从后台服务源码和测试中清理内部 substrate 路径，将 `ConceptCard` 接入经过整形的数据源，并为 For You 增加服务端优先级窗口。

没有破坏 schema 的 migration。现有 v0.3.1 数据库会在首次运行 `zrig daemon start` 时升级：新增 migration `041_rig_policy`，为新的运维上下文模式绑定创建表。该 `CREATE TABLE` 不影响现有数据；绑定行由运维人员在运行时创建。

## 本次发布包含的内容

- **Rigbundle 一等能力（slice 05）** — 五类内容（skills、plugins HYBRID、workflow_specs、context_packs、agent_images）的跨原语打包实现端到端路由。`zrig bundle create` 会自动检测作者提供的 `bundle.yaml`，vendoring 声明的内容时同时对源路径和目标路径执行 containment 检查，并防止 symlink escape，最终生成带完整性哈希的 manifest。`zrig bundle install` 会将各内容类型路由到 `$OPENRIG_HOME` 下的规范 library，同时维持 consumer scan 可见性。`zrig bundle inspect` 会将跨原语内容字段作为一等信息显示。CLI 安装超时已提高；原来的 5 秒上限不足以完成需要启动 tmux 会话的安装。
- **Workspace + Workflow GA（slice 01）** — 强化面向运维人员的界面。`zrig workspace validate --max-files` 采用严格整数正则；`zrig workflow project --exit` 增加枚举 guard；提前失败时会在 `client.post` 前返回三段式错误，以提高清晰度；validator 路径新增 14 项 discriminator 测试。
- **`zrig up <starter>` 易用性修复轮次（slice 22）** — 解决 v0.3.1→v0.3.2 全新安装时阻塞首页快速入门的问题，包含四项有界修复：
  - 启动前失败改为 HTTP 4xx 界面（`cycle_error` / `preflight_failed` / `validation_failed` / `service_boot_failed`），此前只返回 500。
  - 启动前失败时不再留下孤立工作组记录：调整 instantiator 顺序、增加 rollback 路径，并收紧 compose 拆除顺序。
  - 路径形式的 `zrig up <install-internal-spec>` 默认将 `cwd` 设为调用者目录，消除路径形式与 bare 形式调用之间的差异。
  - `walkYamlFiles` 跳过标准噪声目录（`.worktrees`、`node_modules`、`.git`、`dist`、`.turbo`、`.next`）；启动时清理过期 `workflow_specs` 行，同时通过 install-root preservation guard 保证随产品发布的内置 spec 不会被清理。
- **协调与首次用户初始化修复轮次（slice 21）** — 五组有界后续改进：
  - FR-1：在 `core/openrig-user/SKILL.md` 中明确协调模型的启动直觉，包括 `zrig send`、`zrig queue`、`zrig queue handoff` 的区别和 §1b 原则。
  - FR-2：新增首次用户 workspace + workflow 初始化教学内容（技能和文档）。
  - FR-3：强化 MISSION_NOTES 持久化模式，包括模板、codemap 约定，以及通过 `zrig scope mission create` 自动搭建 scope primitive。
  - FR-4：Queue 易用性改进。`zrig queue create --body-file <path>`（用 `-` 表示 stdin）消除多行正文被 shell 反引号破坏的问题；一等 `--mission` / `--slice` flag 会组合成 tag；修正 `lastNudgeResult` 文案；记录 closure 与 acceptance 的区别。
  - FR-5：新增 `zrig workspace doctor` 子命令，提供 7 项工作区就绪诊断：workspace root、missions folder、file allowlist、daemon alignment、daemon reload、可选 slice 文档以及 MISSION_NOTES 是否存在。
- **后台服务测试 Substrate 路径清理（slice 14）** — 从 4 处后台服务源码和 10 个测试文件中清理内部团队 substrate 路径形态，去除重复 hook constant，并在纳入版本控制的源码/测试界面中关闭该隐私问题类别。
- **`ConceptCard` 数据源（slice 17）** — 接入经过整形的 backlog candidate；完成从 0.3.1 推迟的 storytelling adapter 工作。
- **For-You 优先级窗口（slice 20）** — 服务端 attention query（Option 3）：SQL predicate pushdown、精确匹配 attention 的正则，以及 queue 派生卡片使用字符串 key 记录 dismissal。
- **运维上下文模式绑定（slice 09）** — 新增 `zrig policy` 命令界面，并配套后台服务 typed-primitive store（migration `041_rig_policy`）。六种模式（`sleep | desk | mobile | away | focus | debug`）可绑定到四层 scope（`global_host | rig | workstream | qitem`）。系统采用“复述并确认”机制，脚本未显式传入 `--confirm` 时无法静默应用绑定。Citation、effective-mode resolve 和 `defaults` 命令共同补全该界面。
- **Scope Tree Primitive（slice 12）** — 新增 `zrig scope` 命令，按照 `conventions/scope-and-versioning` 操作 substrate scope tree（missions、slices、sub-slices）。任务目标层提供 `ls` / `show` / `create`；slice 层提供 `ls` / `show` / `create` / `ship` / `close` / `move`。系统会在任务目标 frontmatter 中自动生成稳定 dot-ID；任务目标模板包括 `release` / `placeholder` / `mission-notes`。

## 面向用户的变更

### Rigbundle 一等能力

`zrig bundle` 现在提供一等的跨原语打包能力：

```
zrig bundle create <spec> -o <path>
    [--name <n>] [--bundle-version <v>] [--include-packages <refs...>]
    [--rig-root <r>] [--notes <text>]
    [--min-daemon-version <ver>] [--min-cli-version <ver>] [--json]
zrig bundle inspect <path> [--json]
zrig bundle install <path>
    [--plan] [--yes] [--target <root>]
    [--skip-version-check] [--force] [--json]
zrig bundle history [--rig <name>] [--since <iso>] [--json]
```

安装时路由的内容类型包括 `skills`、`plugins`（hybrid）、`workflow_specs`、`context_packs`、`agent_images`。每一类都会进入 `$OPENRIG_HOME` 下对应的规范 library，同时保留 consumer scan 可见性。

如果存在作者提供的 `bundle.yaml` manifest，系统会自动检测。Vendoring 会同时检查源路径和目标路径的 containment，并防止 symlink escape。Bundle manifest 会记录完整性哈希。

`install` 上的 `--skip-version-check` 和 `--force` 分别是对安装时后台服务/CLI 兼容门禁和冲突门禁的运维人员显式覆盖。日常使用**不建议**使用这些选项；它们仅为运维人员已经确认安全的场景而提供。

`zrig bundle history` 读取 `~/.openrig/bundle-audit.jsonl`，即每次安装的 audit ledger，并可按目标工作组名称和最早安装时间筛选。

### Workspace Doctor（`zrig workspace doctor`）

针对后台服务解析出的工作区执行 7 项就绪诊断：

```
zrig workspace doctor [--workspace <path>] [--strict] [--json]
```

检查项包括 workspace root、missions folder、file allowlist、daemon alignment、daemon reload、可选 slice 文档以及 MISSION_NOTES 是否存在。

默认退出码只在出现 `fail` 时非零。`--strict` 会让 warn 或 fail 均返回非零。CLI 会叠加运维人员 shell 环境中的 `OPENRIG_FILES_ALLOWLIST`，因此即使后台服务环境未变化，诊断也能反映运维人员预期的 allowlist。

### Queue 易用性

`zrig queue create` 可以从文件或 stdin 读取正文，并公开一等任务目标/slice scope：

```
zrig queue create --source <s> --destination <d> \
    (--body <text> | --body-file <path>) \
    [--mission <id>] [--slice <id>] \
    [--priority <p>] [--tier <t>] [--tags <csv>] \
    [--target-repo <name>] [--no-nudge] \
    [--expires-at <iso>] [--id <qitemId>] [--json]
```

`--body-file -` 从 stdin 读取。`--mission <id>` / `--slice <id>` 会转换为 `mission:<id>` / `slice:<id>` tag，并与 `--tags` 组合。

### 运维上下文模式绑定（`zrig policy`）

```
zrig policy set <mode> [--scope <scope>] [--qualifier <id>] \
    [--<field> ...] [--evidence <citation>] \
    [--confirm] [--bearer <token>] [--json]
zrig policy show [--json]
zrig policy effective [--rig <id>] [--workstream <id>] [--qitem <id>] [--json]
zrig policy cite [--rig <id>] [--workstream <id>] [--qitem <id>]
zrig policy unset <scope> [qualifier] [--bearer <token>] [--json]
zrig policy defaults [--json]
```

未提供 `--confirm` 时，`set` 只复述提议：CLI 会回显拟议绑定并以 `exit 2` 退出，因此脚本无法静默应用绑定。

六种模式为 `sleep | desk | mobile | away | focus | debug`，四层 scope 为 `global_host | rig | workstream | qitem`。`rig | workstream | qitem` scope 必须提供 `--qualifier`，而 `global_host` 会显式拒绝该参数。

运维编辑 verb（`set --confirm`、`unset`）需要运维 bearer token，可通过 `--bearer` 或 `OPENRIG_AUTH_BEARER_TOKEN` 环境变量提供。

### Scope Tree Primitive（`zrig scope`）

```
zrig scope slice ls    [--mission <m>] [--state <s>] [--json]
zrig scope slice show  <slice-path> [--mission <m>] [--json]
zrig scope slice create <mission> <slug> [--template <k>] [--title <t>] [--json]
zrig scope slice ship  <slice-path> <release-mission> [--mission <m>] [--json]
zrig scope slice close <slice-path> --reason <r> [--note <t>] [--mission <m>] [--json]
zrig scope slice move  <slice-path> <dest-mission> [--mission <m>] [--json]
zrig scope mission ls  [--json]
zrig scope mission show <mission> [--json]
zrig scope mission create <name> [--template <k>] [--id <dot-id>] [--title <t>] [--json]
```

顶层选项 `--workspace <path>` 可以覆盖工作区根目录；否则从 `cwd` 或 `$OPENRIG_WORK_ROOT` 推断。

### `zrig up` 易用性修复

```
zrig up <source> [--plan] [--yes] [--cwd <path>] [--target <root>] [--existing] [--json]
```

- 启动前失败现在返回结构化 HTTP 4xx（`cycle_error` / `preflight_failed` / `validation_failed` / `service_boot_failed`），不再只返回 500。
- 启动失败不再在磁盘上留下孤立工作组记录。
- 路径形式调用默认将 `cwd` 设为调用者目录。
- `--existing` 跳过 library spec 名称解析，直接将 `<source>` 视为现有工作组名称。

### MISSION_NOTES 持久化模式（slice 21 FR-3）

默认情况下，`zrig scope mission create` 会根据 `conventions/mission-notes/TEMPLATE.md` 自动创建 `MISSION_NOTES.md`；可通过 `--no-mission-notes` 选择退出，但这种情况较少见。该约定将工作区技能和规范模板中记录的持久化模式整理成标准，使任务目标在发布时拥有统一、便于随时关注的 notes 界面。

## 运维 / 初始化说明

升级已发布的 CLI 后：

```bash
npm install -g @openrig/cli@0.3.2
zrig --version    # 预期输出 0.3.2
zrig daemon stop
zrig daemon start
```

升级后首次启动后台服务时会自动应用 migration `041_rig_policy`。这是非破坏性的 `CREATE TABLE`，不影响现有数据；绑定行由运维人员在运行时通过 `zrig policy set --confirm` 创建。

新的 `zrig policy` 界面默认不设置任何绑定，需要选择启用。没有绑定时行为不变。创建绑定前，可使用 `zrig policy defaults` 检查建议的每模式 6×7 映射及默认 scope 映射。

新的 `zrig scope` 界面默认对工作区执行只读操作（`ls`/`show`）；创作 verb（`create`/`ship`/`close`/`move`）会按说明操作 substrate scope tree。使用 `--workspace <path>` 可以覆盖解析出的工作区根目录。

## 已知限制 / 推迟到 0.3.3 的内容

- **Slice-05 Item-3 sub-scope 推迟到 0.3.3**：智能体/端口/托管应用冲突检测（Item 4.3）；更广泛的安装到现有工作组路径验收（Item 4.4）；安装时覆盖工作组名称的 `--target-name` CLI flag。这些内容取决于 CLI 界面决策：A-breaking rename 或 A-additive new flag。
- **Slice-21 FR-4(d) accepted queue state schema 推迟到 0.3.3**：新的 `accepted` queue 状态会改变 schema 模型，根据已确定的发布分流原则继续后移。
- **Onboarding journey 与 battle-hardening 推迟到 0.3.3**：收尾时，slice 04（new-user-journey）、08（hooks-elite）、10（rig-self）、11（personal-rig）已实际移到 `release-0.3.3` 任务目标树。
- **工作区 symlink 对齐**：后台服务 workspace resolver 与运维人员使用 symlink 的工作区根目录仍需后续对齐；该问题由 slice-21 FR-5 QA 发现，不阻塞 0.3.2。
- **Slice-13 permission-block-routing-architecture 仍处于 held 状态**：需要运维人员 review 后给出 big-green-light，仅限 `rigx-experimental`；不会拆分推迟到 0.3.3，而是继续保持 held。
- **`zrig down <name>` 仍返回 HTTP 404** — v0.3.2 的按名称拆除仍无法通过后台服务 down 路由解析；请改用 `zrig down <rigId> --delete`。该问题继续作为已知问题保留。
- **`zrig view list/show --json` flag 不一致** — wrapper-layer 路由路径上的 flag 框架仍然存在；直接调用时，后台服务的 `view show <name>` 路由能够正确返回 JSON，这一点有 v0.3.1 切换证据。临时方案是使用人类可读输出；已记录的修复目标是 wrapper layer。
