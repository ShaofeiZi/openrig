# zrig v0.5.11 — 更清晰的首次使用、工作流与日常运维

**状态：** release candidate。Publication 与最终发布验证是独立步骤。

zrig 0.5.11 使用户更容易在普通仓库中开始有用工作、通过 TUI 理解团队及其 workflow，并诊断配置或生命周期故障，而不会把不确定状态误认为成功。

## 首次有用工作与共享视图

- `first-project` starter 为单个仓库提供聚焦的 Codex owner/checker 配对。README 会沿该路径引导用户从启动到完成有用变更、独立检查，再返回工作。
- 新 kernel 包含共享 TUI terminal。`zrig tui --shared` attach 到该既有 view；普通 `zrig tui` 打开 standalone view。加入共享 view 不会静默启动缺失 terminal 或 agent。
- Herdr 用户可以遵循相同的仓库与终端 journey。这是无需插件即可进行有用运维的准备；本版本不包含 Herdr plugin，也不声称已获得 community adoption 结果。

## 在日常 TUI 中理解工作

- Mission view 展示 workflow、当前 step 与 owner、wait，以及 transition 背后的 work packet。Source navigation 将 view 与作者编写的工作和 spec 相连接。
- Specs 展示声明的 purpose，包括工作组 `summary`，并区分内容缺失与读取失败。
- Connections 展示运行中的后台服务与 CLI identity、effective instance setting、configured/applied gateway state 和 registered human route。它是被动检查界面；connector 已配置不等于人类已收到消息。
- Command completion、可读 Recent activity 和持久可配置 timezone 使日常导航更方便。默认显示时区为 America/Los_Angeles。
- 超时的后台服务 probe 在整个 TUI chrome 中保持 unverified，不会标记为已确认 outage。

## 更可靠的协调与生命周期

- Project owned release profile 提供可复用 ceremony 与 post release boundary step。关闭当前 release 不依赖虚构 successor mission；每项 obligation 背后的 evidence 仍由智能体判断。
- Workflow exception recovery 会保留正确 owner，并清除已解决 exception state。Stuck work finding 保留真实路由所需的 source evidence。
- Terminal delivery 保留较长的作者上下文；paced walk verification 会检查预期 piece 以及适用 runtime/generation record。Delivery 与 native turn completion 仍不同于 comprehension。
- Context profile 与 work install 命令一致接受 Claude runtime 拼写 `claude-code` 和 `claude`，同时接受 `codex`；显式无效值在 projection 前拒绝。
- 启动使用选定的作者 proof，不会增加未请求 exercise；terminal only member 不会收到 agent proof challenge。
- 后台服务 shutdown 具有有界预算和带 attribution 的 outcome receipt。失败或缺失 receipt 在受支持 stop 路径上保持可见。
- 后台服务 startup 将 success 和 state publication 绑定到其实际 child，处理并发 start，并在无法确认 child liveness 时保留不确定性。跨主机请求 attribution 独立标识 origin，不依赖选定 destination。

## 运维说明

Root、CLI、后台服务和 Web UI package version 为 0.5.11；终端 TUI 保持独立 package version 0.1.0。Node 要求不变。有序数据库 migration head 仍为 `079_workflow_lifecycle_parallel`；相较 0.5.10 source baseline，本版本未新增 migration。

Diagnosis `show` 和 `list` 现在返回 summary depth `--json`，保留当前 state 和 decision，同时标识省略的 evidence。需要完整 record 的 consumer 必须使用 `--full --json`，或执行输出中给出的 expansion command。Queue `show` 保留 512 codepoint body preview，并新增显式 size、completeness 和 expansion 元数据。HTTP response 与 mutation JSON 仍然完整。这些默认值不是全局 output size cap。

请使用受支持的升级流程，并执行数据库备份与连续性检查。重启后台服务与关闭工作组效果不同，后者会停止席位。现有 kernel 不会自动重建以获得新的共享 terminal。

## 验证范围与限制

候选版本保留早先在隔离、installed package 环境中对 connected first project/workflow/TUI journey 的 evidence，以及对 purpose 和 unverified state 修正的定向验证。这些早先运行被标记为 prior evidence，不是本切点新的端到端或 provider enrollment test。候选准备会附带 package identity 和有界 installed rendering check；publication 前仍需要 exact cut substance 与最终发布验证。

- 首次使用 evidence 包含 fresh re-entry；不能据此证明 same conversation resume 或完整 mixed runtime enrollment。
- 受控 Connections evidence 和被动检查不能证明 external human delivery。瞬态 probe latency 与 view population 延迟仍是已观察限制，不作普遍 responsiveness 主张。
- Authored completion、legacy provenance 与 proof pairing 是相互独立的 reader。更新 declaration 不会创建缺失 provenance 或 execution wave history。
- 有界 health analysis proof of concept 已产出带 attribution 的 diagnosis 并退出。它是研究 evidence，不是已发布的 cold agent/run API、provider abstraction，也不是相较 residency 的成本或延迟优势证明。
