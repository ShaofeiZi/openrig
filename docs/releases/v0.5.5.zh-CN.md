# zrig v0.5.5

## 摘要 — “环境感知关注版本”

**v0.5.5 让 fleet 能够自行发现、重试、升级、诊断和引导新用户。** 无需再人工守着运行中的工作：`zrig parked` 以置信度和教学指引诊断静默卡住；常驻 stuck sweep 无人值守运行；baton wake 自行重试、聚合和升级；park 自带 wake，并显示为 HEALTHY；`zrig ps` 从统一 oracle 获得 typed `ACTIVITY` 列；Slack human layer 端到端上线；全新安装可自行 onboarding。

**v0.5.5 完整包含 v0.5.4。** 使用同一条已对齐 lineage。

**Migration**：新增两个，head 从 `071` 前进到 `073`：
- `072_thread_seat_map.ts`
- `073_queue_transition_wakes.ts`

**新 verb**：`zrig parked [seat]`、`zrig seat handover --source fork:|rebuild`（执行路径）、`queue block --on <blocker>`（带 wake 的 park）、`zrig gateway human` fragment lifecycle verb、`zrig view show escalations`。`zrig ps` 新增 typed `ACTIVITY` 列。

## 已发布内容

### `zrig parked [seat]` — 派生的静默卡住诊断

将 activity 与 open obligation 结合，并为每项输入内联显示置信度和修复建议。当席位看似空闲、怀疑工作丢失时，请先使用它，再考虑任何 `claimedAt` 算术或 pane capture。过去 row face 无法区分 park 与 strand；该 verb 结束了这种模糊。

### 自重试 Wake 阶梯与 Escalation View

失败的 baton wake 会自行重试、聚合和升级。Transition 就是阶梯状态，因此可跨重启保持；按 destination 聚合；每一级投递并前进；未确认且未 pickup 时直接升级，不重复发送。使用 `zrig view show escalations` 查看聚合项。完成 row handoff 后无需继续追踪 nudge。

### 常驻 Stuck Sweep 无人值守运行

Overdue + undelivered 会转化为 routed finding，并内联派生证据。无需再按定时器手工运行 `queue overdue` / `undelivered`；请消费 sweep finding。

**注意事项（5.6 backlog）：** 跨主机 successor 可见性是已经证明的假阳性类别；census 时有 39 个活跃 finding，其中 20 个已证明为 FP，19 个尚未验证。Fleet wide 按每条件一项控制；在 5.6 detector 修复前，请将跨主机 lineage finding 视为未验证。差异本身会说明此注意事项。

### `queue block --on <blocker>` — 带 Wake 的 Park

Park 可以携带自己的 wake，并显示为 HEALTHY。`queue block --on <blocker-qitem>` 记录 wake；有 live wake 的 held 项不会被标记；自动 unpark 的 owner 会收到真实 wake。仅用于即将执行但被阻塞的工作；不紧迫的工作应放入任务目标工作区，因为 queue 是 conveyor。

### `zrig ps` 从统一 Oracle 获得真实 `ACTIVITY` 列

Typed taxonomy 为 working / idle-at-prompt / needs-input-as-count+reason / unknown。Evidence ladder 顶端是 self report，并显式显示 rung degradation。跨 swap 以 seat 为 key。TUI 读取相同真相。对于任何“它正在思考还是卡住”的问题，应以 oracle 为准，capture 只作辅助。

### `zrig seat handover --source fork:|rebuild` — 执行

`fork:` 携带 live context；`rebuild` 从 durable chain 预热，并命名 priming artifact。Swap 中途失败会如实记录。替换 occupant 时不再只有 dry run planning 界面。

### Slack Human Layer 端到端上线

Gateway 运行、每席位一个 thread、inbound reconcile 恰好一次、escalation loudness（mention）与 routine 分离。人类是可寻址成员；`zrig gateway human` 具有完整 fragment lifecycle verb。任何智能体都可直接升级；escalation 类 send 会在目标手机上以高显著度到达。

### 全新安装自动 Onboarding

全新安装默认获得聚焦的 onboarding pack，配置默认为 off，现有工作组不受影响。新建工作组或席位时，无需再手工引导八个组成部分。

### Refocus 只在应触发时触发

Refocus 仅在达到上下文阈值或按需触发，**绝不在 session start 时触发**。两种运行时均支持压缩后 refocus；usage threshold 仅适用于 Claude。全新席位收到 refocus 现在应视为需要报告的 bug，而不是可忽略噪声。

### 单文件 Scope 约定

`scope mission create` 生成 `NOTES.md` + 携带 intent 的 `SPEC`；`slice create` 只生成 `SPEC`，不生成 `IMPLEMENTATION-PRD`，并生成 acceptance `PROGRESS`；release mission 获得 capability delta scaffold。`repair` 为叠加式：stamp 只追加，绝不重写作者 frontmatter。Stamp verification 再次采用机械 strip。

### 后台服务 Bind Intent 具有 Provenance

继承的 `OPENRIG_HOST` 绝不会选择 single bind；adoption gate 会测试所有必需 listener。从任意托管环境维护后台服务，不再需要 `env -u` 仪式。

## 请停止以下旧做法（在 0.5.4 下曾经正确，现在已经错误）

1. **停止逐 lock 执行作者重建协议。** Stamp 现在只追加，strip reconstruction 是机械过程。
2. **停止通过 `claimedAt` 算术 + capture 诊断 park。** `zrig parked` 以置信度和教学指引派生诊断；capture 只是 fallback glance。
3. **停止将延期工作存为 queue row。** Queue 是处理即将到来的顺序工作的 conveyor；延期工作放入任务目标工作区。
4. **停止为新工作创作 `IMPLEMENTATION-PRD.md` 和 `MISSION_NOTES.md`。** `SPEC.md` 是唯一 spec 文件，`NOTES.md` 是 chain 名称。
5. **停止默认通过 orchestrator 路由联系。** 任何智能体都可直接升级。
