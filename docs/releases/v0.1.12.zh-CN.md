# zrig v0.1.12

## 摘要

本版本强化了启动状态的真实性，改进了会话记录清理，并提高了 Claude 和 Codex 托管会话在恢复与故障恢复过程中的可靠性。

## 本次发布包含的内容

- 规范化可由用户解除的启动阻塞，避免将其误报为严重故障。
- 更彻底地清除过期的 Claude 启动状态和错误残留。
- 改进 Codex 恢复连续性检测以及 resume 元数据采集。
- 修复会话记录重绘和状态噪声的清理。
- 强化 Claude 托管会话启动时对 MCP 相关阻塞的处理。
- 提高 tmux 健康检查和实例化时序方面的运维可靠性。

## 面向用户的变更

- 因交互式启动提示而受阻的节点，现在会被规范化为“可由用户解除的启动阻塞”，不再停留在容易造成误解的过期失败状态。
- 当当前运行时证据能够证明旧的失败残留已经过期时，系统会更彻底地清理 Claude 启动状态。
- 恢复被包装的进程时，以及 TUI 已滚动或渲染了额外页脚、页眉噪声时，Codex 的恢复行为更加稳健。
- 会话记录清理产生的噪声更少，并能更有效地移除重绘和状态伪影，避免留下令人困惑的终端输出。

## 运维 / 初始化说明

- 升级后请重启后台服务，使新的启动与恢复行为生效：

  ```bash
  zrig daemon stop
  zrig daemon start
  ```

- 本版本改进了分类与故障恢复行为，但并不意味着每个被中断的运行时都一定能够获得原生连续性。运维人员仍应如实看待恢复结果；当产品提示无法证明连续性时，请使用手动恢复路径。

## 已知限制

- 生命周期和状态处理比以前更加真实，但 zrig 仍没有完全显式、达到基础设施级别的状态机。
- 恢复仍然取决于具体运行时并以证据为依据；部分故障恢复路径依然依赖启发式判断，而非完美的 provider 原生能力。

## 已执行的验证

- 在本版本开发期间执行了针对后台服务和 CLI 的定向测试。
- 对会话记录清理变更集进行了重点审查和验证。
- 在全新 VM 上验证已发布的 `@openrig/cli` package 的 npm 安装，包括后台服务启动、健康检查路由、doctor 检查、`zrig ps --nodes` 以及 UI 加载。
