# zrig v0.4.0

## 摘要

zrig v0.4.0 是一次“高 token 效率默认值 + 恢复能力收官”发布。智能体频繁运行的五个读取命令（`zrig ps`、`zrig whoami`、`zrig queue list`、`zrig restore-check`、`zrig context`）从默认输出海量信息改为默认紧凑，并通过显式 `--full` / `--all` 选择完整输出；`zrig queue list` 采用与 docker/kubectl 一致的读取命令 grammar：`-a` 表示历史，`-A` 表示跨工作组广度，`-o json|wide` 表示编码，`--mine` / `--source` / `--destination` 表示 scope。`zrig seat clear-attention` 扩展到处理 v0.3.4 已产生但当时无法触达的 restoreOutcome 派生投影过期。`zrig scope mission|slice create` 现在可靠搭建 `PROGRESS.md`，并提供 `progress` 更新 verb，使智能体通过命令更新进度，不再手改 Markdown。

这些面向用户的默认值背后还有多项改进：后台服务侧 payload 源头去重，使 `zrig ps` 的 `recoveryGuidance` 不再逐节点重复，list payload 中的 `contextUsage` 也变得紧凑，因此即使 `--full` 和 UI consumer 也不再为冗余付出代价；实时智能体终端取代只读 3 秒快照视图（slice 01）；多主机 dogfood 强化 `--host` 的跨主机使用（slice 02）；Agent Images library 增加 Fork-now 操作与行元数据（slice 07）；attention/activity 检测在 UI 中更充分消费 `agentActivity` 真实状态（slice 09）；技能级联 provenance 与 freshness 新增只读 `zrig skill audit` 界面（slice 10）；身份重构基础提供后台服务与 CLI 共用的 identity 类型（slice 11）；`zrig scope` progress rail 重新连接任务目标/slice 树、`PROGRESS.md` 与 Project UI（slice 15）；Codex resume 保留启动席位的 approval posture，使恢复后的席位能运行生命周期命令而不触发隐式拒绝（slice 17）；active/idle 节点状态环更加可靠（slice 18）；拓扑 graph view 的斜向 ghost 从源头修复（slice 21）；收尾阻塞修复 slice 24 交付 P1（For-You 下钻 captured/live 契约）和 P2（后台服务测试 harness WebSocket 注册）。

现有 v0.3.4 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。Migration 均为叠加式。

## 本次发布包含的内容

### 新的顶层 CLI verb 与子命令

- **`zrig skill audit`（slice 10）** — 新增只读命令与后台服务界面，包括 `/api/skills/audit`、discovery、mirror drift 检测和 skills route。它会报告从 canonical → product mirror → hub cwd → installed plugin 的技能级联中，missing / stale / self-referential / invalid-date / mirror-drift 等 provenance 问题。当 mirror-drift 证据不可用时，它会阻止 CLI 产生虚假绿色成功；这是 v0.3.4 wrap gate AC-3 几乎遗漏的失败模式。该命令与既有 `scripts/mirror-skills.mjs` guardrail 组合使用。
- **`zrig scope mission progress` / `zrig scope slice progress`（slice 33）** — 新增 `progress` verb，通过命令界面确定性地向 `PROGRESS.md` 追加、设置或更新条目，不再手改 Markdown。它写入 zrig PROGRESS UI 页面所读取的规范结构。

### 默认紧凑的读取命令（token 效率系列）

- **`zrig ps` — 紧凑默认值 + `--full` + 当前工作组默认值 + `-A`/`--all-rigs`（slice 25 + 34）** — 默认逐节点输出紧凑 TL;DR：session、工作组、活动状态与原因、assigned/pending 数量，以及最必要的身份恢复信息。`--full` 返回完整记录，与原始字节等价。**Slice 34 将广度默认值改为当前工作组**，根据 `OPENRIG_SESSION_NAME` 的 `@<rig>` 后缀推导，与 docker/kubectl 风格的 `zrig queue list` grammar 保持一致：`-A`/`--all-rigs` 扩展到全部工作组，`--rig <name>` 覆盖当前工作组默认值，`--session <sess>` 进一步缩小范围。默认仍显示所有状态；按 orch-lead 决定，ps 展示的是拓扑/就绪状态，stopped/recoverable/attention 正是可操作信号，与 queue list 默认只显示活跃项不同。`--active` / `--running` 仍用于选择活跃状态过滤。此变更解决根工作区一次约 77,000 token 的状态查看事故和 fleet scale 无界默认输出风险。**Resume token 安全性**：`--full` JSON 现在输出布尔值 `resumeTokenPresent`，不再输出 resume token 本身，避免 orchestration 浏览时意外泄漏 token。
- **`zrig ps` payload 源头去重（slice 26）** — 后台服务 node list payload 从源头裁剪：不再把几乎相同的 `recoveryGuidance` 模板正文序列化到每个节点，而是移到顶层 guidance-by-reference map，4 个现有 consumer 仍可解析；list payload 中 `contextUsage` 变为紧凑摘要，完整 telemetry 仍可通过逐节点 whoami/detail query 获取。约 7 个 contextUsage UI consumer 与 4 个 recoveryGuidance consumer 均已迁移且无回归。即使 `--full` 和 UI Project view 也不再承担逐节点冗余 blob。
- **`zrig whoami` — 紧凑默认值 + `--full`（slice 27）** — `zrig whoami` 和 `zrig whoami --json` 默认只返回身份恢复要素：`identity`、peers 名称与 sessionName、`edges` 的有向 kind 与 `to.sessionName`、`transcriptPath`。`--full`（别名 `--verbose`）返回此前的完整 payload，包括 `contextUsage`、`commands`、`peersNote`、`runtimeContext`。请求紧凑模式时，后台服务跳过 `contextUsageStore` lookup 和 `runtimeContext` 构建。智能体启动和每次压缩恢复时执行的首个命令从约 909 token 降到约 192 token。
- **`zrig queue list` — 活跃前沿紧凑默认值 + 读取命令 grammar（slice 28 + 32）** — 无 flag 时只返回活跃状态（`pending` / `in-progress` / `claimed` / `blocked` / `handed-off`，不含 `done` / `canceled`）、当前工作组广度以及紧凑行：id、state、source→destination/current-owner、handed-off/blocked 时的 closure_reason 与 closure_target、mission、slice、tier/priority、age/updated_at、短 title 和截断 tags。四个正交维度可以组合：
  - **`-a` / `--all`** — 在当前广度内包含 closed/done 历史，对应 docker 的历史轴。
  - **`-A` / `--all-rigs`** — 扩展为跨工作组广度，对应 kubectl 的广度轴。
  - **`--full`** — 在选定 scope 中增加 body、chain-of-record、完整 tag 和 transition 历史，对应字段广度轴。
  - **`-o json|wide`** — 控制编码，仍默认紧凑。`-o json` 不隐含完整 body，因此 compact JSON 兼顾 token 安全和机器可解析；`--full -o json` 才返回完整 JSON。
  - `--mine` 只返回调用者项目；`--destination <s>` / `--source <s>` 用于显式缩小 scope。此前 bare command 默认聚合跨工作组完整历史，在活跃主机约 64,000 token；现在只有显式 `-A -a --full` 才会获得这种完整输出。
- **`zrig restore-check` — 默认摘要 + 未就绪项 + `--full`（slice 29）** — 默认输出汇总数量（total / ready / not-ready / error-degraded）和未就绪席位；每个席位只含 seat 与 readiness reason。`--full` / `--json` 返回此前完整的全 fleet 逐席位 readiness。紧凑模式下，后台服务为 ready 席位计算 verdict 后跳过 detail assembly。`--rig <name>` / `--as <me>` 用于缩小范围。此变更解决读取命令界面上测得最大的输出风险，约 79,000 token。
- **`zrig context` — 默认紧凑摘要 + `--full`（slice 30）** — 默认输出常见用途需要的少数字段；`--full` / `--json` 返回完整当前 payload。紧凑模式下，后台服务跳过昂贵 aggregation。其收益低于 slice 28/29，但保证升级后读取命令一致采用紧凑默认值。

### 恢复与韧性收官

- **`zrig seat clear-attention` 扩展到派生投影过期（slice 16）** — v0.3.4 的 `clear-attention` 只根据 `session.startupStatus` 门控。首次真实生产使用在 host cutover 残留的 `advisor-lead@kernel` 投影中发现缺口：席位可能为 `startupStatus=ready` + `sessionStatus=running`，但携带 `restoreOutcome=failed` / `continuityOutcome=failed`；后台服务会派生 `lifecycleState=attention_required`，而 verb 却拒绝并返回 `{ok:false, code:not_in_attention}`。v0.4.0 `clear-attention` 现在同时覆盖 startupStatus 驱动的 attention 与 restoreOutcome 派生投影，继续使用相同的证据门控审计行和 `--reason <text>` 运维人员 attestation override。
- **Codex Resume 保留 Approval Posture（slice 17）** — 恢复后的 Codex 席位现在具有与全新启动相同的 permission/approval posture。此前恢复席位运行已发布生命周期命令时会遇到 “approval required but approvals disabled” 隐式拒绝且无解决路径。此项有界修复以 0.4.0 韧性集合为依据，并在 GS1 Studio capture 中发现。

### UI 与拓扑界面

- **真实交互终端（slice 01）** — UI 中的逐席位终端变为可交互：点击席位即可直接向智能体输入，共享 pane，保持“手在方向盘附近”；本地主机席位的只读 3 秒快照视图被淘汰。对于工作组高度“一览全部终端”同时打开约 20–30 个 pane 的性能约束，通过全局 `LiveTerminalRegistry` 限制并发 live terminal（配置 key `ui.terminal.max_live_terminals`、环境变量 `OPENRIG_UI_TERMINAL_MAX_LIVE_TERMINALS`），并采用 progressive multi-live 模型：用户关注处为 live（focused popover / grid 原位展开 / node detail panel），其余位置显示静态烟熏玻璃缩略图，由 `LiveTerminalProvider` 协调。拓扑 grid 支持原位 multi-live，focused / popover / grid / node-detail 共享烟熏玻璃样式。远程席位终端留到 0.4.1，因为需要后台服务间 transport。
- **真实终端 Session Broker（slice 38）** — 来自 2026-06-21 founder live dogfood 的发布关键可靠性修复。旧架构每个 view 都建立 WebSocket，且每个 WebSocket 对同一 pane 启动自己的 tmux `pipe-pane`；tmux 每个 pane 只允许一个 pipe-pane，打开同一会话的第二个 live view 会**夺走第一个 view 的输出**，导致在一个可见终端输入，echo 却出现在另一 tab。v0.4.0 使用由后台服务拥有、以规范 `sessionName` 为 key 的 `TerminalSessionBroker`：每个会话一个 tmux pipe-pane、N 个 WebSocket subscriber、output fanout、会话级 seed 与供后加入 subscriber 使用的共享 scrollback ring、显式 input owner 语义（focused view 才可发送输入），以及最后一个 subscriber 离开或会话终止时的真实清理。`terminal-ws` 现在只是轻量 broker subscriber，不再逐连接拥有 pipe-pane。**Resize policy 使用规范固定 geometry**：broker 将 tmux pane 固定为适合 Claude/Codex TUI 的 120×40 grid；subscriber 只通过 CSS 适配/滚动容器，绝不发送 tmux resize。这样只有一个稳定真源，不会发生 resize 争夺，TUI 始终以最佳宽度渲染。
- **统一静态/实时终端组件（slice 39）** — 静态缩略图与 live xterm 共享同一个 `StaticTerminalPlate` 组件和 mirror geometry：缩略图/mirror 为 90×27，broker live stream 为 120×40，缩略图是 live stream 适配容器后的投影。包括 opaque mirror render、静态 line return 修复、grid 原位 multi-live 和 graph/table popover。缩放 view 中的 live terminal selection 现在使用 fontSize 缩放而非 CSS transform，因此文本选择能落在正确字符 cell。Geometry 注释清理不改变行为，但消除了会误导后续修改的过期注释。
- **Agent Images Library 完善（slice 07）** — Agent Images library UI 为可 clone image 增加 `Fork now` 操作，组合既有 add-member endpoint 与 `session_source.mode: "agent_image"`；增加轻量行元数据（version、token、fork-count、last-used）；并正确渲染嵌套失败，嵌套 `failed` / `attention_required` 显示红色失败而非绿色成功。Image 缺少 `sourceCwd` 时隐藏/禁用 Fork-now；确认路径要求存在 runtime 匹配且携带 `agentRef` + `profile` 的 sibling；不会虚构 fallback cwd。
- **Attention / Activity Detection — Elite Tier（slice 09）** — UI 和运维界面更充分消费 0.3.4 中已经存在的 `agentActivity` 真实状态，包括 needs-input 突出显示、time-in-state 和 POST-18 activity rollup。
- **拓扑 Graph View Ghost 渲染修复（slice 21）** — 从源头修复 Dashboard topology/graph view 节点后方的斜向 ghost。该问题出现在 launch video reviewer kit 的每次 graph view capture 中，table view 已无此问题；涉及 launch video 与 Dashboard 的核心展示界面。
- **可靠的 Active/Idle 节点状态（slice 18）** — 亮/暗 activity ring 已经发布；本 slice 完成 `DOT→terminalActive` fallback，并移除已失效的 `pane_silence_flag` 派生逻辑，为旗舰视频 F1 提供可靠信号层。

### 多主机与身份基础

- **多主机 Dogfood（slice 02）** — `--host` CLI flag 在 0.4.0 前已经发布；本 slice 通过多机器 dogfood 和外部 QA 补全跨机器集成故事。Transport 以 HTTP 为主；跨主机身份留到 0.4.1。
- **原生 Codex Session Identity（slice 11）** — 提供后台服务与 CLI 共用的 identity 类型，包括原生 Codex session identity capture，并为 0.4.1 的 slice-12 identity refactor 奠定基础。

### Scope 自动化

- **`zrig scope` 搭建 PROGRESS.md + README（slice 33）** — `zrig scope mission create` 和 `zrig scope slice create` 现在按照 `conventions/scope-and-versioning/README.md` 创建规范 `PROGRESS.md`（zrig PROGRESS UI 页面解析的结构）以及具有正确 frontmatter 的 README，修复新建任务目标与 slice 完全缺少 `PROGRESS.md` 的问题。`zrig scope ... progress` 更新 verb 可确定性地追加、设置和记录进度条目；智能体通过命令更新，结构天然可被 UI 读取，不再因手改 Markdown 漂移。
- **`zrig scope` stage / verified / reconcile verb（slice 35）** — 将 `conventions/scope-and-versioning` §2 的成熟度词汇（`stage` + `verified`）通过命令强制执行，不再手改 Markdown；与 slice 33 的 `PROGRESS.md` 和搭建功能组合，使 `zrig scope` 成为确定性的约定执行器。
  - `zrig scope <slice|mission> stage <id> <new-stage>` — 确定性设置 `stage`（wip / provisional / established / canonical / superseded / retired）。`superseded` 必须提供 `--successor <id>`，否则拒绝；`retired` 警告“请勿使用”；无效 stage 会被拒绝并列出有效集合。
  - `zrig scope <slice|mission> verified <id> --against "<source>"` — 在 frontmatter 写入 `verified: <today> against <source>`。`--against` 必填；拒绝只有时间戳的写法，因为裸时间戳会让过期 tracker 看似新鲜。该命令覆盖此前的 verified 行。
  - `zrig scope <slice|mission> reconcile <id>` — 幂等修复 verb，补全缺失的 `PROGRESS.md`，对齐必填 frontmatter（`id` / `stage` / `verified`），并修复 id registration ghost（`id:null` / 重复 prefix）；可安全重复运行。
  - `zrig scope <slice|mission> create` 现在写入必填 `stage`（默认 `wip`）和 `verified` placeholder，因此不会再产生缺字段的新产物。
  - `zrig scope <slice|mission> show` 在读取时从 stage × verified 派生 effective reliability：`verified` 过期的 `canonical` 会显示为实际 `provisional`；这是派生值而非存储值，为 UI 和智能体提供自校正信号。
- **由 Scope 支撑的 Progress Rail（slice 15）** — 将 scope tree、启动技能、`PROGRESS.md` rail 和 Project UI 警告连接成一致工作流。0.3.4 发布审计发现任务目标/slice 树与 queue traffic 已很丰富，但 Dashboard 依赖的 `PROGRESS.md` 缺失或使用不足。它与 slice 33 配套：33 提供命令，15 提供使用该命令的工作流。

### Bug 修复收尾

- **收尾一致性修复（slice 24）** — 来自 0.4.0 convergence 深度审查的收尾阻塞 bug-fix slice，修复两个窄范围真实终端集成缺陷：**P1** For-You terminal drill 混用了 captured/live 契约，位于 slice 01↔09 交界；**P2** 无条件 Node WebSocket 注册破坏后台服务 test harness，使 suite failure 从 51 增至 411。按 founder 要求，两者都属于收尾前必须落入 0.4.0 的真实一致性 bug。Reviewer 未发现更广泛的跨 slice 一致性问题。

## 面向用户的变更

### 新界面（请使用这些方式）

- **读取命令默认紧凑**：`zrig ps`、`zrig whoami`、`zrig queue list`、`zrig restore-check`、`zrig context`。覆盖范围保持不变，默认 payload 大幅缩小；需要完整输出时使用 `--full`，queue list 则使用 `-A -a --full`。
- **`zrig queue list` grammar（与 docker / kubectl 一致）**：
  ```
  zrig queue list                      # 活跃、紧凑、当前工作组
  zrig queue list -a                   # 加入 closed/done 历史
  zrig queue list -A                   # 跨工作组广度，与 kubectl 的 -A 一致
  zrig queue list --full               # 加入 body + chain-of-record
  zrig queue list -o json              # 紧凑 JSON，token 安全
  zrig queue list --full -o json       # 完整 JSON
  zrig queue list --mine               # 仅调用者项目
  zrig queue list --destination <s>    # 目标为 <s>
  zrig queue list --source <s>         # 来源为 <s>
  zrig queue show <qitemId>            # 完整单项，类似 kubectl describe
  ```
- **`zrig skill audit`** — 对技能级联执行只读审计，检测 canonical → product mirror → hub cwd → installed plugin 链中的 missing / stale / self-referential / invalid-date / mirror-drift；mirror drift 证据不可用时不会产生虚假绿色成功。
- **`zrig scope ... progress`** — 确定性更新 `PROGRESS.md`。通过命令追加条目、设置状态、记录里程碑；UI 读取的正是该命令写入的规范结构。
- **`zrig seat clear-attention` 支持 restoreOutcome 派生投影** — v0.3.4 的 verb 现在可处理第二类投影过期，继续使用相同的证据门控审计行与 `--reason <text>` 运维人员 attestation override。

### 应停止使用的旧方式

- **不要再把 `zrig ps --nodes --json` 当作随手状态检查。** 紧凑默认值用于常规检查，完整输出使用 `--full`。逐节点几乎相同的 `recoveryGuidance` 正文已去重；逐节点完整 `contextUsage` 已从 list payload 移除，应通过单节点/whoami/detail query 获取。
- **不要再把 bare `zrig queue list` 当作跨工作组完整输出。** 默认是活跃 + 紧凑 + 当前工作组。跨工作组 ambient frontier 使用 `-A`；跨工作组加历史使用 `-A -a`；完整输出使用 `-A -a --full -o json`。
- **不要再在启动时用 `zrig whoami --json` 获取重 payload。** 默认返回紧凑身份要素；`--full` 或 `--verbose` 返回完整 payload。
- **不要再把 `zrig restore-check` 当作逐席位详情 fleet scan。** 默认只返回摘要与未就绪项；确需逐席位详情时使用 `--full`。
- **不要再手改 `PROGRESS.md` 记录进度。** 使用 `zrig scope ... progress`，它确定性地产生 UI 可读结构，不会漂移。
- **不要再为新任务目标/slice 手建 `PROGRESS.md`。** `zrig scope mission create` 与 `zrig scope slice create` 现在会自动搭建。
- **不要再在运行 0.4.0 的主机上应用 token-efficiency-boot-guardrail 的 CLI 命令禁令。** 这些禁令只是旧版主机默认输出臃肿时的 workaround，本版本已解决。Pack 的 bounded local search 规则和 scope/over-flag discipline 升级为长期约定 `conventions/bounded-local-search-and-flag-scope`，继续跨主机版本生效；CLI 命令禁令在主机升级到 0.4.0 后退休。

### 运维 / 初始化说明
