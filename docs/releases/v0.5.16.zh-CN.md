# zrig v0.5.16 — 选择 Claude 指令文件

版本 **0.5.16** 的变更。Publication 状态与日期记录在 [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.5.16) 和 npm 中。

zrig 0.5.16 允许工作组不把 managed Claude Code 指令写入已纳入版本控制的 `CLAUDE.md`，并为 pull request 新增 advisory portability report。

## 保持已纳入版本控制的 CLAUDE.md 不变

zrig 将 Claude Code 成员的指令写入各成员工作目录中的 managed block。默认文件是 `CLAUDE.md`。如果仓库跟踪 `CLAUDE.md`，可在工作组 spec 中选择 `CLAUDE.local.md`：

```yaml
managed_blocks:
  claude-code: CLAUDE.local.md
```

Claude Code 同样会从工作目录加载 `CLAUDE.local.md`；请不要将其提交到 Git，例如可添加 `.gitignore` 条目。该选择会在成员 launch、restore、relaunch 或 add 时应用，并由 `zrig export` 和工作组 bundle 保留。`zrig down` 只会从选定文件中移除 zrig managed block。zrig 绝不会编辑、移动或删除另一个文件中的 block。

只接受 `claude-code` key，值只能为 `CLAUDE.md` 或 `CLAUDE.local.md`；任何其他 key 或 value 都会在成员启动前被拒绝。不提供该字段时行为不变。Codex 成员始终使用 `AGENTS.md`。

**切换现有工作组：** zrig 已写入 `CLAUDE.md` 的 block 会保留。移除前，该文件仍处于 modified 状态，Claude Code 会同时加载两份副本。请手动删除每个 `<!-- BEGIN OpenRig MANAGED BLOCK: … -->` … `<!-- END OpenRig MANAGED BLOCK: … -->` 区段，并保留文件其余内容。如果 `CLAUDE.md` 不含需要保留的其他未提交修改，也可以改为运行 `git restore CLAUDE.md`；该命令会丢弃文件中的**所有** unstaged change，而不只是 zrig block。详情参见 [RigSpec 参考](../reference/rig-spec.md#choosing-the-claude-instruction-file)。

## Pull Request Portability Report

新的 pull request workflow 会列出新增行中与单台机器、网络或账户绑定的值，包括 credential、home/temp path、network address 和 email address。疑似 credential 不会显示在报告中。Finding 永远不会令检查失败，是否修改由作者决定。该检查基于 pattern，不能保证所有私密信息均已清除。本地运行方式：

```sh
node scripts/portability-report.mjs
```
