# zrig v0.5.15 — 首次使用恢复、Software Factory 指引与 Pi 修复

版本 **0.5.15** 的变更。Publication 状态与日期记录在 [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.5.15) 和 npm 中。

zrig 0.5.15 改进启动与恢复，增加持续软件团队和用户自选命令权限的公开指引，并修复 Pi reply 可见性、shell context 和 terminal input 处理。

## 以更清晰的指引启动并返回

启动前，请阅读 [zrig 会对你的机器做出哪些变更](../../README.md#what-openrig-changes-on-your-machine)。Provider 集成可能配置 executable hook 和 workspace trust；只改变 `OPENRIG_HOME` 无法隔离 provider 配置。[入门指南](../reference/getting-started.md)会引导完成首个任务，并解释这些 setup effect。

检查当前安装中可用的命令：

```sh
zrig --version
zrig --help
zrig up --help
```

Startup 与 recovery 可以通过 shell 和 Node launcher 识别原生 Codex；无法确认 process identity 时会报告不确定性。已识别的 update notice 会被跳过，不会安装 provider update。Authentication 与 trust 选择仍由用户决定。

启动错误现在会说明问题和恢复操作。如果一个名称同时匹配 starter 和 stopped 工作组，`zrig up <name> --existing` 会选择现有工作组。分配更多工作前，请检查报告的状态。

## 持续推进有价值且经过 Review 的工作

为智能体提供真实仓库、期望 outcome 和需要保留的 decision。Bundled zrig Software Factory recipe 支持直接 team work、queue supported orchestration 或可选显式 Workflow。

```sh
zrig context show skills/core/openrig-software-factory --json
zrig context get skills/core/openrig-software-factory/SKILL.md
zrig context get skills/core/openrig-software-factory/references/worked-example.md
```

从双席位团队开始。当工作适合分离职责时，使用 `zrig grow` 增加一到两个席位。示例覆盖 role、context、work ownership、independent review、concurrency 与 cost，并区分修改运行中团队与保存更新后的 RigSpec。请使用与已安装版本匹配的指引。

## 选择命令权限

请让智能体检查目标 harness、解释可用 scope，并在保留现有 rule 的前提下应用选择：

```sh
zrig context get skills/applying-a-permission-policy/SKILL.md
```

允许整个 `zrig` 命令族，意味着同时允许 lifecycle/configuration change 与 read。适当时请选择更窄命令，或保留 approval prompt。Project only setup 要求受支持、活跃且 trusted 的 project 配置；不可用时，智能体应解释限制，而非改用 user wide permission。备份受影响文件，并在实际 conversation 中验证选定 rule。已发布 sandbox、approval 和 permission 默认值不变。

## 已知兼容性限制

在 macOS arm64 与 Node 24 上，当没有合适预构建 binary 且无法编译时，SQLite dependency 安装可能失败。通过 compiler 构建的 SQLite 也曾在运行时数据库 cleanup 期间失败。**目前请在 macOS arm64 上使用 Node 22。** 此建议不改变声明的 Node 支持范围，本版本也未更新 SQLite。

## Pi Reply、Input 与恢复

对于受支持 RPC event shape，Pi reply 和 tool progress 现在可见。Shell tool 保留 identity 与 routing 所需的 managed zrig context。Provider error 使用有界文本显示；retry 耗尽后不会重复打印同一错误。

粘贴的消息会等待显式提交。Terminal runner 接受超过终端规范 buffer 上限的 input，同时保留 edit 和 cancel 能力；拒绝过大 framed message 后可以恢复。这不是通用 latency 保证，也不是无限 input size 承诺。

新增席位首次启动若在保存 startup context 前因 resource projection 失败，修正 setup 问题后可以使用 guarded retry。必须保留完整的原始 member fragment 与 source root；只有 snapshot 无法重建缺失的 startup configuration。每次只执行一次 retry。普通 conversation resume 与此相互独立。

**Pi 支持是有限定且受监督的。** 使用 Pi 0.87.1 与 OpenRouter `z-ai/glm-5.3-flash` 已验证受控 coding、follow-up、reporting 和 conversation continuity；普通席位 identity、tool 与一次 reply 也可工作。普通有用任务完成和无人值守团队运行仍未验证。Context profile selection 与 hook generation 覆盖有限；不要假定与每个 Codex 或 Claude 集成等价。Software Factory 指引同样不能证明完全无人值守运行。
