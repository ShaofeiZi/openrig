# zrig v0.4.1

## 摘要

zrig v0.4.1 对可观测性和运维 UI 进行了全面升级：工作区成为开发者的任务目标驾驶舱。Project UI 使用工作高度投影（工作区 → 任务目标 → slice）和一致的 tab 集合，取代 v0.4.0 中尚未完成的 Project 页面。Mission landing tab 显示 steering 和面向人类的任务目标 brief；Story tab 将 queue lineage 派生的真实任务过程重建为可滚动 git graph；Workflow tab 可视化已配置的 workflow spec；Artifacts navigator、Proof tab 与 Progress heat map 为工作区高度提供原生界面；Dashboard 路由也获得简洁的视觉刷新，成为启动器首页。

底层方面，UI digital twin 可以根据 typed fixture，在无需后台服务的情况下 1:1 渲染全部六个真实 Project 界面，使视觉意图能够在任何 UI slice 构建前获批，并在最后通过真实截图证明。拓扑 edge flow 动画展示拓扑 graph 上真实的 queue/handoff 移动，由信号驱动，绝非装饰。For-You feed 采用适合手机的样式，同时保持真实数据保真度。

新 CLI `zrig auth` 是产品原生、CLI 本地的 Codex auth profile manager，具有强化的 secret boundary，会拒绝通过 symlink 和 hardlink 逃逸 CODEX_HOME。`zrig send` 提供三层交互 prompt guard：目标 pane 位于 prompt 时默认阻止发送；`--raw` 原始按键仍受保护；`--dangerously-interact --reason` 是经过审计的 override，防止 peer 消息意外选择另一个智能体终端中的选项。

可靠性修复方面，全新执行 `npm install -g @openrig/cli` 后再运行 `zrig daemon start` 现在能够正常解析依赖。此前缺少 `@hono/node-ws` runtime dependency，开发主机上的 monorepo hoisting 掩盖了问题，但全新安装会失败；CLI 现在镜像后台服务完整 runtime dependency 集合，并由 package completeness test 守护。Table view 与 hybrid terminal action 的错误会显示为可见 alert，不再静默失败，且 table terminal 能正常打开。Queue item 新增人类可读 `summary` 字段（叠加式 migration 044，author 阶段以 WARN 渐进启用）。

现有 v0.4.0 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。Migration 均为叠加式：044 新增 nullable `queue_items.summary` 列；0.4.1 前的项目会安全回退到从 body 派生的 label。

## 本次发布包含的内容

### 新的顶层 CLI 界面

- **`zrig auth`** — 产品原生、CLI 本地的 Codex auth profile 管理。在 CLI 拥有的 `~/.openrig/codex-auth/` 下 list / show / switch / capture / forget Codex profile，绝不越出 CODEX_HOME。对抗性路径已关闭：拒绝 symlink active auth，hardlink 和 symlink parent 不能逃逸 CODEX_HOME，并有集成测试验证 secret boundary。它用一个一等产品界面取代了产品外临时 Codex auth 切换方式。

### `zrig send` — 交互 Prompt Guard

Peer 消息不再能意外选择另一智能体终端中的选项或批准权限。保护分为三层：

- **L0（默认）** — 当目标 pane 处于交互 prompt 或 permission block 时，`zrig send` 会被阻止。检测以 hook 为主（Codex `PermissionRequest`），并使用强化的 capture-pane fallback（扫描末尾 12 行内容 + 15 秒 send readiness freshness）。
- **L1 — `--raw`** — 发送精确按键，但 L0 guard 仍然生效。
- **L2 — `--dangerously-interact --reason "..."`** — 显式 override，隐含 `--raw`、强制要求 `--reason`，并写入审计行。

这关闭了长期存在的脚枪：stand-down 消息可能会提交默认 authorize-publish 选项。

### 工作区可观测性 Tab（重点）

- **Steering tab（任务目标 landing）** — Panel 1 投影 `STEERING.md`，即智能体当前收到的指令；Panel 2 投影采用新的锁定 7 节 schema、面向人类的 `MISSION_BRIEF.md`。点击进入任务目标时默认打开此 tab；Overview 仍可使用。
- **Mission brief 文档类型与投影** — 与 `README.md` / `PROGRESS.md` / `MISSION_NOTES.md` 并列的真实、规范、面向人类的文档类型。`zrig scope init-workspace` / `zrig scope mission create` 根据 7 节模板创建根 `MISSION_BRIEF.md`（Brief / What & why / Building / Progress / Proven / Needs you / Pointers），也可按需向现有任务目标补全同一模板。Mission Steering tab 将其从 Markdown 渲染到 UI。
- **Story tab — queue item DAG git graph** — 根据 `chain_of_record` 和 handoff lineage 重建 DAG forest，并显示为可滚动、向上增长的 git graph。只使用单 parent edge，不虚构 merge state；一行内容配曲线 gutter；行展开后占满宽度；Tier-3 drawer 复用 queue item viewer，展示完整智能体正文与 chain。任务目标和 slice 高度均支持；客户端直接消费既有 `/api/queue` read API，无新增界面。Queue tab 合并到 Story。
- **Workflow tab — spec visualizer** — 将尚未完成的 Project Topology tab 补成真实的只读 workflow spec visualizer：点阵 grid canvas、深色 header step card、逐 step 状态点、dagre LR 布局、amber reject → rework loop back。标签从 Topology 改为 Workflow，test id `project-tab-topology` 保持稳定。任务目标与 slice 高度均支持。只作用于 Workspace，独立 Topology 页面（NOC）不变。
- **Proof tab** — 逐 slice proof gallery，并为已搭建但没有内容的 slice 显示 empty state。读取 slice 的 `proof/` 目录，以及存在时的 `PROOF.md` 摘要。
- **Progress heat map** — Project Progress tab 收敛为 heat map，移除逐 slice rollup card；heat map 提供一眼可见的状态，避免重复 card 噪声。
- **Artifacts navigator** — slice 高度的 `ArtifactsNavigator` 取代旧 `SliceArtifactsTab` card wall；文件与文档通过同一 `/api/files/*` 界面解析；proof 产物归 Proof tab 管理；Decisions 界面路由到 Story，因为 decision of record 项本来就是 Story node。
- **Workspace portfolio** — 工作区 parent 高度显示跨任务目标 portfolio panel：任务目标列表展开时包含 steering glance，惰性获取 `MISSION_BRIEF.md`；汇总指标统计的是从 `hasProofPacket` 获得的 *proven* 数量，而非 `done`。

### UI Digital Twin 与“视觉意图 → 证明”约定

- **UI digital twin（harness）** — derive-from-source twin 使用 typed fixture，在无需后台服务的情况下 1:1 渲染六个真实 Project UI 界面。实现方式是 cache seed、轻量 fetch override 和 seeded SSE stream，**不使用 MSW**。每个界面输出一个自包含 `intent.html`；tsc 在编译期守护漂移，真实 interface 变化会让 twin build 失败；每个 slice 的创作循环约两步；dev-only target 与生产隔离。可使用 `TWIN_ROUTE=<route> npm run twin:build` 构建任意界面。
- **`zrig scope` intent visual slot** — `zrig scope slice create` 搭建的 slice `README.md` 包含 `## Intent visual` slot，其中有 `[change.diff]` 和 `TWIN_ROUTE=<route> npm run twin:build` 重建命令。非视觉 slice 会显式写入 `N/A`，确保每个 slice 都是存在 slot 或明确 N/A。
- **视觉意图 → 证明约定** — 与 harness 同步采用：构建前先通过 twin mockup 批准视觉意图，结束时再以真实截图证明。Twin data freshness 条件要求每个全新 UI 界面都有 twin fixture 且数据结构与真实情况匹配，并纳入 release close gate。

### Topology 与 For-You

- **拓扑 edge flow 动画** — 当真实 queue handoff 或 `zrig send` 沿 edge 从 source 流向 destination 时，edge 沿 handoff 方向动画、live 时高亮，并在 TTL 后恢复静态。真实性契约保持：只有真实 queue/send 信号才触发动画，不使用 workflow DAG 或环境动画；无信号 edge 保持静态；reduced motion 模式不显示流动。仅应用于 topology graph 界面。
- **For-You 手机样式与真实数据保真** — Dashboard 样式扩展到 For-You，采用适合手机的 card 布局和 altitude dial level filter（All activity → Highlights → Needs you，不同 level 显示不同 card 集合）。内部 `source.type` wrapper 字符串不再渲染到 feed card；过滤 feed 上方遗留的 storytelling preview band 已移除，因为它忽略 level filter 并在视觉上掩盖新样式。

### 可靠性与正确性

- **全新安装后台服务启动修复** — CLI package 现在声明 `@hono/node-ws`。CLI vendoring 构建后的后台服务，且不依赖 `@openrig/daemon`，因此其 `package.json` 必须镜像后台服务 runtime dependency，才能在全局 `npm install -g @openrig/cli` 中解析。Monorepo hoisting 的盲点导致开发主机正常而全新安装失败；package completeness gate 现在会在任何后台服务 runtime dependency 未镜像到 CLI 时令测试失败。
- **Table / hybrid terminal action 可靠性** — Topology Table view 与 hybrid 界面中的 terminal action 错误会显示为可见 cmux/auth alert，不再静默失败；Table terminal 现在能正常打开。
- **Queue item 人类可读摘要** — queue item 新增 nullable `summary` 字段（migration 044）。`zrig queue create` 与 `zrig queue handoff` 新增 `--summary`，采用 WARN-on-author：缺失时警告，但不会强行中断现有调用者，属于渐进式 enforcement。智能体正文仍是真源，可在 queue item drawer 中查看。Story row label 优先使用作者提供的 summary；0.4.1 前项目安全回退到 body label。
- **席位 scope 的压缩后恢复** — Claude Code 席位从 JSONL transcript 派生 scope 明确、幂等的恢复 packet；压缩后的智能体根据持久证据重建工作心智模型，不依赖模糊回忆。
- **Table view 崩溃修复** — TanStack filter 增加 null safety，三个 topology Table mount（host / rig / pod）均增加 `ErrorBoundary`，单条错误行不会让页面崩溃，并新增回归测试。
- **Dashboard 路由刷新** — welcome/home launcher 路由获得纯视觉升级：paper draft launcher grid、六张 card、Field Environment 与 drafting footer。仅改变外观，六个 launcher route 和 card test id 均保留。

### 采用的约定

- **视觉意图 → 证明** — digital twin 约定包含三项已批准内容：derive-from-source twin（不使用 MSW）、每个界面一个 `intent.html`、twin data freshness 作为 release close 的剩余检查。
- **Release durability close — AC-9（技能级联完整性）** — 发布集合的 `zrig skill audit` 必须干净，每条 drift edge 为绿色，内置插件与 canonical 对齐，只允许声明过的转换。Condition 2（drift edge）在 shipping cascade checker 落地前仍为 advisory；condition 1 和 3 从本版本起为 hard gate。
- **Release durability close — AC-10（twin data freshness）** — twin 的组件外观通过结构保证 1:1；门禁只覆盖结构无法保证的两项残差：dummy dataset 代表性（由 twin build 机械检查）和 net-new route fixture 覆盖。

## 行为与兼容性

- **Migration** — 仅叠加。Migration 044 新增 nullable `queue_items.summary` 列；0.4.1 前的项目回退到 body label。未包含 044 的 0.4.1 前后台服务，也会通过 `detectQueueColumn` guard 的读取路径安全降级。现有 v0.4.0 数据库可运行 `zrig daemon start` 升级。
- **`zrig queue create` / `zrig queue handoff` — `--summary`** — 可选；缺失 summary 只发出 WARN，绝不 hard error，以便平滑迁移。未来强化可能改为强制要求。
- **`zrig send` 默认行为** — 目标 pane 位于 prompt 时拒绝发送。显式 override 路径为 `--dangerously-interact --reason "..."`。
- **Project tab 外观重命名** — Topology → Workflow，test id 保持稳定；Queue 合并到 Story。
- **For-You feed** — `/for-you` 的 storytelling preview band 已移除，其任务目标 progress rollup 仍保留在 Dashboard / Project。

## 已知限制与后续事项

- **技能层切点深度（slice 04 family）** — canonical 技能层切点仍需决定 load-bearing skill 集合，本版本不执行切点。04.3 shipping cascade drift checker 未进入本次发布。
- **约定漂移控制（slice 28）** — 已部分交付；约定已批准并纳入 release close gate，但 shipping product skill 与 audit code 仍在进行。
- **Twin capture 工具（slice 11.2）** — twin harness 已发布；单命令 capture wrapper 仍在进行。
- **工作区 UX 架构（slice 15）** — design discovery scope 已批准；剩余 mockup 仍在进行，它们限制未来 UI slice，不限制 0.4.1 已发布界面。
- **For-You 终端手机 UX（slice 27）** — For-You 样式与真实数据保真已经发布；嵌入终端的手机 UX（键盘/触控/宽度/性能）仍是非门禁 polish 检查，尚未在手机上验证。
- **`zrig send` 交互 prompt guard 的 hook-primary 路径** — fallback capture-pane guard 已完整证明；hook-primary `PermissionRequest` 路径随本版本落地，完整证明留待下一次迭代。
- **`zrig auth` 后续事项（B1 secret boundary）** — 已合并的对抗强化关闭 symlink 与 hardlink escape；更深层结构化后续事项单独跟踪，不在本切点。
- **继承的级联元数据卫生** — 0.4.0 延续的技能层 `missing_provenance` + `missing_verified` audit finding 仍是已记录残留；批量修复属于单独的 0.4.0 后技能卫生工作项。
