# zrig v0.5.9 — 对开发者友好的任务控制

zrig 0.5.9 将终端 UI 提升为真正的任务控制界面，并为其下层 instance 提供更简洁、更持久的运维模型。TUI 在常见终端尺寸下更易扫描、导航和操作；System World、project context 和 managed skill 现在显式组合；restore、fresh launch、scheduled wake 与 project workflow 会报告实际操作的状态。

## 对开发者友好的终端 UI

- **一眼读取整个 instance。** Topology view 现在以跨工作组的连续智能体表格展示，并保持 pod separator 可见；从重要 queue transition 中显示有界 `RECENT` 工作，不重复归档工作组，也不虚构缺失 summary。
- **从概览进入操作而不丢失上下文。** Instance、工作组、任务目标、slice、智能体与 Explorer 页面共享同一 responsive visual grammar；滚动时保留工作组 identity，并在 160、120、84 列宽下保持 lifecycle evidence 与 action 可达。
- **将终端作为一等界面。** Semantic state color、紧凑 glyph、克制 motion、resize redraw、filtering、pointer local scrolling、终端原生 selection/copy、attach action 和 socket driven command，均通过同一个生产界面工作。

## 一致的 Instance、Context 与 Skill 模型

- **从统一的叠加式 instance layout 启动。** CLI 与后台服务启动会 reconcile 同一规范 `$OPENRIG_HOME` 结构，保留现有内容，并在写入前拒绝类型错误的 managed path。
- **将 System World 与当前 project 组合。** `context.root` 是可寻址上下文库，`context.system_world` 选择 instance wide baseline，`zrig context work-install` 会一起报告 System World、topology 和 project 输入。
- **将 skill 作为独立资源管理。** `skills.root` 指定一个可版本化 catalog。`zrig skill loadout` 组合 system、topology 和 project selector；apply mode 只拥有 manifest 列出的 projection，并拒绝擦除 local 或 modified content。
- **以合适宽度预热每种运行时。** Provider shaped onboarding 为 Codex 提供紧凑 bootstrap 与可寻址 coverage map，同时为受益于完整引导的运行时保留更完整路径。

## 生命周期与恢复真实性

- **为单个席位创建有意空白的 occupant。** `zrig seat launch <seat> --fresh --reason <why>` 是显式无连续性路径；它会保留 sibling seat 和 durable work，并拒绝 unmanaged ambiguity。
- **将作者编写的工作编译为可执行生命周期。** `zrig workflow compile` 将 `project.yaml`、`mission.yaml` 和 `slice.yaml` 作为一张 graph 读取；`instantiate-lifecycle` 用 opaque replay key 启动符合条件的 graph；typed acceptance evidence 防止 workflow advance 冒充 release acceptance。
- **了解 restore 尝试了什么。** 可以显式选择 snapshot，snapshot 可以保留 intended seat roster；`zrig restore status` 会派生当前 intended set 结果，同时排除 historical node 和未经验证的 resume lineage，避免虚假成功。
- **保持自动化可归因。** Watchdog reminder 使用显式 scheduler identity 投递作者编写的消息；effective model 检测跟随身份已验证的当前 occupant，而不是保留的 predecessor session。
- **只在值得时使用判断循环。** 已发布的 `agent-operated-workflows` 技能区分 AI enabled software、agent operated workflow 与 agent operated software。0.5.9 instance migration 是其首个参考实现。

## 升级与初始化说明

- Root、CLI、后台服务和 Web UI package version 前进到 `0.5.9`；终端 TUI 保持独立版本 `0.1.0`。
- 数据库 migration head 从 `078_idle_gate_fired_condition` 前进到 `079_workflow_lifecycle_parallel`；后台服务正常启动时自动应用。
- 现有 instance 具有明确 layout boundary：context telemetry 移到 `state/context-usage`，provider telemetry 位于 `state/provider-usage`，可寻址 library 移到 `context/`，默认 System World 位于 `context/system/system-world.yaml`。
- 旧 collector 正在写入时，不要通过直接重命名目录来完成变更。请加载已发布的 `openrig-upgrade` 技能，并遵循其 0.5.9 Agent Operated Migration：检查、保留 preimage 后准备、单独启用精确 target runtime、验证成对 canonical sample，最后使用该精确 receipt 调用非破坏性 library finalizer。完整命令序列与 rollback 契约位于顶层 README。

## 已知限制

- Migration helper 有意不停止或启动后台服务、不修改数据库、不重启席位，也不删除旧 telemetry/library state。这些生命周期和最终退休决策仍由运维人员显式执行。
- Restore attempt receipt 只派生持久 event 与当前 process evidence 能证明的内容；native identity 缺失或有歧义时保持 unresolved，不会猜测。
- TUI 仍是终端界面。字体选择和终端颜色渲染由用户的 terminal emulator 决定，而不是 zrig。
