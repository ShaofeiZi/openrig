# zrig v0.5.3

## 摘要 — “上下文版本”

**v0.5.3 让上下文进入规范轨道。** 可以按地址提取已发布技能和 library entry 的精确章节，无需读取整个文件；可以通过提问发现上下文，无需猜测路径；refocus 自动解析 ref；handover 会写入持久、带 superseded chain 的席位 recap，并将其加入每个 restore packet；组合通过引用完成，因此不会产生可能漂移的第二份副本。

**v0.5.3 完整包含 v0.5.2。** 两者属于同一 lineage，没有分歧。

没有新 migration。Migration head 保持 071，与 v0.5.2 相同；v0.5.2→v0.5.3 升级无需应用任何内容。相较 v0.5.2，没有删除或重命名 CLI 命令/flag。

## 已发布内容

### 上下文地址 Grammar：`zrig context get`（重点）

提取某一章节的精确字节：

```
zrig context get <pack-ref>/<file>#<H2-slug>[/<H3-slug>]
```

即使 pack 只有一个文件，`/<file>` component 也必填。Ref 使用规范完整路径，例如 `skills/<namespace>/<name>`。无效 slug 会明确失败，并列出可寻址章节。`zrig context list` 枚举每个已发布 entry 的 ref 与名称；`zrig context show` 检查一个 entry。跨来源访问（`seat:` / `mission:` atom）是**创作**能力：在 pack manifest 中声明，并在组合期间通过 `zrig context profile --rig/--seat/--mission` 授权，而不是 `get` 的临时参数。

### `openrig-skills` Router — Ask → Ref → Load

Router 教授三个步骤：提出问题、获得 ref、按 ref 加载。当不知道应使用哪个技能或上下文，或者冷启动后没有投影任何内容时，请使用它。

### 持久席位 Recap — `zrig context recap-write`

在 handover、compaction boundary，或 successor 否则需要从 scrollback 重新推导状态的任何时刻，`zrig context recap-write` 会在 `LEARNED` 旁维护席位 scope 的 `RECAP.md`，并带防冲突的 superseded chain。Restore packet 现在携带作者编写的 recap pointer。

### Refocus 自动解析 Ref

Refocus hook 自动解析 library ref，以 ref 优先于 file；失败会明确显示但不阻塞，并投递 pointer。这是将运行中席位指向新内容的已发布 channel。

### 按需加载有界 Expertise Pack

`zrig context get` 通过类似路径的 ref 提供 expertise pack，例如 `skills/process/context-engineering`。旧 `context-pack:` 冒号形式已经移除，CLI 会明确说明。

**该 pack 的注意事项：** 它被命名为 “Traditional Context Engineering — 2024-2025 Snapshot” 是有原因的：根据 founder 决定，它是 provisional、historical、non-normative。发生冲突时，当前 zrig 技能、明确用户决定和测量实践优先级更高。

## 请停止以下旧做法（在 0.5.2 下曾经正确，现在已经错误）

1. **停止将 library 内容复制到席位或任务目标文件来组合上下文。** 请按 ref 组合；可寻址意味着不产生会漂移的第二份副本。系统不会自动捕获复制行为，但按规则这仍然是缺陷。
2. **停止把 `MODEL DIVERGENCE` 声明视为 alias 噪声。** 先 canonicalize 再 compare 的修复消除了 pinned=fable / effective=claude-fable-5 假阳性；monitor 现在还会隔离逐席位 throw。在此运行时看到声明就是真实 escalation，应采取行动。
3. **停止把工具错误中的 “founder-gated” 理解为授权墙。** 脚本中夸大的措辞已移除；这些 guard 要求的是显式路径，例如 `OPENRIG_SKILL_CANON_ROOT`，而不是权限。真正的 founder boundary 恰好只有 push 与 PR；本地 commit 和普通 apply 工作无需 founder 许可。
4. **停止手工放置 evidence，也不要把 placeholder PRD 当作 proof contract。** `zrig proof add` 会将 evidence 与 contract 配对；原始 scaffold PRD 不会再静默成为 contract。已创作 SPEC 会被采用，并显示具名 advisory；echo 中的 `contractSource` 会说明绑定了哪个来源。

## 已落地但尚不可驱动

Eval CASES 已发布，包含 14 个 selection/loading case，但当前没有可运行的 grading pass。`--provider rig` 是 live proof contract 入口，但**尚未驱动**；命令自身会明确说明并重定向到 fake，接线属于正在进行的 convergence test driver 工作。`--provider fake` 只重放通过 `--transcripts <map.json>` 提供的 transcript；缺失映射时每个 case 都会报错。Live 入口真正可驱动后，下一版本会将其升级为正式能力。

## 已知限制（5.4 Backlog）

- **Reply hint 自限定** — 从 5.2 延续；某些跨主机消息的 reply hint 使用 machine ID 而非 registered host name 指向自身。请用 `zrig host list` 中的 registered host name 替换。计划在 5.4 修复。
- **Eval grading pass** — CASES 已发布，但没有可运行 grading pass。可驱动的 `--provider rig` 在 5.4 落地。
- **`zrig send --verify` 无法检测 staged-unsent**，适用于发往 Claude 席位的多行 send；从 5.2 backlog 延续。
- **Claude transcript 在 fullscreen upsell 下变薄** — 从 5.2 backlog 延续。
- 此外还有内部技术债已记录，供维护处理。
