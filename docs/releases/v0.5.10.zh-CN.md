# zrig v0.5.10 — 可解释的系统健康状态

zrig 0.5.10 让 fleet 健康状态可检查，同时避免把观察本身变成另一份工作。智能体和运维人员可以通过 CLI 与 TUI 查询相同的有界、带证据 finding，将不确定 pattern 交给智能体诊断，并在 project policy 要求时路由经过验证的人类请求。本版本还会让作者编写的任务目标上下文穿越 workflow wait，因此生命周期进度不再依赖 orchestrator 记住仪式步骤。

## 系统健康状态

- **在实际拥有的 scope 检查健康状态。** `zrig health` 支持当前席位、稳定 seat ID、工作组或本地 instance。每条 finding 都保留 category、severity、status、confidence、source window、freshness、rule、evidence、policy version 和最小有效的下一步检查。空输出明确不代表系统健康。
- **在终端 UI 中查看同一真相。** Instance、工作组和席位 view 使用与 CLI 相同的规范 record，提供紧凑健康摘要、HEALTH 列表和 finding drill in。不存在第二套 score 或 TUI 专属健康权威。
- **无需 transcript sentiment 即可检测高置信度运维故障。** 确定性 detector 覆盖 process、governance 和 context signal，例如 queue amplification、authority boundary traffic 和 context pressure。稳定 episode identity、source bound、freshness 和显式 indeterminate 状态，可防止将缺失或过期 evidence 误读为健康。
- **让智能体诊断代码无法判断的情况。** 选择启用的 health policy 可以为 ceremony amplification 提供一个有界 investigation packet。被分配的智能体可以检查 packet 之外的信息、记录带 attribution 的 disposition，并且只在已配置 policy 与 connector ready 时请求通知人类。Diagnosis traffic 不作为自身 detector 的输入。

## 持久生命周期与人类投递

- **让作者编写的任务目标上下文穿越 workflow wait。** 任务目标可以在 `mission.yaml` 中选择显式 boundary workflow；编译会包含 project 和 mission manifest 以及已声明 context ref。Waiting step 可以通过有界指数 backoff 重复呈现同一个 packet，保留一项 obligation，而不是制造替代 row。
- **从作者编写的 component 和 wave 中选择 SDLC 严谨度。** 已发布 role 与 pod 指引遵循 project 和 mission 选择，不根据 seat name 推断 builder→QA→review chain。Role capacity 不会自动创建 gate。
- **通过已注册 delivery channel 寻址人类。** 已注册 `<entityId>@external` 地址公开 readiness 与下一步检查。Verified queue create 会先持久化请求，再检查 receipt；posted、pending、failed 和 indeterminate 结果保持不同。直接 reply 通过关联 queue thread 返回，不会改写为 terminal input。

## 升级与初始化说明

- Root、CLI、后台服务和 Web UI package version 前进到 `0.5.10`；终端 TUI 保持独立版本 `0.1.0`。
- 本版本未在 `0.5.9` migration head 之外新增数据库 migration。正常重启后台服务足以处理 schema state；runtime adoption 仍是独立的运维决策。
- Health list 与 explain 只读。只有 policy 显式启用后才会执行自动诊断；任何 detector 都不会自动重试、重新路由、重新启动、编辑 scope 或改变 lifecycle state。
- 人类投递需要已注册地址，以及已配置、启用、ready 的 connector。Connector setup 或 verification 本身不会发送消息。

## 已知限制

- 已发布的确定性 detector domain 为 process、governance 和 context。Behavioral 与 epistemic 结论仍是带 attribution 的智能体判断，而不是不透明 score。
- System Health 观察有界保留 record。Unsupported、clipped、stale、contradictory 或 unavailable input 保持 indeterminate；没有 finding 并不能证明系统健康。
- Mission boundary workflow 携带 context 和 scheduling，但 evidence、publication 与 activation 的判断仍由智能体负责。后台服务不会解释 Markdown receipt，也不会虚构下一任务目标。
- Slack 只是人类 delivery connector 之一，并非 addressing contract；posted receipt 只证明 connector 接受，不证明人类已经阅读。
