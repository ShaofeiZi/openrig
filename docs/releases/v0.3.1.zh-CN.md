# zrig v0.3.1

## 摘要

zrig v0.3.1 在 v0.3.0 的基础上增加了面向运维人员的 UX 改进、作为重点功能的 Claude 自动压缩策略、Dashboard 与 For You 的视觉刷新、Plugin Primitive v0 界面（`zrig plugin`）、完整的 Library Explorer（技能、插件和 spec，支持真实文件夹浏览）、Settings Destination Explorer、操作结果与内联错误 UX，以及一次全面的隐私卫生清理。

没有破坏 schema 的 migration。现有 v0.3.0 数据库会在首次运行 `zrig daemon start` 时升级：新增 migration `040_workflow_specs_diagnostic`，即在 `workflow_specs` cache 中通过带安全默认值的 `ALTER TABLE ADD COLUMN` 添加两个诊断列。

## 本次发布包含的内容

- **Claude 自动压缩策略** — 运维人员可以配置会话自动执行 `/compact`，并采用安全默认值：默认关闭、需要选择启用，除非显式启用，否则行为不变。新增 7 个 ConfigStore key；由后台服务到 LLM 的生命周期分为 6 个阶段（预准备 prompt → compact → handshake → restore → compliance audit → cooldown）；同时提供 PreCompact hook 和 SessionStart/UserPromptSubmit bridge。
- **Plugin Primitive v0** — 新增 `zrig plugin` 命令界面；v0 仅提供只读的 `list`、`show`、`used-by`、`validate`。插件从 `$OPENRIG_HOME/plugins/` 发现，采用 vendored-and-provenance 模式。v0 没有 `install` verb，该功能推迟到 0.3.2。
- **Library Explorer 完善** — 技能、插件和 spec 现在构成完整的运维界面，并支持真实文件夹浏览。新增由后台服务拥有的 library discovery API：`/api/skills/library`、`/api/skills/:id/files/...`、`/api/plugins/:id/files/...`。
- **Settings Destination Explorer** — Settings 变为包含 4 个条目的 Explorer 目标区域，与 Topology / Project / Library / For-You 模式一致；提供 `/settings`、`/settings/policies`、`/settings/log`、`/settings/status` 子路由。
- **Dashboard 与 For You 视觉刷新** — 两个路由都采用共享的 “vellum” 界面语言：半透明石色卡片、纸张网格背景、环境阴影、等宽字体加圆点的类型指示器，以及 L 形角标定位记号。生产界面与 `/lab/vellum-lab` 使用同一真源。
- **For You Storytelling Adapter** — Progress / Shipped / Incident / Approval 四类卡片接入真实数据，包括任务目标、slice、activity feed 和 queue item。ApprovalCard 会展示真正等待批准的 queue item。
- **操作结果与内联错误界面** — queue item 动词操作（Approve/Deny/Route/Hold/Drop/Annotate/Handoff）成功后立即渲染结果，失败时在原位显示错误，不再静默恢复原状态。此项修复解决了一个会阻塞演示的静默回退问题。
- **移动端 Drawer 行为** — 在 375px 宽度下，Settings / Project / Library / For-You 的 Explorer drawer 现在会显示在 rail tray 上方。Topology 移动端 drawer 在 0.3.1 中有意隐藏，计划在 0.3.2 中完整恢复。
- **Vendored Skill Provenance** — vendored 技能通过 `metadata.openrig` frontmatter 声明上游 lineage；有修改时，还会带有配套的 `OPENRIG.md` sidecar。此规则已应用于全部 10 个 process-skill 界面。
- **Workflow spec 诊断界面** — migration `040` 在 `workflow_specs` cache 中增加 `status` 和 `error_message` 列，使 Library UI 能将解析/验证错误渲染为诊断行，而不是将其隐藏。
- **隐私卫生清理** — 通过三轮 filter-repo 从历史中清理个人数据、内部引用和历史版本；同时润色 commit subject 和正文，使其适合公开展示。保留备份仓库以便回滚。

## 面向用户的变更

### Claude 自动压缩策略

运维人员现在可以配置 Claude 会话自动执行 `/compact`，其默认设置以安全为先：

- **默认关闭、选择启用**：只有显式启用策略后行为才会发生变化。未配置策略时，后台服务绝不会自动发送 `/compact`。
- **7 个新的 ConfigStore key**，位于 `policies.claude_compaction.*` namespace：`enabled`、`threshold_percent`（严格要求 1-100 的整数）、`compact_instruction`（由运维人员提供；设置后附加到 `/compact` 参数）、`message_inline`、`message_file_path`、`pre_compact_instruction`、`post_restore_audit_instruction`。所有来源层（`set`/`POST`/env/file）都进行严格验证。无效环境变量值会回退到默认值，并向 stderr 发出警告，不会静默强制转换。
- **Settings → Policies UI 中 5 个可由运维人员编辑的 prompt 界面**：压缩前准备、压缩指令、压缩后恢复（inline）、恢复文件路径和恢复后审计。由后台服务拥有的 wrapper 不可编辑，其中包括用量/阈值 framing、信任通道保留、marker 路径、读取深度强制、turn boundary handshake、去重和 cooldown。
- **6 阶段生命周期**：压缩前准备 prompt（以“退出前保存游戏”的心智模型保存恢复映射）→ 带运维指令的 `/compact` → 压缩后的 turn boundary handshake → 带纵深防御 fallback chain 的恢复 prompt → compliance audit（强制输出 FULL/PARTIAL/NOT_READ 表）→ 10 分钟 cooldown。
- **安全强化**：已输入的 prompt draft 会归类为 attention 状态，因此自动 `/compact` 会稍后重试，不会覆盖人类输入。发送失败不会推进去重状态。只有再次跨越阈值后才会重新 arm。

### 新的 `zrig plugin` 命令（v0 只读）

```
zrig plugin list                   # 发现 vendored 和运行时 cache 中的插件
zrig plugin show <id>              # 查看插件 manifest、技能、hook 和 MCP server
zrig plugin used-by <id>           # 查看引用此插件的智能体
zrig plugin validate <path>        # 验证插件 manifest 与技能 frontmatter
```

v0 没有 `install` verb；安装需要由运维人员显式复制或创建 symlink 到 `$OPENRIG_HOME/plugins/<plugin-id>/`。每个插件的 `OPENRIG-INSTALL.md` 都记录了复制/symlink 工作流。`zrig plugin install <substrate-path>` verb 推迟到 0.3.2。

### Library Explorer 完善

Library 目标区域（技能、插件和 spec）现在已完整面向运维人员：

- 不再有重复的顶层条目：已从 `SpecsTreeView` 移除 `> SKILLS` / `> PLUGINS` 行；点击底部行会导航并展开树。
- 树中 Plugins 位于 Skills 上方。
- 在生产 VM 环境中，现在可以发现 32 个由 zrig 管理的共享技能；此前因使用工作区相对路径查找而为空。
- 由后台服务拥有的 library discovery API：`GET /api/skills/library`、`GET /api/skills/:id/files/list?path=...` 与 `/files/read?path=...`；`/api/plugins/:id/` 下有对应的并行路由。
- 插件和技能详情页使用真实 file browser 与 docs browser。Markdown 自动渲染，非 Markdown 文件渲染为文本，并支持文件夹导航。
- `/specs/skills` 和 `/specs/plugins` 提供汇总 index page，包含平铺行列表、来源标签、文件数量和入口链接。

### Settings Destination Explorer

Settings 现在是顶层 Explorer 目标区域，与 Topology / Project / Library / For-You 模式一致：

- `/settings`（通用配置 key 表单）
- `/settings/policies`（Claude 自动压缩策略表单位于此处）
- `/settings/log`
- `/settings/status`

旧的顶部 tab 导航已移除。4 个子路由统一使用共享的 `SettingsPageShell` chrome。

### Dashboard 与 For You 视觉刷新

这次协调一致的视觉刷新采用共享的 “vellum” 界面语言：

- **Dashboard `/`** — 基于新的 `dashboard/vellum/` primitive 全面重写。Hero 字样 “WELCOME BACK” 使用 display-lg 与 headline-bold。战术仪表板式统计行使用表格数字。六张目标区域卡片（Topology / Project / For You / Library / Search / Settings）共享数字布局。真实数据 hook 包括 `useRigSummary`、`usePsEntries`、`useSpecLibrary`。
- **For You `/for-you`** — 两套卡片系统统一采用 vellum recipe：storytelling band（重写 `CardShell`，使用 bg-stone-100/45、backdrop-blur、环境阴影和角标）以及 queue item 的 `FeedCard.tsx`（使用相同外层 chrome；vellum 有边框无填充操作按钮支持 hover 反色，并提供 44px 触控目标）。
- **`/dashboard` 与 `/lab/vellum-lab` 使用同一真源**：公共实现位于 `packages/ui/src/components/dashboard/vellum/`。
- **Lab 路由** — `/lab/card-previews`、`/lab/vellum-lab`、`/lab/vellum-bg/{a-large,b-small,c-allover}` 是纳入版本控制、供设计师迭代的实验界面。生产环境可通过直接 URL 访问，但主导航不会链接到这些页面。

### For You Storytelling Adapter

`/for-you` 顶部的 storytelling band 现在将四类卡片接入真实数据：

- **Progress** — 前 2 个活跃任务目标（`useMissionDiscovery`）
- **Shipped** — 状态为 shipped/complete/done 的 slice（最多 3 个，来自 `useSlices`）
- **Incident** — 状态为 blocked/failed/danger 的 slice（最多 3 个）
- **Approval** — 来自 `useActivityFeed` 与 `classifyFeed`、正在等待批准的 queue item（最多 2 个）

`ConceptCard` 组件保留在源码中，但生产 adapter 不会输出它；关于其数据来源的明确决策计划在 0.3.2 中作出。

### 操作结果与内联错误界面

对于 queue item 动词操作（Approve/Deny/Route/Hold/Drop/Annotate/Handoff）：

- 成功时立即渲染 `ActionOutcomePanel`（例如 “Approved by X”“Routed by X to Y”），无需等待 audit log 往返。
- 出错时，在动词按钮下方渲染带三级边框的错误块，并显示后台服务错误消息；动词选择状态会保留，运维人员可以修正后重试。
- 这取代了以前的静默回退 UX，并有回归测试明确守护该行为。

## 运维 / 初始化说明

升级已发布的 CLI 后：

```bash
npm install -g @openrig/cli@0.3.1
zrig --version    # 预期输出 0.3.1
zrig daemon stop
zrig daemon start
```

升级后首次启动后台服务时，会自动应用 migration `040_workflow_specs_diagnostic`。这是带安全默认值的非破坏性 `ALTER TABLE ADD COLUMN`，现有行会追溯获得 `status: 'valid'`，无需手动操作。

Claude 自动压缩策略默认关闭、需要选择启用。请访问 `/settings/policies` 进行配置。对于经常面临上下文耗尽问题的会话，建议使用此功能；启用前请阅读 Settings UI 中的文档章节。

新的 `zrig plugin` 界面不会自行改变行为，只有安装插件后才会生效。后台服务随附内置 `openrig-core` 插件（11 个技能）。运维人员可以按照各插件 `OPENRIG-INSTALL.md` 中的工作流安装 `gstack`（45 个技能）或 `obra-superpowers`（14 个技能）。

## 已知限制

- **`zrig down <name>` 仍返回 HTTP 404** — v0.3.1 的按名称拆除仍无法通过后台服务 down 路由解析。请改用 `zrig down <rigId> --delete`。该已知问题延续到 v0.3.2。
- **`zrig queue list --json --limit` 与 `zrig view list/show --json` 的 flag 不一致** — flag 已搭建框架，但未完全接线。目前请使用人类可读输出。该问题延续到 v0.3.2。
- **Topology 移动端 drawer 在 375px viewport 下隐藏**（有意如此；点击 hamburger 会触发既有的 `TopologyTableView` renderer cascade）。计划在 0.3.2 中通过专门的渲染路径 slice 完整恢复。
- **`ConceptCard` 组件保留在源码中**，但生产 For You adapter 不会输出它。关于其数据来源的明确决策计划在 0.3.2 中作出。
- **`/lab/*` 路由会进入生产 build**，这是根据 founder 指示有意保留的行为；0.3.2 将增加 index page、每个 lab 的 banner 以及 manifest 模式。
- **插件安装易用性** — v0 插件由运维人员复制或创建 symlink 安装；一等的 `zrig plugin install <substrate-path>` 推迟到 0.3.2。
- **生命周期分类**保持真实，但部分故障恢复路径仍依赖启发式判断，而非完美的 provider 原生能力。
