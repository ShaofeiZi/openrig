# zrig v0.5.13 — 阅读、决策并返回工作

**状态：** release candidate，尚未发布。Exact cut substance review、release verification 与 publication 仍待完成。此 candidate 尚未采用到 live installation。

zrig 0.5.13 连接完整的人类 TUI journey：进入 instance、选择 project、阅读当前指引、了解哪些事项需要决定，并有意打开所需 terminal。限定 scope 的 oversight 与显式 Git context update 帮助智能体依据正确指引工作，同时保持 authority、evidence 与 local authorship 可见。

## 从有用内容开始

在 startup check 运行中、后台服务停止或状态 unverified 时，交互式 bare `zrig` 仍提供 Help、Skip 和本地读取。可以从磁盘读取选定 project、任务目标和 slice intent，不会伪装成 live queue、execution 或 topology data。读取失败与 source provenance 保持可见。启动后台服务或让席位恢复工作仍是有意操作；读取和跳过不代表同意。

## 阅读当前来源并找到返回路径

PROJECTS 会在任务目标、slice 和 source view 之间保留所选 project 的 identity 与 root，包括 display name 相同的 project。Source 不可用时会针对该 project 报告，而不会换用另一 project 的工作。Refresh 会读取当前文件。

共享 reader 显示 source path、修改/hash 信息和有界内容，并支持滚动、本地 link、heading link 与 Back。HTTP(S) link 显示可选择、可复制的 destination，不会打开 browser。Missing、unreadable、binary 或超出 root 的文件保持具名错误。大文件会显示 1 MiB 返回内容上限；截断 prefix 中缺失 heading 时，不会声称整个文件都没有该 heading。Back 会恢复先前阅读与导航位置。

## 了解哪些事项需要你的决定

ATTENTION 会区分 **Action required** 与 **Updates**。Human request 和显式 blocker 会显示 request、urgency、scope 及其将解除阻塞的工作。Outcome 与 health update 保留自己的 source 和 history。打开 detail 或关联 evidence 以了解情况；查看 request 不等于 approval 或 delivery，关闭 queue item 也不能证明产品 outcome 已完成。Missing 或 incomplete read 保持可见。

## 打开终端前先预览

TERMINALS 列出保存和派生的 view，以及各自 member 与已解析 layout。Preview 是被动操作。有意执行 Open 时，会使用已检查 plan，并报告 opened、absent 或 degraded member，包括部分失败。Help 与 side trip 会返回同一 preview 和 page。观测到的 native provider journey 使用 Herdr；更广泛的 provider 限制见下文。

CONFIG 保持完整值、默认值和 source/override provenance 可读。Help 提供命令描述、grammar 与示例，包括 startup failure 期间。窄 view 保留滚动与返回控件。Health 将 INFO severity 与 Unknown assessment 区分，公开 stale 和 unavailable read，并解释空 finding list **不代表健康 verdict**。完整 empty health 说明在 80 列下仍可阅读。

## 为当前工作选择 Oversight

对于仅流程诊断，human led work 默认保持安静。显式 delegation 可以在 planning 和 execution 阶段启用 oversight，但仍受既有 diagnosis policy 与 delivery prerequisite 约束。普通 work reminder 和 operational health 行为不变。Scope、phase 与 posture 来自显式 source；无法解析的 identity 保持 unknown。

使用带显式 scope 的 `zrig mode effective` 检查结果。[限定范围的运行 posture 参考](../reference/scoped-operating-posture.md)说明选择与优先级。Posture preference 不授予执行权限。Correction record 可以保留选定的当前 guidance，并区分 assessment、实际执行的 action 与之后观察到的 effect。这些只是受支持的机制，不是改进判断的证据：自然 behavioral effect 仍为 **UNOBSERVED**，human time cost 仍为 **UNMEASURED**。不声称能够治愈或减少复发。

## 更新 Context 而不丢弃本地作者工作

`zrig context add <repository-path-or-URL> --git` 保留 Git source、其 checkout 与所选 context pack 之间的关系。在仓库中选择 pack 时使用 `--pack`。沿用现有 Git credential。

使用 `zrig context source inspect <ref>` 在不 fetch 的情况下检查 local change、conflict、revision 与 selection。`zrig context source update <ref>` 会显式 fetch 并 merge upstream，再选择 clean content。已 commit 的本地工作会在普通 merge 中保留。Dirty work、conflicting change、unavailable upstream 或对 served selection 的编辑会触发具名拒绝，而不是 reset 或 overwrite。重试前，请在保留 checkout 中解决并 commit，或 abort merge；冲突期间仍可使用此前 served selection。Update 不会 push。

Checkout history、选定 served byte 和智能体实际 consumption 是三个不同事实。使用 `zrig context get <ref>` 读取选定 byte，并检查预期 consumer。这不会自动同步每个 context library，也不会把 guidance 采用到运行中智能体。

## 运维说明与验证限制

Root、CLI、后台服务和 Web UI package version 为 0.5.13；终端 TUI 保持独立版本 0.1.0。Node 要求不变。有序 migration head 从 079 前进到 `080_scoped_operating_posture`，扩展既有 mode binding store，加入限定 scope 的 human led/delegated 选择，并保留 legacy row。获得 adoption 授权后请使用受支持的升级与连续性流程；准备此 candidate 不执行 live migration 或 restart。

已接受开发 evidence 在 140×42 与 80×24 下连接完整 journey，包括 unavailable/Unknown control、双 project 隔离、current source 读取、有意打开 native terminal，以及保留 Git conflict。这些 observation 保留其原始 development cut 与 attribution。Version、release note 和 package check 与这些 journey 分开，不构成新的 whole release usability study。

- 同时运行的默认 TUI client 可能相互替换 programmatic control socket address。这是已知且未修复的限制；对于已演示的单 client 人类 journey，它被判定为非阻塞。唯一 test socket 不能证明产品级 multi client 隔离；历史 lost request 仍未验证。
- Native terminal proof 覆盖 Herdr。SSH login、cmux 端到端行为和对 parent host 的影响仍未验证。既有 native continuity evidence 只复用于未变路径，不代表新增 provider 覆盖。

- Synthetic finding 和 request 只演练机制，不证明自然 behavioral improvement 或真实 human approval/delivery。尚未完成 unfamiliar human study、real host reboot、全平台运行或 live 0.5.13 adoption。
