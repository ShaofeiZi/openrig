# zrig v0.4.7

> **⚠️ 里程碑：** v0.4.7 是 **Web UI 进入维护模式**的版本。从本版本开始，CLI 成为主要产品界面；Web UI 仍会随产品发布且仍可使用，但不再增加新功能。如果目前通过浏览器使用 zrig，请计划迁移到 CLI；从 v0.5.0 起还可使用终端 TUI：`zrig` / `zrig tui`。0.4.7 实际交付的具体 UI 内容见下文。

## 摘要 — 恢复真实性 + Starter Bootstrap + 技能扩展 + Slack Connector + UI 维护模式

**恢复真实性贯穿本版本。** 恢复已有会话时，启动序列现在会在定义角色的第一条消息之前，加载适用于该席位的技能 preload，使恢复席位在开始工作前已经了解自己的技能。压缩恢复保持真实：transcript ingest 显式公开降级状态；只有席位空闲时才发送压缩后的恢复与审计，因此 “restore-sent” 确实表示 “delivered”。后台服务 liveness 报告也保持真实：dead seat 会将 effective running 降为 0 并报告 `attention_required`；席位消失时，`zrig send` 和 `zrig capture` 会返回明确的 “session missing” 错误。CLI probe 会如实报告不确定性：无法确认的状态返回 `UNKNOWN`，不提供虚假的启动建议；确认停止的席位会失败并给出可操作指引。

Migration 仅叠加。现有 v0.4.6 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。

## 已发布内容

### Starter Bootstrap

Product-team starter bootstrap 更加简洁；无论全新启动还是恢复，starter 席位都会获得技能 preload。默认 culture 在启动时加载，工作组 spec 在加载时审计。**v0.4.7 之前实例化的工作组需要重新实例化**，或在 spec 层修补，才能获取 starter 修复。Loader 与 audit 变更会立即生效，但 starter spec 内容只在实例化时写入。

### 技能扩展

Bundled skill 层新增公开 routing 与默认 projection，以及 public skill strip 和 mirror control；同时修复插件，使文档中的技能数量保持真实。Bundled skill inventory 从少量技能扩展为广泛覆盖 core、PM、pod 和 process family。

### Slack Connector 与 Human Queue

提供一等 Slack connector 结构，包括 CLI `zrig slack` 命令和支持 library。Hosted create 会越过结论不明确的本地 probe，以真实 configured daemon 的结果为准。

### CLI 契约真实性

收紧 `--json` 错误、flag 验证和带 scope 的 overdue 行为，以便机器读取。

### UI — 进入维护模式

**Web UI 从本版本起冻结并进入维护模式。** 对外措辞是 CLI-primary，绝不称为“弃用”；UI 仍随产品发布且仍可运行，但不再增加新功能，后续以 CLI/TUI 为主要界面。v0.4.7 为向用户明确这一状态，交付以下内容：

- Web UI 中可关闭的应用内 banner，说明维护模式状态。
- 运行 `zrig ui open` 时在 stderr 显示提示，使通过 CLI 操作的运维人员在打开浏览器前知晓状态。
- 更新 README 和面向用户的文档定位。

现有 v0.4.6 部署继续工作，不会删除任何内容。实质产品投入转向 CLI，以及从 v0.5.0 开始的终端 TUI。

### Queue、Topology 与 Review 完善

- Queue compact list 行会标记已省略字段，使“省略”与“空值”可区分。
- Nested Approve 会提交相对于 missions root 的 scope path。
- 完善 Mission review card 组合。
- 未验证的 delivered item 显示 “artifact-recorded”，而非 “nothing delivered”。
- Drawer file viewer 通过 file asset API 解析正文中的内联图片。
- Proof-of-work Markdown link 在应用内 drawer 打开。
- Docs guard 编码 `docs/DESIGN.md` 的根目录放置规则。

### 主机容量建议

建议在主机上增加 swap；根据观测基线，每个席位约需 2 GB RSS，请据此规划。

## 行为与兼容性

- **Migration** — 仅叠加。现有 v0.4.6 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。
- **工作组 spec starter 行为** — loader 与 audit 变更立即生效；starter spec 内容在工作组实例化时写入。v0.4.7 前实例化的工作组需要重新实例化或在 spec 层修补，才能获取 starter 修复。
- **席位 liveness API** — consumer 应以每几秒更新一次的真实 lifecycle state 判断席位是否存活，不要依赖较旧的 session status 字段；其过期清理将在后续版本跟踪。
- **Web UI posture** — 冻结在维护模式，不破坏 CLI 界面；本版本不会从 UI 移除任何内容。
