# zrig v0.4.2

## 摘要

zrig v0.4.2 是一次定向 hotfix，用于修复 CLI `daemon-status` probe 在执行 `zrig daemon start` 或重启后短暂出现的假阴性。此前 0.4.1 build 的每个 `getDaemonStatus` 分支只请求一次 `/healthz`；如果后台服务进程已经启动，但 HTTP listener 尚未开始接受连接，单次 probe 就会在竞态中失败，导致 `zrig daemon status` 错误报告 “Daemon not running” / “healthz failed”，即使随后 `/healthz` 已返回 `200`。

修复会在三个 `getDaemonStatus` `/healthz` 分支中加入仅限 status probe 的有界 settle：最多尝试 5 次，backoff 为 200ms，结构上具有硬上限。后台服务确实停止时，所有尝试仍会失败，并在预算耗尽后报告 stopped / unhealthy；不会掩盖故障，也不会无限等待。`fetchDaemonProbe` 以及 start / stop / checkPid 的时序保持不变。

## 变更内容

- **`zrig daemon status` 不再在后台服务启动后绑定 listener 的窗口内产生假阴性。** Probe 在报告 stopped 前会以短 backoff 最多复查 5 次，因此仍在绑定 listener 的健康后台服务最终会显示 running / healthy，而不是错误的 down 状态。
- **后台服务确实停止时的报告不变。** 如果后台服务真的没有运行，所有尝试都会失败，probe 在有界预算耗尽后报告 stopped 或 unhealthy；不会挂起，也不会掩盖。

## 涉及的文件

- `packages/cli/src/daemon-lifecycle.ts` — 三个 probe 分支（PID 存活时的 `/healthz`、无状态时的 `/healthz` 和 injected probe wrapper）现在都经过 `probeHealthzWithSettle`。
- `packages/cli/test/daemon-lifecycle.test.ts` — 定向 probe 层测试：先瞬态失败后健康会 settle 为 running / healthy；PID 存活但始终无响应时保持 `healthy: false`；后台服务确实停止时，在硬上限预算后报告 stopped。

## 行为与兼容性

- **CLI 界面没有变化。** 所有命令、flag 和参数与 `0.4.1` 完全相同。
- **后台服务 / DB / migration 没有变化。** Migration 状态与 `0.4.1` 相同；本版本不包含新的 schema migration。
- **依赖没有变化。** `package-lock.json` 只因版本号更新而刷新。

现有 v0.4.1 数据库不受影响。升级只需执行 `npm install -g @openrig/cli@0.4.2`（或刷新 package）；如果后台服务正在运行，再按常规流程重启 `zrig daemon`。
