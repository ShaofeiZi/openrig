# zrig v0.6.0 — 能够服务陌生用户

版本 **0.6.0** 的变更。Publication 状态与日期记录在 [GitHub release](https://github.com/mvschwarz/openrig/releases/tag/v0.6.0) 和 npm 中。

zrig 0.6.0 要求 Node.js 22 或 24。本版本新增逐席位 permission 选择、保护人工输入席位的逐席位 typing guard，以及在 Herdr 中一步打开整个工作组的方式；同时修复 Pi 席位 activity，并澄清 kernel starter 的 runtime 选择。

本版本还包含两个**实验性**功能：Slack app manifest 与 setup assistance，以及默认关闭的可选 stream classifier（Jev with Rig Stream）。它们可能不完整，也可能无法在你的环境中工作。参见[报告实验性功能问题](#report-experimental-problems)。

## 破坏性变更：Node.js 22 或 24

zrig 0.6.0 只支持 Node.js 22 和 24，并使用要求 Node 22 或更新版本的 better-sqlite3 13。Node 20 不再受支持：安装检查会拒绝该版本并解释原因。Node 26 及其他版本未测试。

如果当前在 Node 20 上运行 zrig，请先切换 Node，再在新 Node 下重新安装 CLI。现有数据仍保留在原位置；后台服务会重新打开同一数据库，并原位应用 pending migration。参见[迁离 Node 20](../../README.md#moving-off-node-20)。

zrig 支持 macOS 或 Linux。原生 Windows 尚不支持，WSL2 尚未测试。在 Apple silicon Mac 上请使用 Node.js 22，参见[兼容性历史](v0.5.15.md#known-compatibility-limitation)。

## 逐席位选择权限

`zrig seat set-permissions <seat> --mode <mode> --reason <text>` 会为席位后续启动记录经过审计的 permission 选择：`floor`、`full_bypass`，或使用 `inherit` 清除 override。Codex `full_bypass` 现在传入 `-s danger-full-access -a never`，因此同时绕过 approval 与 sandbox。Claude Code 的其他 mode（例如 `auto`）只有在席位的 managed Claude executable 声明支持时才会接受；zrig 会在选择时和每次启动时检查，失败则拒绝且不 fallback。

该选择不会重新启动席位，也不会改变当前 process、history、rule 或 hook。`zrig seat status` 显示所选 mode 和最近一次 launch argument；两者均不能证明原生 permission 行为，因此依赖前应检查运行中 session。工作组级 policy 移到 `zrig policy permissions list|show|current|apply`；旧 `zrig policy` verb 保留为 alias。参见 [permission 指南](../reference/getting-started.md#per-seat-permission-mode)。

## 保护由你手工输入的席位

`zrig seat set-typing-guard <seat> --enabled true --reason <text>` 会暂停对该席位的所有自动 terminal input，即使当前是空 prompt。Message 与 wake 保留在 outbox 中，而不会输入终端；使用 `zrig seat held-messages <seat>` 读取，使用 `zrig seat retire-held-message <seat> <id> --reason <text>` 将已审阅项目退休。关闭 guard 只允许新的 send；它绝不会重放 held message。

Guard 默认关闭，其他席位继续自动投递。依赖该设置前，请等待 `zrig seat status <seat>` 报告它已经 effective。它覆盖 zrig 自己的 input path，不覆盖其他工具直接向 terminal 写入。`zrig seat set-typing-guard --help` 会列出 retention limit。

## 实验性功能：Slack App Manifest 与 Setup Assistance

`zrig slack manifest` 会输出供你在自己 workspace 创建 app 的 Slack app manifest。它离线运行，不需要后台服务或 token；`--url` 输出已预填 manifest 的 Slack create app link，`--json` 列出每个请求 scope 及其原因。Slack 未配置时，TUI Connections 页面会显示同一 link。zrig 不会在此托管 app、打开 browser 或接收 token。

该 manifest 和 [Slack setup 指南](../reference/slack-app-setup.md) 是实验性的。指南中的创建步骤依据 Slack manifest 文档，但尚未通过真实 app 创建确认：我们没有观察 Slack 会预填哪些字段，也没有观察完整 granted scope 集合。仍需手工创建 token 与 private env file。既有 Slack connector 及其 `zrig slack setup`、`verify`、`enable`、`disable`、`status` 命令不是实验性的；`setup` 和 `status` 现在也会指向 manifest。`zrig slack verify` 只检查 baseline scope，因此 READY 不能证明 attachment 或 mention 可用。

## 在 Herdr 中打开整个工作组

在 TUI 中，工作组 detail view 提供 `term ▸ zrig <name>` link，command bar 接受 `terminal <view>`。使用 Herdr 时，工作组所有 running seat 会在以该工作组命名的 workspace 中打开，每个 tab 最多 16 个席位；cmux 使用自身限制。只有 zrig 能确认工作组自身 tab 已经打开时，才会关闭初始空 tab；否则保留空 tab，并在结果中说明。未运行席位会报告 absent 或 degraded，而非 opened。

## 首次使用与兼容性修复

- Pi 席位 activity report 现在携带 occupant generation；只有 generation 与席位当前 occupant 匹配时，后台服务才接受。Missing、earlier 或 foreign generation report 会被拒绝，不会归因到席位。
- Kernel starter 摘要现在会说明何时显示 library preview，解释 runtime variant 自动选择，并指向实际运行的席位。
- 已安装 Codex 支持时，Codex 席位使用 `--no-daemon` 启动，使每个席位的 tool 都在自己的 app server 中运行，而不是共享后台服务。zrig 每次启动前检查支持情况，检查失败则拒绝启动。
- 使用 `zrig scope` 创建的任务目标与 slice，在 manifest 没有 `metadata` block 时不再让 readiness reader 失败。
- 0.5.16 新增的 Claude Code managed block 使用 `CLAUDE.local.md` 的选择保持不变。

## 实验性功能：Stream Classification（Jev with Rig Stream）

zrig 0.6.0 包含一种可选、实验性方式，使 classifier seat 通过 OpenRouter 使用 Jev 标注 Rig Stream observation。该功能可能不完整，也可能无法工作。它默认关闭，可针对本地配置文件启用：

```sh
zrig project experimental status --config ./experiment.json --json
zrig project experimental enable --config ./experiment.json --max-requests 3 --timeout-ms 10000 --json
zrig project experimental disable --config ./experiment.json --json
```

启用不会启动 processing、capture、后台服务或智能体。只有 classifier seat 运行一个前台命令 `zrig project wake … --experiment ./experiment.json` 时才会执行工作；该命令允许 1–20 个 request，默认 3 个，并且绝不会在后台 retry。运行进程的环境中必须存在 `OPENROUTER_API_KEY`；它会将所选 item 的文本、taxonomy question、scope ID 和 roster destination 发送到 OpenRouter。Disable 会阻止后续调用并丢弃迟到结果；Ctrl-C 会取消运行，但已经转发的 request 仍可能产生费用。

这些 label 仅供参考。它们没有已证明 accuracy 或 calibrated confidence，本版本也未增加消费这些 label 的 delivery、watchdog 或 routing consumer。`zrig project experimental capture` 对现有 shadow capture archive 使用相同 client；`zrig project shadow-status`、`shadow-drain` 与 `shadow-stop` 管理 capture，而 capture 需要单独配置的后台服务启动；`zrig project shadow-stop` 会将其停止。Taxonomy 格式、request limit 与错误处理参见 [stream classification](../reference/stream-classifier-worker.md)。

## 报告实验性功能问题

如果 Slack manifest、setup guide 或 stream classifier 未按说明工作，请使用 bug template [创建 issue](https://github.com/mvschwarz/openrig/issues/new/choose)，或按照 [CONTRIBUTING.md](../../CONTRIBUTING.md) 提交 pull request。既有 Slack connector 或其他既有功能的问题属于普通 bug report。

## 已知限制

- 逐席位 permission：发布前没有验证 fresh launch、resume 与 same seat fork 的 authenticated native enforcement。Status 输出与 launch argument 不能证明所选 mode 的 effective permission；请检查运行中 session。
- Slack manifest 与 setup assistance（实验性）：尚未根据已发布步骤在真实 workspace 创建 app，也没有观察 Slack 预填字段和完整 granted scope。
- Herdr：请检查当前 Herdr 版本中工作组是否按预期打开。
- Pi：已安装 Pi 席位的 activity reporting 尚未完成端到端验证。
- Stream classification（实验性）：尚未验证 installed run 与真实 OpenRouter access，输出可能不完整或错误。不作 accuracy 或 production reliability 声明。
- [#17](https://github.com/mvschwarz/openrig/issues/17) 报告的 Codex hook trust dialog 尚未复现，本版本未改变该问题。
- Node 26 与奇数版本 Node 不受支持，也未测试。

## 验证范围

发布准备在 [#109](https://github.com/mvschwarz/openrig/pull/109) 中跟踪。普通 candidate tarball 已在全新 macOS 15.7.3 ARM64 VM 上通过安装，使用 Node.js 22.22.1 和真实 npm postinstall。检查覆盖 better-sqlite3 13.0.3、全部 89 个 migration、数据库写入与 close/reopen，以及普通未认证后台服务 startup 与 shutdown。

此前 Node 24 candidate 检查覆盖已安装 SQLite、migration 和 allocation driven garbage collection。相关安装与数据库机制没有变化。该安装使用 staged offline postinstall，不是 fresh machine install。由于主机资源压力，未执行全新 Node 24 VM 安装。

这些检查不能证明 authenticated first agent launch、全新 Linux 或 Windows 安装、无 compiler tool 安装，或从 npm registry 下载后安装。最终 artifact 将单独绑定到已 merge release commit。
