# zrig v0.5.4

## 摘要 — “真实性版本”

**v0.5.4 让命令输出描述真实发生的效果。** Transport 解析会区分 missing、found 和 indeterminate session；delivery verification 会区分 staged input 与智能体已消费的 turn；queue、refocus、lifecycle、import 和 preview 界面会保留真实状态和拒绝语义，不再将其折叠成看似合理的成功。

**v0.5.4 完整包含 v0.5.3。** VM 切点通过有序 32/32 稳定 patch ID 匹配，对齐到已发布 lineage。

没有新 migration。Migration head 保持 071，与 v0.5.3 一致。Node engine 要求不变。既有 CLI 命令全部保留；本版本新增 `zrig seat set-model`、`zrig seat stop` 和 `zrig seat clean`。

## 已发布内容

### 统一的分类 Session Resolution 路径

Send、capture、nudge 和 walk 消费同一个 probe 结果：found、absent 或 indeterminate。tmux 或 transport 抖动不再被错误转换为 `Session not found`，恢复输出会说明实际检查了什么。

### 按效果验证投递

`zrig send --verify` 会检查输入仍处于 staged 状态，还是已经被智能体作为一个 turn 消费。单目标、fanout 和 JSON 输出使用相同分类，因此 “typed” 与 “delivered” 不再同义。

### 真实投递未知发送者消息

无法确定发送者身份的消息会带 unknown-sender 标签投递，而不是拒绝。在可行时，发送者会收到补充 attribution 的提示。

### 受支持的单席位生命周期控制

- `zrig seat set-model` 修改规范 model binding，并要求可审计原因。
- `zrig seat stop` 停止一个 live seat，不影响 sibling。
- `zrig seat clean` 清理 dead session 残留，使 logical seat 可以再次启动。

安全性覆盖整个类别：生命周期操作可能修改的每个 session 都会先 probe；结果为 live 或 indeterminate 时拒绝操作。Model change 已通过真实托管 successor 演练。

### 保持状态的 Queue 与 Refocus 行为

Queue note 会保留行状态。没有身份时请求 owned listing 会拒绝，而不是静默扩大或改变 scope。Refocus 保留 due 状态，直到 delivery 可见。Preview 与 handoff 输出会说明内容何时有界或可选。

### Create 与 Import 的运行中名称 Guard

无法通过另一个 instantiator 或 import route 重新创建正在运行的工作组名称。每条路径都会跨 CLI boundary 保持相同的 `409 rig_name_running` code 和教学消息。

### Hermetic 启动与插件权威

Scratch/test 启动边界保持 hermetic。Bundled `openrig-core` plugin 在显式版本权威下前进，防止旧运行时静默将已安装指引回滚。过期 lab refocus registration 已淘汰。

## 行为与兼容性

- **Migration** — 无；schema head 保持 071。
- **API 兼容性** — 既有命令保持可用；三个席位生命周期 verb 为叠加式新增。
- **Lineage** — 0.5.4 产品差异通过 patch identity 对齐到已发布的 0.5.3 lineage。
- **发布边界** — tag、npm publish、主机安装和后台服务 cutover 仍是各自独立、需要授权的操作；本文不暗示这些操作已经执行。

## 已知限制（0.5.5 Backlog）

- **Writer 层磁盘上限** — cleanup 是临时控制；永久 write layer cap 尚未完成。
- **Repair/approve frontmatter 重写** — 已知重写缺陷仍未解决。
- **Observation pipeline 性能** — 更大范围的 pane/process polling 重构仍需测量后决定，本版本不声称包含该能力。
