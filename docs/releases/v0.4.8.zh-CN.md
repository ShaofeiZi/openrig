# zrig v0.4.8

## 摘要 — Permission Posture 快速后续

启动 posture 现在可配置；deny set 写入 project local approval 无法覆盖的层级；危险操作由显式 prefix rule 门控，并且这些规则在当前 harness 下确实有效。

Migration 仅叠加。现有 v0.4.7 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。

## 已发布内容

### 可配置的启动 Posture

硬编码的 `--permission-mode acceptEdits` 启动 flag 已替换为可配置 posture，默认值为 `dontAsk`。这解决了自主席位卡在 modal permission prompt 且无人点击时的冻结问题。选择 `dontAsk` 作为默认值，是因为它符合自主席位真正能够响应的方式；席位需要旧行为时仍可选择 `acceptEdits`；有意设置的 `bypassPermissions` 值在写入过程中会保持不变。

### Project Local Approval 无法覆盖的 Deny Set

Posture 会写入用户级 `~/.claude/settings.json`，而不是 project local approval 文件。因此，**deny 优先于 project local approval**。写入仅叠加，绝不破坏 sibling key；同时会将旧版 `acceptEdits` 值向前迁移到新 schema。有意设置的 `bypassPermissions` 值会保留。

### 有界危险操作 Deny Set

默认门控四项危险操作：`git push`、`gh pr create`、`npm publish` 和 `zrig down`。其中 `zrig down` 通过 prefix rule `Bash(rig down:*)` 门控；当前 Claude harness（2.1.220）只支持 Bash rule 的 prefix match，且已经证明只匹配 flag 的 pattern 无法门控 `rig down <rig> --force` 这类 target first 形式，因此 prefix rule 是唯一真正有效的结构。v0.4.8 会门控普通 `zrig down`；选择性允许特定目标（例如 `zrig down <rig>`）推迟到 v0.5.0 的服务端 enforcement。这里的 `Bash(rig down:*)` 是 Claude 权限协议中的兼容规则文本，按原值保留。

### 取消 `zrig up` 门禁

移除上一版本对 `zrig up` 的 ask gate；`zrig up` 是可逆操作，不需要交互门禁。

### Permission Policy 基础（Built-in 将在 v0.5.0 提供）

- **Harness neutral policy schema。** Permission policy spec 是与 harness 无关的界面，包含 `default_posture`、`floor`，以及用**语义操作**表达的 `allow` / `ask` / `deny`（例如 `push_to_remote`、`force_push`、`delete_files`、`read_secrets`、`create_pr`、`publish_package`），而非原始 shell command pattern。
- **`zrig setup --policy <name>`** — `zrig setup` 新增 flag，将 permission policy 选择写入现有工作组 spec。参数可以是内置名称或自定义 policy 文件路径。**内置 policy 文件本身随 v0.5.0 发布**；v0.4.8 只发布消费这些文件的 framework。
- **两类界面。** **Launch flag** 界面由 zrig 稳定设置，包括 Claude `--permission-mode`、Codex sandbox/bypass flag、Pi `--approve` / `--no-approve`，这里承载 floor 与 full bypass YOLO。**Config file** 界面（Claude `~/.claude/settings.json`、Codex `config.toml`）承载 allow/ask/deny rule。由于 harness rule grammar 经常跨版本变化，该界面由智能体驱动的技能交互应用；该技能会在 v0.5.0 以 `applying-a-permission-policy` 发布。

## 部署说明（运维人员请阅读）

要使 posture 写入到达席位，**后台服务的 `HOME` 必须与席位 tmux 的 `HOME` 一致**。这是 Claude 2.1.220 settings path invariant，对任何升级的远程主机部分都很重要：

- 仅本地主机通常会自动满足。
- 远程主机升级时，必须先验证后台服务进程与 tmux 席位进程的 HOME 一致，再将升级视为完成。

（v0.5.0 将其记录为 Codex `HOME` divergence 的已知问题；产品修复在 v0.5.1 发布。）

## 已被取代的尝试

最初的 v0.4.8 尝试将 `dontAsk` 固化为**平台默认值**，而不是 zrig 侧默认值；最终 review 后，该尝试被撤回。实际发布的 v0.4.8 是重新限定 scope、与具体 permission 无关的基础和 policy spec 系统。撤回版本中的任何内容均未发布。

## 行为与兼容性

- **Migration** — 仅叠加。现有 v0.4.7 数据库可通过在新后台服务上运行 `zrig daemon start` 升级。
- **默认启动 posture** — 从硬编码 `acceptEdits` 改为可配置，默认 `dontAsk`。席位需要旧行为时，请显式选择 `acceptEdits`。
- **Deny set 写入位置** — 用户级 `~/.claude/settings.json`；deny set 优先于 project local approval。写入仅叠加。
- **`zrig up`** — 不再使用 ask gate；可逆操作无需交互门禁。
