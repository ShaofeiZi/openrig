# zrig 中文化统一规范

## 名称与兼容性
- 用户看到的产品品牌是 **zrig**，表示中文版本；命令示例默认 `zrig`。
- 同时保留 `rig` 和 `openrig` 旧执行入口作为兼容别名。`rig` 若为协议名、枚举、命令内部语法（如 `zrig rig list` 的子命令）、数据字段、文件名、环境变量、URL、socket、导入包、服务发现标识或 tmux session 前缀，不改为 zrig。
- 保持 package name、包依赖、导入名、API/JSON keys、数据库值、机器可读格式及外部程序 `claude`/`codex`/`tmux` 不变，除非入口负责人证明发布所需兼容性。
- 只翻译人类阅读的自然语言。JSON 输出、协议错误 code、状态枚举保持原值；可在展示层增加中文标签，不把数据改成中文。不得对整个标准输出做不区分来源的词语替换。

## 表达与术语
简体中文，自然直接，不加无关宣传语。中文说明使用中文标点；代码符号保留 ASCII。快捷键保持可输入的原键值并给中文说明；占位符和插值数量、顺序、转义、正则、ANSI 控制符必须不变。

## 文档统一结构
保留原始 Markdown 不变，旁边生成 `*.zh-CN.md`。保持标题层级、表格、列表、代码围栏、链接和原文的信息量，不得以中文摘要冒充全文译本。不复制大块未翻译英文后声称完成。专有名词、路径、标识符、URL、版本号保留。命令示例的顶层 `rig` 改为 `zrig` 是本任务明确例外，但内部子命令不变。必要时增加简短中文说明，例如迁移兼容性或操作前提；不捏造行为。内部链接仅在目标伴随版确实生成时才可指向中文版本。

## 代码与测试
翻译已有英文注释，并对非显然的边界、协议、宽度处理补充必要中文说明，不在简单赋值上堆砌注释。所有机器字段和业务行为不变。不能因中文化删除测试、跳过原断言或全局放宽匹配；更新展示文本断言但保留行为验证，新增中文显示/品牌/兼容测试。中英文宽度不同，终端列宽必须按显示宽度而非字符串 length，截断不得切断中文/ANSI 控制序列。

## 状态与自检
先备份再修改。每个分配文件必须逐个有状态及可复核说明。`done` 表示整个指定范围内容完成并审查，不是只加入中文注释；有剩余英文自然语言须如实记录 failed 或具体跳过原因。禁止用通用前缀翻译或若干词替换把全部文件标 done。修改后应跑最相关类型/单元/展示检查，返回命令退出码和剩余数。文档无需新增未经请求的报告格式；代码/文档最终在项目原位交付。
